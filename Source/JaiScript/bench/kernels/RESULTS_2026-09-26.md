## Where JaiScript stands

- Faster than Lua 5.5: sha256 (0.18x typed; Lua's script pays variadic bit helpers), mandelbrot (0.36x;
  scalar float locals against Lua's complex tables), float2string (0.51x). Ahead of LuaJIT -joff on
  float2string only; behind the DAS estimate everywhere.
- Within 2x of Lua: primes (1.71x), spectral norm typed (1.74x), string2float (1.94x).
- 2.5-7x: fib loop (2.66x, one extra mask op per iteration), queen (3.88x), dict (4.79x), fib recursive
  (5.60x), particles (5.86x), exp (6.46x).
- About 10x: n-bodies (10.0x), sort (10.3x), interop (10.7x), tree (10.7x).
- Typed vs dynamic: the gap is 1.0-1.3x except spectral norm (5.9x: the typed A(i, j) is grafted, the
  untyped one is a real call) and mandelbrot (1.8x). Dynamic is faster than typed on particles, tree,
  dict and string2float by a few percent.
- Interpreter: 11x Lua on the geometric mean, 20-44x on the call- and loop-bound kernels.

## What the profiles say (VMPROF build, `-DCMAKE_CXX_FLAGS=/DJAISCRIPT_VM_PROFILE`, rdtsc cycles
under instrumentation; ratios between opcodes are the signal, not the absolute numbers)

- **n-bodies** (`advance` 98%): the inner j loop is ~43 dispatches per iteration. `MEMBER_TEMP` 21%
  (87 cyc avg, 14.7M), `SET_MEMBER_VALUE` 14% (139 cyc), `sqrt` as a host call 12%
  (`CALL_FROM_SCRATCH` 427 + `PROBE_CALLEE` 143 cyc per sqrt), `INDEX_FUSED` + `DECL_REF_VALUE`
  for `Body& bj = bodies[j]` ~230 cyc. The census rejects `bodies`/`bj` (address-taken references)
  and marks every member-read temp "unproven kernel definition", so the loop never becomes a cell
  block and every float read through `Body&` boxes. Hottest line: `float distance = sqrt(...)`.
- **particles** (`update` 59% of the profile incl. setup): the range-for over `array<Particle>` with
  `p.pos.x = p.pos.x + p.vel.x` runs entirely on general opcodes: `GET_MEMBER` (85 cyc, 16.8M),
  `LOAD` (94), generic `BINARY` (226), `STORE` (306), `SET_MEMBER` (106). No typed lane touches the
  nested value-class member chain. The first of the three statements costs 4.7x each of the other
  two (2439 vs ~520 Mcyc for equal op counts). Probe: 1M element updates take 1057 ms nested
  (`p.pos.x`) vs 402 ms with the six floats flattened into one class; range-for vs `P& p = ps[i]`
  makes no difference.
- **sort**: the builtin sort is 89% of cycles and the comparator lambda body 6%; the native-to-script
  comparator crossing is ~565 cyc per compare (5.25M compares per 100k-element sort). Lua's
  `table.sort` crosses C to Lua too and is 10x cheaper.
- **tree**: `split`/`merge` recursion with `shared_ptr<Node>&` out-parameters: `CALL_FROM_SCRATCH`
  733 cyc avg (41%), `STORE` through reference parameters 238 cyc, `HALT` (void return) 218 cyc per
  call, `LOAD` 3.8M.
- **fib recursive**: pure call floor: `CALL_FROM_SCRATCH` 245 + `RETURN_BINARY`/`RETURN_IDENT`
  ~250 + `PROBE_CALLEE` 45 cyc per call against ~60 cyc of body.
- **interop / exp**: the loop closes as a cell block (`CELLS_CFOR_BACK`), and the host call inside it
  costs ~100 ns (113 ns per `add_one`, ~110 ns per `exp`) vs ~10 ns for a Lua C function.
- **spectral norm dyn**: `A(i, j)` stays a real call (2M `CALL_FROM_SCRATCH` + `RETURN`, ~500 cyc
  per call); the typed version runs it grafted.

## Investigation leads (ordered by expected payoff on this suite)

1. Host-call crossing (interop, exp, n-bodies' sqrt, any math builtin): ~100 ns per call. Intrinsic
   opcodes for proven-float `sqrt`/`exp`/`abs`/`floor`, and a direct typed thunk for registered
   `(script_int|script_float...) -> scalar` functions, skipping the script_value argument vector and
   `checked_result` wrapping.
2. Members of class elements reached through `T&` / range-for `auto&` (n-bodies, particles): member
   reads and stores through an element reference never reach the typed/cell lanes; nested value-class
   members (`p.pos.x`) fall to fully generic `GET_MEMBER`/`BINARY`/`STORE`. Proving the field kind of
   a typed class member read (class fields are declared `float`) would let the census accept the
   temps, and an element-reference alias would let the loop close as a cell block.
3. Script comparator in `sort` (and any native-to-script callback): ~565 cyc per invocation; run the
   comparator in-loop on a reused frame, or recognize `a > b` / `a < b` lambdas and sort natively.
4. Call floor (fib, tree, spectral dyn): ~550 cyc per call/return pair under the profiler; void
   returns through `HALT` at 218 cyc; stores through reference parameters at 238 cyc.
5. Untyped callees are not grafted (spectral norm dyn 5.9x typed): grafting could key on the call
   site's argument kinds at compile time where the checker proves them.
