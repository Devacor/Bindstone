## Rules this pass ran under

- 4%+ is the headline bar; consistent, proven 2-3% wins are acceptable when the
  complexity is proportionate (Dev, this session). Anything below that or unproven is
  reverted, and the row says so.
- Zero non-const static / thread_local state. Engines are not internally thread-safe,
  but distinct engines on distinct threads must never touch shared mutable state.
- checked_result stays; starve it (fewer dispatches, cheaper success tests), never
  replace it with throws. Engine code throws only at host boundaries.
- Interned ids everywhere; no strings on hot paths.
- Both backends byte-identical (results, error codes, error text). A concession on
  error text needs a pinned test per backend and a row here. None were needed.
- Interpreter is the oracle and must not lose: every increment re-runs the full suite
  on both backends and the three same-seed hash tripwires on both backends.
- Value semantics stay; the ruled call-result binding change (`var p = f()` copies /
  `var& p = f()` aliases) is out of scope; the return path stays copy-free.
- **Representation follows the declared type** (Dev, this session, after the typed-storage
  finding): `array<int>`/`array<float>` are raw buffers, period; `array<var>` is the only
  `script_value`-vector form; converting between them is an explicit language step
  (`array<var> x = ints;`); nothing demotes silently (a demote is a full copy the type
  never asked for); no Debug/Release behavior difference; `bound_array` keeps its
  in-place C++ mutation contract; maps follow the same rule (next campaign).

## Findings that named the increments

- **STORE @ 282 cyc (5.2% of GLOOM) was ONE store.** A profile-only taxonomy added to
  `exec_store` (cycles by landing path + by symbol name, permanent in the Profile
  dump) attributed 101 of STORE's ~108 Mcyc to 192 stores of `pix` at 527k cycles
  each: `render.jai:331 pix = G.bg` through a `var&` param, one per frame, deep-copying
  an UNTYPED 4000-int array element by element (~130 cyc per scalar element through
  an out-of-line `clone()` call). Slot stores are 38 cyc; env-cell stores are rare
  (31 per 200 ticks). The general fix is in the shared clone kernel (#3).
- **Typed array storage is OFF everywhere except the GLOOM host.** `engine::typed_array_storage_`
  defaults to false (typed_array_design.md: "scaffold flag, default OFF — DELETE when the
  default flips after stage 3 bake"); only `gloom_adapter_jai.cpp` sets it. So in the runner
  (the whole DOOM tape), the test suite and Bindstone, every `array<int>`/`array<float>` is
  32-byte heterogeneous storage: the new copy rows show a typed 1000-int copy at 120 µs vs
  89 µs untyped (a per-element rebuild walk instead of one 8 KB memcpy), and the Release
  micro `typedcopy2.jai` shows 6 ns per element flat across sizes for typed→typed copies.
  (History: #5 measured it behind an opt-in flag; Dev then ruled it the representation and
  #6 removed the flag altogether.)
- The Profile config does not reproduce Release's operand-ladder cost (#1 read as
  neutral in the profile but −1.5% in Release): rank with the profile, decide with
  Release walls and Foundry rows, as the protocol says.

## Follow-on campaign: typed representation for every element type (Dev's direction)

Ruled tonight, not yet built — in the order I would take them:

1. **`array<auto>` inference from a uniform literal.** LANDED as #7 (both `auto` and
   `array<auto>`; mixed literals stay rejected by the validator; empty/nested/object stay
   dynamic).
2. **More primitive kinds**: LANDED as #8 (bool/char byte buffers) and #9 (string handle
   buffer). Byte/string kinds box through get/set in the INDEX family; raw INDEX lanes for
   bool/char (and a `raw_bool` decl sink) are the remaining per-op win there.
3. **Object kind for user types** (`array<CreatureBase>`): node pins the class, stores
   handles (8 bytes), homogeneous by declared class. Boundary: `std::vector<std::shared_ptr<Base>>`
   / `std::vector<Base*>` bind with ONE class check per array (hybrids hand over their
   C++ object pointer), no per-element probing. Needs the hybrid layer's upcast rule and
   the reference holder's element mode for object buffers.
4. **Maps follow the same rule**: `map<string,int>` etc. get typed key/value storage;
   `map<var,var>` is the only dynamic form. Ordering contract (`script_map` stays ordered)
   holds; the win is key compare + value footprint.
5. **parallel_transform stage 3**: workers read typed buffers raw (today: a boxed snapshot
   of a typed input, no demote).
6. ~~Zero-copy `std::vector<script_int>&` parameters~~ — not applicable (#9b): the binder
   rejects container references by design; `bound_array<T>&` is the buffer-binding path.
