# Environment LOAD cost controls, 2026-09-10

The environment-read cost changes with the number of read sites in a loop. These controls quantify the full LOAD-and-discard path and its difference from a local read. They do not establish a universal nanoseconds-per-LOAD constant to multiply by a whole-program instruction count.

The measured library is fixed master `ed7c3bd0bd67f9855c67a8711a73633cd196ef3b`.

## Raw loop cost

Each function has the same loop control and returns its iteration count. The body reads an unchanged integer either from `GLOBAL_VALUE` or from a local initialized from it, then discards the result. The three bodies contain one, four or eight read statements. The table is nanoseconds per whole loop iteration, including all reads and loop control.

Each value is the median of six accepted processes. The padding band is the range of the six matched normal-to-padding percentage changes. The padding executable adds 40 retained volatile statements in its unexecuted help function.

## Marginal LOAD plus POP

A second estimate subtracts the one-site loop from the four-site loop, or the four-site loop from the eight-site loop, then divides by the added read count. Each subtraction matches round, repetition and layout; the values are medians of six differences. Loop control cancels to first order. The estimate still includes LOAD dispatch, value copying, POP and value release.

| Source | Added-site interval | Normal ns/added read | Padding ns/added read | Derived padding band |
|---|---|---:|---:|---:|
| global | 1 to 4 | 8.215 | 7.807 | -6.69% to -4.35% |
| global | 4 to 8 | 11.652 | 10.990 | -6.59% to -4.61% |
| local | 1 to 4 | 5.812 | 5.592 | -5.17% to -0.42% |
| local | 4 to 8 | 5.695 | 5.564 | -12.76% to +10.07% |

Local marginal cost is close across the two intervals. Environment marginal cost rises for the larger body. The cause of that nonlinearity was not isolated; cache behavior, instruction placement and dispatch interactions require separate experiments. No allocation rate or isolated lookup-function latency is inferred from it.

The environment in this control is stable, with one unchanged scalar global and a simple function frame. It does not model member lookup, mutable scope chains, cache invalidation, property references or the fused operands in JaiDOOM's renderer. The [JaiDOOM count attribution](JAIDOOM_GENERAL_ROWS.md) identifies the relevant source functions and separates standalone LOADs from fused accesses; multiplying its total LOAD count by one of these micro estimates would not produce a defensible savings budget.

## Method and verification

One Intel Core Ultra 9 285HX P core, logical CPU 0. Every process warms 65,536 iterations, then executes eight measured invocations of 4,000,000 iterations each. It verifies the result of every invocation. Three rounds interleave read-site count, environment/local source and both layouts, with two repetitions per round. The accepted projection for every comparison retains the interleaving. One workload process runs at a time, after Fable releases the machine; competing processes and background load above 1.0 core-equivalent reject a timing attempt.

The host uses the Release options recorded in the [fixed-master whole-program report](../../examples/gloom/ports/RESULTS_FIXED_MASTER_2026-09-10.md): MSVC 19.51.36252, x64, `/O2 /Ob2 /Oi /Ot /GL /Zi /MT /DNDEBUG`, `/LTCG /OPT:REF /OPT:ICF /DEBUG:FULL /INCREMENTAL:NO`. No VM profiling is compiled into the measured executable. The engine uses the VM backend, disabled execution budget and parameter-alias support, matching the earlier technique controls. The cold padding function is never called.

Astra ran 87 processes: 72 accepted timings and 15 busy-machine exclusions. Every process exited zero and produced the exact expected result. An independent audit re-parsed every output, verified all input hashes and the exact accepted plan, recomputed screening verdicts, and recomputed the medians and padding bands. There are no omitted slow accepted samples.

The freshly linked fixed-library binaries also passed 24 short correctness checks across all six functions, both backends and both layouts. A separate instrumented parent build at `4bd53021` verified one LOAD and one POP per read site, identical loop-control counts, and the intended environment-versus-frame-slot operand encoding. Its timings were discarded. Reading the minimal `ed7c3bd0` compiler correction establishes that it changes the guarded metadata read in the lifted-expression path; these simple identifier-read loops do not use that path. The measured binaries and fixed library are identified separately from the parent counter capture in the raw evidence.

This is a cost experiment on one machine, not a measured optimization. Whole-program gains require their own hash-checked comparison. The wider eight-site padding bands and the changing environment slope limit the precision of any extrapolation.
