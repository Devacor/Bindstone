    From JavaScript​

    JaiScript takes two words from JavaScript: var for a variable that holds anything, and function for declaring one. Template strings with ${...}, null, ?., array literals and try/catch/throw of any value read the same as well. Underneath, the contract is C++'s: assignment copies (arrays and objects included), int and float are separate types, a class declares its fields, a lambda names what it captures, and a static checker reads the whole program before its first statement runs. This page sets the two languages side by side, then lists the places where a JavaScript habit gets a different answer. Every JaiScript line on it was run on both backends, and the output under each sample is what they printed.

    Side by side​

    Watch out​

    The differences below are the ones a JavaScript habit runs into first. Each sample shows what JaiScript does.

    Assignment copies arrays and objects​

    In JavaScript, b = a makes two names for one array. In JaiScript it makes a second array, and the same holds for class instances and for by-value parameters. Share on purpose with a handle (new, shared_ptr<T>), or alias with a reference (auto&, a var& parameter):

    jaiscript
    var a = [1, 2, 3];
var b = a;                     // a copy
b.push(4);

class Hero { int hp = 10; }
Hero h = Hero();
Hero other = h;                // a copy too
other.hp = 1;

shared_ptr<Hero> s = new Hero();
auto alias = s;                // a handle: both names reach one object
alias.hp = 99;

function add_item(var& list, string item) { list.push(item); }
var bag = [];
add_item(bag, "rope");         // a reference parameter reaches the caller's array
print(a.size(), " ", b.size(), " ", h.hp, " ", s.hp, " ", bag.size());
    output
    3 4 10 99 1

    Value Semantics & References is the chapter to read first.

    == compares contents, and never converts​

    Two arrays, maps or instances are equal when their contents are; same_object(x, y) asks whether they are one object. There is no === (writing one is an error that points to ==) and nothing to need it: == never turns a string into a number.

    jaiscript
    print([1, 2] == [1, 2], " ", {"a": 1} == {"a": 1});
var a = [1, 2];
var b = a;
print(same_object(a, b));      // b is a separate array with equal contents
print(1 == "1", " ", 1 == 1.0);
    output
    true true
false
false true

    Integers and floats are different numbers​

    An int divided by an int is an int. Integer overflow and division by zero raise errors that catch sees, instead of producing Infinity:

    jaiscript
    print(7 / 2, " ", 7 / 2.0, " ", 0.1 + 0.2);
int big = 9223372036854775807;
try { big += 1; } catch (e) { print("caught: ", e); }
try { print(1 / 0); } catch (e) { print("caught: ", e); }
    output
    3 3.5 0.30000000000000004
caught: Integer overflow in '+='
caught: Division by zero

    + converts a number to text; += does not​

    + with a string on either side turns the other side into text, left to right as in JavaScript. += onto a string accepts only strings and chars, so a number is spelled to_string(n) there:

    jaiscript
    print("hp: " + 10, " / ", 1 + "0", " / ", "v" + 1 + 2);
string label = "hp: ";
var n = 10;
try { label += n; } catch (e) { print("caught: ", e); }
label += to_string(n);
print(label);
    output
    hp: 10 / 10 / v12
caught: Cannot apply '+=' to string and int
hp: 10

    Written with a literal (label += 10;), the same mistake is a load error.

    Empty containers are false​

    0, 0.0, "", null and an empty array or map are false in a condition; everything else is true. JavaScript treats [] and {} as true. A class instance is true unless its class declares bool to_bool(), which if (v) calls and !v negates:

    jaiscript
    var values = [0, 0.0, "", [], {}, null, "0", [0]];
for (var v : values) { print("{} {}", to_json(v), v ? "true" : "false"); }
    output
    0 false
0.0 false
"" false
[] false
{} false
null false
"0" true
[0] true

    switch breaks by default​

    A case ends at the next case. fallthrough; is how a case continues into the one below:

    jaiscript
    function ranks(int level) {
    string t = "";
    switch (level) {
        case 1: t += "novice ";
        case 2:
            t += "adept ";
            fallthrough;
        case 3: t += "master";
    }
    return t;
}
print("[", ranks(1), "] [", ranks(2), "]");
    output
    [novice ] [adept master]

    Some string methods change the string​

    to_upper, to_lower, trim, replace_all, pad_left and the other mutators change the string they are called on and return it. The string:: functions are the versions that return a new string:

    jaiscript
    string name = "ada";
string shout = name.to_upper();          // name changes too
print(name, " ", shout);
string quiet = "BOB";
print(string::to_lower(quiet), " ", quiet);
    output
    ADA ADA
bob BOB

    Map keys​

    A bare name before a colon is the key's text, as in JavaScript; a computed key goes through []. A missing key reads null and adds nothing. A map walks its keys in key order, whatever order they were added in. A dot reads a key that exists (a missing one raises map has no member or key 'mana', where [] reads null), and a store needs []:

    jaiscript
    var key = "speed";
var stats = {speed: 3, hp: 10};          // the keys "speed" and "hp"
stats[key] = 4;
print(to_json(stats), " ", stats["mana"] == null, " ", stats.size());
print(stats.hp);
try { stats.hp = 1; } catch (e) { print("caught: ", e); }
    output
    {"hp":10,"speed":4} true 2
10
caught: Cannot assign to member of non-object type

    The array helpers​

    Arrays have JavaScript's helpers, spelled in snake_case: map, reduce, for_each, find, find_index, some, every, concat and filter, with index_of and contains for indexOf and includes, and insert(i, x) for an insert by splice. A callback takes the element, or the element and its index; a predicate answers with true. There is no shift or splice:

    jaiscript
    var a = [1, 2, 3, 4];
print(to_json(array::map(a, x => x * 2)), " ", a.reduce((sum, x) => sum + x, 0), " ", a.find(x => x > 2));
print(a.find_index(x => x > 9), " ", a.some(x => x > 3), " ", a.every(x => x > 0));
a.for_each((x, i) => print(i, "=", x));
var b = array::concat(a, [5]);
b.insert(0, 0);
print(to_json(b), " ", to_json(a));
    output
    [2,4,6,8] 10 3
-1 true true
0=1
1=2
2=3
3=4
[0,1,2,3,4,5] [1,2,3,4]

    Dot map, filter, concat and slice change the array; the matching array:: functions return new arrays. A map's filter pairs the same way: m.filter(f) keeps the entries in m, map::filter(m, f) returns a new map. insert, sort and remove_if also mutate. Dot map retains the input element type; array::map returns an array<T> when its callback declares return type T, and an array of anything otherwise. A callback whose element parameter is T& gets the live element, so a.for_each([](int& x) { x *= 2; }) doubles every element, as std::for_each does in C++.

    A function expression closes over its scope; a lambda names what it captures​

    A function(...) expression is JavaScript's closure: it shares the variables of the function around it, and they outlive that function, so the counter is safe to return. In lambda terms it is [&]. An arrow function, () => { ... }, closes over its scope the same way:

    jaiscript
    function make_counter() {
    int count = 0;
    return function() { count += 1; return count; };
}
var next = make_counter();
next();
print(next());
    output
    2

    A lambda names what it captures, as C++ does: [] captures nothing, and using a local of the function around it is a load error that names it; [&] shares the variable, [=] or [count] copies it:

    jaiscript
    function broken() {
    int count = 0;
    return []() { return count; };
}
    output
    == error: Parse error: <script>:3:26: Lambda capture list does not capture enclosing local 'count'; name it or use [=] or [&]

    A copy is taken when the lambda is made, so a loop that collects callbacks sees each iteration's value, as let does in JavaScript:

    jaiscript
    var callbacks = [];
for (int i = 0; i < 3; i++) { callbacks.push([i]() { return i; }); }
for (auto cb : callbacks) { print(cb()); }
    output
    0
1
2

    Declare before use​

    Top-level code runs from the top down, and nothing is hoisted: a function is defined when execution reaches its declaration. A function body may call one declared further down, because the body runs later:

    jaiscript
    print(double_it(4));
function double_it(int x) { return x * 2; }
    output
    == error: Undefined variable 'double_it'

    print shows a container's kind​

    print(a, b) joins its arguments with no separator, and a container prints as [array] or [map]; to_json prints the contents. An instance prints its class's to_string(), as "text" + x does. A first argument that holds {} is a format string, so data that might contain braces goes in a placeholder:

    jaiscript
    var a = [1, 2];
print(a);
print(to_json(a));
print("{} and {}", 1, "two");
print(1, 2, 3);
var empty = {};
print(to_json(empty), " entries");         // "{}" is read as a placeholder
print("{} entries", to_json(empty));
class Tag { string to_string() { return "<tag>"; } }
print(Tag());
    output
    [array]
[1,2]
1 and two
123
 entries
{} entries
<tag>

    A complete program​

    A small quest log in the shape a JavaScript program would take: a shared object holding a map, listeners registered as closures, a generator feeding events, and JSON out.

    jaiscript
    class QuestLog {
    var quests = {};                          // quest name -> progress
    array<function> listeners = [];

    void on_change(function f) { listeners.push(f); }

    void advance(string name, int by) {
        int now = quests.contains(name) ? quests[name] + by : by;
        quests[name] = now;
        for (auto& f : listeners) { f(name, now); }
    }
}

shared_ptr<QuestLog> journal = new QuestLog();      // one shared object, like a JavaScript object
array<string> messages = [];
journal.on_change([](string name, int progress) {
    messages.push(`${name}: ${progress}%`);         // messages is program scope: read when the listener runs
});

coroutine events() {
    yield ["rats", 50];
    yield ["relic", 25];
    yield ["rats", 50];
}
for (auto ev : events()) { journal.advance(ev[0], ev[1]); }

var done = [];
for (auto kv : journal.quests) {
    if (kv.second >= 100) { done.push(kv.first); }
}
print(messages.join(" | "));
print("done: ", done.join(", "));
print(to_json(journal.quests));
    output
    rats: 50% | relic: 25% | rats: 100%
done: rats
{"rats":100,"relic":25}
