    From JavaScript​

    JaiScript shares JavaScript's surface: var, let and function, arrow functions, template strings with ${...}, null, ?. and ??, array literals, and try/catch/throw of any value.

    Underneath, the contract is C++'s, and five differences account for most surprises:

    • Assignment copies, arrays and objects included. Sharing is explicit: a handle (new) or a reference (auto&).
    • int and float are separate types, and nothing converts between text and numbers on its own.
    • A method changes its receiver. a.sort(), a.filter(f) and s.to_upper() work in place and return nothing; array::filter(a, f) and string::to_upper(s) return copies.
    • A class declares its fields, and a map is not an object: a key is read with m["key"], never m.key.
    • A static checker reads the whole program before its first statement runs, so many mistakes stop the load instead of surfacing later.

    Ported side by side​

    Five small JavaScript programs and their JaiScript ports. Each pair was run, with Node and on both JaiScript backends, and printed the output shown. The ports use the JavaScript spellings JaiScript shares (let, const, function, arrow functions, ??); Functions sets them beside the C++ ones.

    An array pipeline​

    javascript
    const scores = [72, 95, 40, 88, 61];
const passed = scores.filter(s => s >= 60).map(s => s + 5);
passed.sort((a, b) => b - a);
const total = passed.reduce((sum, s) => sum + s, 0);
console.log(`passed: ${passed.join(", ")}`);
console.log(`average: ${(total / passed.length).toFixed(1)}`);
console.log(`best: ${passed[0]}, any perfect: ${passed.some(s => s === 100)}`);
    jaiscript
    const scores = [72, 95, 40, 88, 61];
let passed = array::map(array::filter(scores, s => s >= 60), s => s + 5);
passed.sort((a, b) => a > b);
const total = passed.reduce((sum, s) => sum + s, 0);
print(`passed: ${passed.join(", ")}`);
print(`average: ${1.0 * total / passed.size():.1f}`);
print(`best: ${passed[0]}, any perfect: ${passed.some(s => s == 100)}`);
    output
    passed: 100, 93, 77, 66
average: 84.0
best: 100, any perfect: true
    • filter and map as methods work in place, so a pipeline that builds new arrays calls array::filter and array::map.
    • A sort comparator answers "does a go first?" with a bool. / on two ints is integer division, hence 1.0 *, and a format spec replaces toFixed.

    A generator and a thrown class​

    javascript
    class ParseError extends Error {
  constructor(line, text) { super(`line ${line}: ${text}`); this.line = line; }
}
function* numbers(lines) {
  let n = 0;
  for (const text of lines) {
    n++;
    if (isNaN(Number(text))) { throw new ParseError(n, `"${text}" is not a number`); }
    yield Number(text);
  }
}
let sum = 0;
try {
  for (const value of numbers(["4", "8", "x", "15"])) { sum += value; }
} catch (e) {
  if (!(e instanceof ParseError)) { throw e; }
  console.log(`parse error, ${e.message}`);
}
console.log(`sum so far: ${sum}`);
    jaiscript
    class ParseError {
    int line;
    string message;
    ParseError(int l, string text) { line = l; message = `line ${l}: ${text}`; }
}
coroutine numbers(lines) {
    let n = 0;
    for (let text : lines) {
        n++;
        if (text.to_int() == null) { throw ParseError(n, `"${text}" is not a number`); }
        yield text.to_int();
    }
}
let sum = 0;
try {
    for (let value : numbers(["4", "8", "x", "15"])) { sum += value; }
} catch (ParseError e) {
    print(`parse error, ${e.message}`);
}
print(`sum so far: ${sum}`);
    output
    parse error, line 3: "x" is not a number
sum so far: 12
    • function* becomes coroutine, and a range-for drives it. Any value can be thrown, so the error class extends nothing.
    • catch (ParseError e) selects by type, which replaces the instanceof test and the rethrow. to_int() answers null for text that is not a number.
    • A range-for variable is written let (or auto); a bare const is not accepted there.

    Assignment copies; == compares contents​

    jaiscript
    var a = [1, 2, 3];
var b = a;                     // a copy: b = a makes a second array
b.push(4);

other.hp = 1;

    3 4 10 99

FFFFFFTT
    • Copies. b = a copies an array, a map or a class instance, and so does passing one by value; a var& parameter reaches the caller's. Value Semantics & References is the chapter to read first.
    • Equality. == compares arrays, maps and instances by contents, and same_object(x, y) asks whether they are one object. == never converts: an int compared with a string is a load error when the checker sees it (Types That Fail Early) and false through a var.
    • Numbers. Integer overflow and integer division by zero raise errors that catch sees; float division by zero gives inf.
    • Truthiness. 0, 0.0, "", null and an empty array or map are false; JavaScript treats [] and {} as true. An instance is true unless its class declares bool to_bool().

    Closures​

    jaiscript
    function make_counter() {
    int count = 0;
    return () => { count += 1; return count; };     // shares count, which outlives make_counter
}
auto next = make_counter();
next();
var callbacks = [];
for (int i = 0; i < 3; i++) { callbacks.push(() => i); }
int total = 0;                                      // program scope
auto bank = [](int n) { total += n; };              // read and written when the lambda runs
bank(5);
print(next(), " ", callbacks[0](), callbacks[1](), callbacks[2](), " ", total);
    output
    2 012 5
    • An arrow function or a function(...) expression is JavaScript's closure: it shares the variables around it.
    • A C-style for variable is each iteration's own for the closures that share it, as let is in JavaScript: the loop above gives 0 1 2.
    • A C++-style lambda names what it captures. [] captures nothing, and using an enclosing function's local in one is a parse error: lambda capture list does not capture enclosing local 'count'; name it or use [=] or [&]. Program-scope variables need no capture (Lambdas and captures).
