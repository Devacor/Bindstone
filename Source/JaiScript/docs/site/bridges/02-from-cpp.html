    From C++​

    JaiScript reads like C++ and keeps C++'s semantics as its contract: classes are value types that copy, references are declared with &, destructors run when a scope ends, operators overload, and auto, range-for, capture lists, switch and try/catch mean what they mean in C++, with C++17's left-to-right evaluation order. What it leaves out is the machinery a script does not need: raw pointers, delete, templates, const, headers and undefined behavior. Integers are 64-bit, overflow and division by zero raise errors a catch sees, a switch never falls through by accident, and a static checker reads the whole program before its first statement runs. From JavaScript it borrows var for a dynamic variable and the function keyword. This page sets the two languages side by side, then lists the places where a C++ habit gets a different answer. Every JaiScript line on it was run on both backends, and the output under each sample is what they printed.

    Side by side​

    Watch out​

    The differences below are the ones a C++ habit runs into first. Each sample shows what JaiScript does.

    switch does not fall through​

    A case ends at the next case, with no break. fallthrough; (C++'s [[fallthrough]]) continues into the case below:

    jaiscript
    int hits = 0;
switch (1) {
    case 1: hits += 1;          // ends here
    case 2: hits += 10;
}
switch (1) {
    case 1:
        hits += 100;
        fallthrough;            // continue into case 2
    case 2: hits += 1000;
}
print(hits);
    output
    1101

    Free functions do not overload​

    Inside a namespace or a class, overloads by parameter count (and, for methods, by type) work as in C++:

    jaiscript
    namespace geo {
    int area(int side) { return side * side; }
    int area(int w, int h) { return w * h; }
}
print(geo::area(4), " ", geo::area(2, 3));
    output
    16 6

    At program scope a second definition of a name replaces the first, which is what hot reload needs. The checker notes the duplicate as a warning (jaiscript --check=warn prints it), and the old arity is gone:

    jaiscript
    int area(int side) { return side * side; }
int area(int w, int h) { return w * h; }     // replaces the one above
print(area(2, 3));
print(area(4));
    output
    6
== error: 'area' expects 2 arguments, got 1

    A base-typed variable keeps the whole object​

    Copying a derived value into a base-typed variable, parameter or element keeps all of it: no slicing. The variable's type decides what the checker lets you name, and cast<T&> reaches the rest:

    jaiscript
    class Shape { string kind() { return "shape"; } }
class Circle : Shape { float r = 1.5; string kind() override { return "circle"; } }
Shape s = Circle();
array<Shape> all = [Shape(), Circle()];
print(s.kind(), " ", type_of(s), " ", all[1].kind(), " ", cast<Circle&>(s).r);
    output
    circle Circle circle 1.5

    Arithmetic has no undefined behavior​

    Signed overflow and division by zero, integer or float, raise an error that catch sees and leave the target untouched. Shifts wrap modulo 264, and math::wrap_add, wrap_sub and wrap_mul wrap on purpose. An int is 64 bits everywhere:

    jaiscript
    int big = 9223372036854775807;
try { big = big + 1; } catch (e) { print("caught: ", e); }
try { print(10 / 0); } catch (e) { print("caught: ", e); }
try { print(1.0 / 0.0); } catch (e) { print("caught: ", e); }
print(1 << 63, " ", math::wrap_add(big, 1), " ", 2147483647 + 1);
    output
    caught: Integer overflow in '+'
caught: Division by zero
caught: Division by zero
-9223372036854775808 -9223372036854775808 2147483648

    Evaluation order is defined​

    The C++17 rule, everywhere: the callee, then its arguments left to right; for an assignment, the right side first, then the target (its container, then its index):

    jaiscript
    string log = "";
int note(string s, int v) { log += s + " "; return v; }
int add(int a, int b) { return a + b; }
array<int> slots = [0, 0];
int r = add(note("first", 1), note("second", 2));
slots[note("index", 0)] = note("value", 7);
print(log, "| ", r, " ", slots[0]);
    output
    first second value index | 3 7

    Reference parameters and literals​

    There is no const. A reference parameter that the body never writes through takes a literal or a temporary, as const T& does, and a variable still binds with no copy. A string& takes a literal too, as a writable temporary:

    jaiscript
    int total(array<int>& xs) { int s = 0; for (auto x : xs) { s += x; } return s; }
void upper(string& s) { s.to_upper(); print(s); }
print(total([1, 2, 3]));
upper("quiet");
    output
    6
QUIET

    A parameter the body does write keeps needing a variable, and the checker names the line that writes:

    jaiscript
    void bump(int& x) { x += 1; }
bump(5);
    output
    jaiscript: static check failed:
<script>:2:6: error: 'bump' writes through parameter 'x' (line 1); pass a variable
    bump(5);
         ^

    A reference capture can outlive its frame​

    [&] and [&x] move the captured local into a shared cell, so returning such a lambda is safe where C++ would leave it dangling:

    jaiscript
    function make_counter() {
    int count = 0;
    return [&count]() { count += 1; return count; };
}
auto next = make_counter();
next();
print(next());
    output
    2

    Methods are called, not taken​

    obj.method without a call is an error, and there is no pointer to member. reflect::bind(obj, "name") makes a callable that keeps the object, or a lambda wraps the call:

    jaiscript
    class Player { int hp = 5; void heal() { hp += 1; } }
Player p;
var heal = reflect::bind(p, "heal");
heal();
heal();
print(p.hp);
    output
    7

    Strings are bytes, and char is unsigned​

    s.size() and s[i] count bytes, a char promotes to an int in 0..255 under arithmetic, and the utf8_ methods (or a utf8_string) count characters:

    jaiscript
    string s = "\xC3\xA9";              // é in UTF-8: two bytes
utf8_string u = s;
print(s.size(), " ", s[0] + 0, " ", s.utf8_length(), " ", u.size());
    output
    2 195 1 1

    What is not there​

    Raw pointers (T*, &x, delete), templates, const and constexpr, unsigned and sized integer types, struct, virtual, mutable, enum class, goto, typed catch clauses, static_cast (spelled cast) and sizeof. &x, delete, const, virtual, goto and a typed catch are parse errors that name the JaiScript spelling; the others fail as a parse error, a load error or an error when the line runs, and the message does not name the missing feature, so a puzzling message on a C++-shaped line is worth checking against this list.

    A complete program​

    A small simulation step in the shape a C++ programmer would write it: value types with operators, a reference parameter for the hot loop, a scope guard whose destructor marks the end of each step, and a snapshot that is a real copy.

    jaiscript
    class Vec2 {
    float x = 0.0;
    float y = 0.0;
    Vec2() {}
    Vec2(float px, float py) { x = px; y = py; }
    Vec2 operator+(Vec2 o) { return Vec2(x + o.x, y + o.y); }
    Vec2 operator*(float k) { return Vec2(x * k, y * k); }
}
class Body {
    string name;
    Vec2 pos;
    Vec2 vel;
    Body() {}
    Body(string n, Vec2 p, Vec2 v) { name = n; pos = p; vel = v; }
}
class Scope {
    string label;
    Scope(string l) { label = l; print("begin ", label); }
    ~Scope() { print("end ", label); }
}
void step(array<Body>& bodies, float dt) {
    Scope guard = Scope("step");
    for (auto& b : bodies) { b.pos = b.pos + b.vel * dt; }
}

array<Body> world = [Body("ship", Vec2(0.0, 0.0), Vec2(2.0, 1.0)),
                     Body("rock", Vec2(10.0, 0.0), Vec2(-1.0, 0.0))];
array<Body> snapshot = world;            // a deep copy, like std::vector<Body>
step(world, 0.5);
step(world, 0.5);
for (auto& b : world) { print(`${b.name}: (${b.pos.x:.1f}, ${b.pos.y:.1f})`); }
print(`snapshot ship: (${snapshot[0].pos.x:.1f}, ${snapshot[0].pos.y:.1f})`);
    output
    begin step
end step
begin step
end step
ship: (2.0, 1.0)
rock: (9.0, 0.0)
snapshot ship: (0.0, 0.0)
