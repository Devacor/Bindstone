    From C#​

    Much of JaiScript's surface will look familiar from C#: classes with constructors and : this(...) chaining, a required override, static members, properties (spelled as accessor methods), foreach-style loops, try/catch/throw, lambdas, namespaces, and yield for iterators. The semantics underneath are C++'s, and the largest consequence is that a class is a value type: b = a copies the object, the way a C# struct copies. new makes the shared reference that every C# class is. JaiScript's var is the dynamic one, C#'s dynamic; auto is C#'s var. Integers are 64-bit and checked, and a static checker reads the whole program before its first statement runs. This page sets the two languages side by side, then lists the places where a C# habit gets a different answer. Every JaiScript line on it was run on both backends, and the output under each sample is what they printed.

    Watch out​

    The differences below are the ones a C# habit runs into first. Each sample shows what JaiScript does.

    A class is a value type​

    This is the one to learn first. Assignment, a by-value parameter and a by-value return copy the whole object, as with a C# struct. new gives the shared reference a C# class always is, and a & parameter is C#'s ref:

    jaiscript
    class Account { int balance = 0; }
Account a = Account();
Account b = a;                  // a copy
b.balance = 50;
print(a.balance, " ", b.balance);

shared_ptr<Account> shared = new Account();   // a shared reference
auto other = shared;
other.balance = 50;
print(shared.balance, " ", other.balance);

void deposit(Account acct) { acct.balance += 10; }        // gets a copy
void deposit_ref(Account& acct) { acct.balance += 10; }   // like ref Account
deposit(a);
deposit_ref(a);
print(a.balance);
    output
    0 50
50 50
10

    Value Semantics & References is the chapter on this, with the cost of each choice.

    A list holds values​

    An array<Unit> holds the units themselves. A loop variable without & is a copy, so changes to it vanish; auto& names the element, and a method called through an element changes that element. An array of handles behaves like a C# List<Unit>:

    jaiscript
    class Unit { int hp = 10; void hit() { hp -= 1; } }
array<Unit> units = [Unit(), Unit()];
for (auto u : units) { u.hp -= 5; }        // u is a copy
print(units[0].hp);
for (auto& u : units) { u.hp -= 5; }       // u is the element
units[1].hit();
print(units[0].hp, " ", units[1].hp);
array<shared_ptr<Unit>> handles = [new Unit()];
for (auto h : handles) { h.hp = 1; }       // copies of a handle share the object
print(handles[0].hp);
    output
    10
5 4
1

    var is dynamic; auto is C#'s var​

    A var takes anything for its whole life. An auto takes its type from the initializer and keeps it, converting what it can as an int variable would:

    jaiscript
    var loose = 5;
loose = "now text";
auto locked = 5;
locked = 9.7;                   // converts: locked stays an int
print(loose, " ", locked);
    output
    now text 9

    A value of the wrong type for an auto is a load error when the checker can see it:

    jaiscript
    auto locked = 5;
locked = "text";
    output
    jaiscript: static check failed:
<script>:2:9: error: cannot assign 'string' to 'locked' declared 'int' (declared at 1:6)
    locked = "text";
            ^

    Properties are accessor methods​

    A plain field already reads and writes as obj.x. A computed property is a pair of methods, _get_x() and _set_x(v), and obj.x goes through them; inside the class a bare x is the backing field, if there is one:

    jaiscript
    class Thermostat {
    float celsius = 20.0;
    float _get_fahrenheit() { return celsius * 9.0 / 5.0 + 32.0; }
    void _set_fahrenheit(float f) { celsius = (f - 32.0) * 5.0 / 9.0; }
}
Thermostat t;
t.fahrenheit = 212.0;
print(t.celsius, " ", t.fahrenheit);
t.celsius = 0.0;
print(t.fahrenheit);
    output
    100.0 212.0
32.0

    Access modifiers are section labels​

    private: and public: label every member below them, as in C++; private int x; does not parse. A private member is reachable from the class and from every class derived from it, where C# would need protected:

    jaiscript
    class Base {
private:
    int secret = 7;
}
class Derived : Base {
    int reveal() { return secret; }
}
print(Derived().reveal());
var b = Base();
try { print(b.secret); } catch (e) { print("caught: ", e); }
    output
    7
caught: Cannot access private member 'secret' of class 'Base'
    jaiscript
    class Base { private int secret = 7; }
    output
    == error: Parse error: <script>:1:22: Expected ':' after 'private'

    No LINQ​

    filter, sort with a comparator, remove_if and loops cover what a LINQ chain does, in place where the name says so:

    jaiscript
    array<int> scores = [72, 95, 40, 88, 61];
// scores.Where(s => s >= 60).OrderByDescending(s => s).Take(3).Sum()
auto passed = scores.filter([](int s) { return s >= 60; });
passed.sort([](int a, int b) { return a > b; });
int top3 = 0;
for (int i = 0; i < 3 && i < passed.size(); i++) { top3 += passed[i]; }
print(to_json(passed), " ", top3);
    output
    [95,88,72,61] 255

    Coroutines instead of async​

    There is no async or await. Work that spans frames is a coroutine: each resume() runs it to its next yield, and the final return value arrives with the last resume. The host's frame loop does the resuming:

    jaiscript
    coroutine function fade(string what, int frames) {
    for (int f = 1; f <= frames; f++) { yield `${what} ${f}/${frames}`; }
    return `${what} done`;
}
auto job = fade("door", 3);
while (!job.done()) {
    print(job.resume());
}
    output
    door 1/3
door 2/3
door 3/3
door done

    print does not call to_string​

    to_string(x), "text" + x and a template splice use a class's to_string() method; print(x) on an instance prints [object]:

    jaiscript
    class Point { int x = 1; int y = 2; string to_string() { return "(" + x + ", " + y + ")"; } }
Point p;
print(p);
print(to_string(p), " ", `${p}`, " ", "at " + p);
    output
    [object]
(1, 2) (1, 2) at (1, 2)

    Strings change in place​

    A string is a value, so a copy never sees a later change, but the mutating methods change the string they are called on and return it. The string:: functions return a new string instead:

    jaiscript
    string name = "ada";
string copy = name;
string upper = name.to_upper();       // changes name and returns it
print(name, " ", copy, " ", upper, " ", string::to_lower(upper), " ", upper);
    output
    ADA ada ADA ada ADA

    Statics use ::​

    Config::volume reaches a static; Config.volume is a member lookup on the class itself and fails when it runs:

    jaiscript
    class Config { static int volume = 7; }
print(Config::volume);
print(Config.volume);
    output
    7
== error: function has no member 'volume'

    Integers are 64-bit and checked​

    There is no wrap at 231, and overflow at 263 raises instead of wrapping, as if every block were checked. math::wrap_add, wrap_sub and wrap_mul are the unchecked arithmetic:

    jaiscript
    int big = 2147483647;
print(big + 1);
int max = 9223372036854775807;
try { max += 1; } catch (e) { print("caught: ", e); }
print(math::wrap_add(max, 1));
    output
    2147483648
caught: Integer overflow in '+='
-9223372036854775808

    A complete program​

    A small shop in the shape a C# programmer would write it: a class with a read-only property and an event, a shared instance, a lambda handler, an iterator feeding customers, and a filter over the stock.

    jaiscript
    class Item {
    string name;
    int price;
    Item(string n, int p) { name = n; price = p; }
    string to_string() { return `${name} (${price}g)`; }
}
class Shop {
private:
    int gold_value = 100;
public:
    array<Item> stock = [];
    array<function> on_sale = [];
    int _get_gold() { return gold_value; }          // a read-only property
    bool sell(string name) {
        for (int i = 0; i < stock.size(); i++) {
            if (stock[i].name == name) {
                Item sold = stock[i];
                stock.remove(i);
                gold_value += sold.price;
                for (auto& h : on_sale) { h(sold); }
                return true;
            }
        }
        return false;
    }
}

shared_ptr<Shop> shop = new Shop();                 // one shared shop, like a C# reference
shop.stock = [Item("sword", 40), Item("potion", 5), Item("shield", 30)];
array<string> receipts = [];
shop.on_sale.push([](Item it) { receipts.push("sold " + it); });

coroutine customers() {
    yield "potion";
    yield "axe";
    yield "sword";
}
for (auto want : customers()) {
    if (!shop.sell(want)) { receipts.push("no " + want); }
}
auto cheap = shop.stock.filter([](Item it) { return it.price < 50; });
print(receipts.join("; "));
print("gold: ", shop.gold, ", left: ", cheap.size(), " ", to_string(cheap[0]));
    output
    sold potion (5g); no axe; sold sword (40g)
gold: 145, left: 1 shield (30g)
