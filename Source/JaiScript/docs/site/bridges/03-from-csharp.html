    From C#​

    Much of JaiScript's surface is familiar from C#: classes with : this(...) chaining, a required override, statics, accessor properties, try/catch/throw, arrow lambdas, namespaces, ?. and ??, and yield.

    The semantics underneath are C++'s. Three things to learn first:

    1. A class is a value, as a C# struct is: b = a copies the object. new Hero() makes the shared reference that every C# class is, a shared_ptr<Hero>.
    2. A class value is never null. Hero h = null; is a load error; a slot that can be empty is a shared_ptr<Hero> or a var.
    3. var is C#'s dynamic; auto is C#'s var.

    jaiscript
    class Hero {
private:
    int hp_value = 10;
public:
    static int count = 0;
    string name;
    Hero(string n) { name = n; Hero::count += 1; }
    int _get_hp() { return hp_value; }
    void _set_hp(int v) { hp_value = v < 0 ? 0 : v; }
    string describe() { return name; }
    string to_string() { return `${name} (${hp_value} hp)`; }
}
class Paladin : Hero {
    Paladin(string n) : super(n) {}
    string describe() override { return "Sir " + super::describe(); }
}
bool is_hero(var x) { try { cast<Hero&>(x); return true; } catch (e) { return false; } }

Paladin p = Paladin("Ada");
p.hp = -3;                                   // through _set_hp
var anyone = p;
print(p.describe(), " ", p.hp, " ", Hero::count, " hero: " + p);
print(type_of(anyone) == "Hero", " ", is_hero(anyone), " ", is_hero("text"));
try { throw anyone; } catch (Hero h) { print("caught a Hero: ", h.name); }
    output
    Sir Ada 0 1 hero: Ada (0 hp)
false true false
caught a Hero: Ada

    The is-a test. There is no is operator. cast<Hero&>(x) succeeds for a Hero or a subclass and raises otherwise, so the helper above answers x is Hero for any value. A typed catch (Hero h) takes a Hero or a subclass the same way. reflect::bases(x) lists a class instance's direct bases only.

    Watch out​

    A class is a value, and so is a list of them​

    Assignment, a by-value parameter and a by-value return copy the whole object. An array<Unit> holds the units themselves, so a loop variable without & is a copy. & is C#'s ref, without the keyword at the call. An array of handles behaves like a C# List<Unit>. Value Semantics & References is the chapter on this.

    jaiscript
    class Unit { int hp = 10; }
Unit a;
Unit b = a;                                  // a copy
b.hp = 50;
void hit(Unit u) { u.hp -= 1; print("inside: ", u.hp); }   // gets a copy
void hit_ref(Unit& u) { u.hp -= 1; }                        // like ref Unit
hit(a);
hit_ref(a);
print(a.hp, " ", b.hp);

array<Unit> units = [Unit(), Unit()];
for (auto& u : units) { u.hp -= 5; }         // u is the element
array<shared_ptr<Unit>> handles = [new Unit()];
for (auto h : handles) { h.hp = 1; }         // a copy of a handle shares the object
print(units[0].hp, " ", handles[0].hp);
    output
    inside: 9
9 50
5 1

    A write to a copy that nothing reads afterwards is usually a mistake, and the plainest cases fail the load (lost writes):

    jaiscript
    class Unit { int hp = 10; }
array<Unit> units = [Unit(), Unit()];
for (auto u : units) { u.hp -= 5; }
Unit nobody = null;
    output
    jaiscript: static check failed:
<script>:3:24: error: 'u.hp' writes to 'u', a copy of the element that is never read afterwards, so the write is lost; iterate with 'auto& u' to change the element
    for (auto u : units) { u.hp -= 5; }
                           ^
<script>:4:6: error: cannot initialize 'nobody' declared 'Unit' with 'null': a 'Unit' is never null; declare 'shared_ptr<Unit>' (or var) for a slot that can be empty
    Unit nobody = null;

    var is dynamic; auto is C#'s var​

    A var takes anything for its whole life. An auto takes its type from the initializer and keeps it: auto n = 5; n = "text"; is the load error cannot assign 'string' to 'n' declared 'int'.

    Integers are 64-bit and checked​

    2147483647 + 1 is 2147483648. Overflow at 263 raises Integer overflow in '+', as if every block were checked.
