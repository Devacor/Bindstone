    From nlohmann::json​

    nlohmann::json gives C++ a JSON value type: parse text into a json, read and write it like a container, and convert your own types through to_json/from_json functions or the NLOHMANN_DEFINE_TYPE_* macros. JaiScript splits those jobs in two:

    • Your own records go through the host archives (jai::to_json, jai::from_json<T>), in JSON or binary, through the same description that makes a class scriptable. The JSON they write is JaiScript's own record format (a "value0" root for a non-record, $id/$type/$val records for pointers, arrays for optional and variant). It is a save format, not interchange JSON for an external API.
    • Plain JSON, the kind a web API or a config file speaks, is the script builtins to_json and from_json, which a host can call too (below). A parsed document is a script map you index.

    There is no C++ DOM type, json_pointer, patch or SAX interface. A host that builds or validates documents for another service in C++ has reason to keep nlohmann::json for that wire and move only its saved records.

    The archives are documented in Serialization; From Cereal covers versions, polymorphic types, the JAI_PROPERTY route and converting existing files.

    The concept map​

    Headers: <jaiscript/serialization/convenience.hpp> for the host entry points; the script builtins come with jai::stdlib::register_all(eng).

    A save type converted​

    C++ (nlohmann::json)
    #include <nlohmann/json.hpp>

using nlohmann::json;

enum class Mood { calm = 0, angry = 1 };

struct Item {
    std::string name;
    int count = 1;
};
NLOHMANN_DEFINE_TYPE_NON_INTRUSIVE(Item, name, count)

struct SaveGame {
    int level = 1;
    std::string hero;
    std::vector<Item> items;
    Mood mood = Mood::calm;
};
NLOHMANN_DEFINE_TYPE_NON_INTRUSIVE(SaveGame, level, hero, items, mood)

json j = save;
std::string text = j.dump();
SaveGame back = json::parse(text).get<SaveGame>();
    text
    {"hero":"Alice","items":[{"count":1,"name":"rope"},{"count":3,"name":"torch"}],"level":7,"mood":1}

    In JaiScript each macro becomes a serialize member (Item's is ar(JAI_NVP(name), JAI_NVP(count))). This version also adds a std::optional member:

    C++ (JaiScript)
    #include <jaiscript/serialization/convenience.hpp>

struct SaveGame {
    int level = 1;
    std::string hero;
    std::vector<Item> items;
    std::optional<int> best;
    Mood mood = Mood::calm;

    template<class Archive>
    void serialize(Archive& ar) { ar(JAI_NVP(level), JAI_NVP(hero), JAI_NVP(items), JAI_NVP(best), JAI_NVP(mood)); }
};

auto eng = jai::engine::make();
std::string text = jai::to_json(*eng, save, 0);
SaveGame back = jai::from_json<SaveGame>(*eng, text);
    text
    {"level": 7,"hero": "Alice","items": [{"name": "rope","count": 1},{"name": "torch","count": 3}],"best": [true,12],"mood": 1}
    • The text is an archive record. A type saved by value writes its properties flat at the root, in call order. A root that is not a record (a number, a vector, a map) sits under "value0": jai::to_json(*eng, std::vector<int>{1, 2, 3}, 0) is {"value0": [1,2,3]}. A std::shared_ptr is written as {"$id": 1, "$val": {...}} the first time and {"$id": 1} after, so shared objects load shared, with "$type" naming a derived class (Pointers and identity).
    • The reader is forgiving about order. from_json<T> finds properties by name in any order and skips keys the type does not read, so plain JSON whose keys match loads. Optional, variant and pointer members still expect their archive shapes.
    • A missing key is an error. from_json<SaveGame>(*eng, R"({"level": 3})") throws jai::serialization_error: Property 'hero' not found during deserialization (nlohmann throws out_of_range, key 'hero' not found). Malformed text throws too: Expected '"' in JSON.

    JSON in script​

    from_json parses text into maps, arrays, numbers, strings, bool and null; to_json writes any script value back as plain JSON, with map keys in order so the same data always writes the same text (JSON in the guide). A script class instance round-trips with its class name:

    jaiscript
    var save = {"name": "orc", "hp": [10, 20], "pos": {"x": 1.5}};
string text = to_json(save);
var back = from_json(text);
print(text);
print(back["hp"][1], " ", back["pos"]["x"], " ", back.contains("gold"));
print(to_json([1, 2.5, "three", true, null]));

class Hero { string name = "Vex"; int hp = 30; }
Hero h;
h.hp = 12;
Hero copy = from_json(to_json(h));
print(to_json(h), " -> ", copy.name, " ", copy.hp);
try { from_json("{bad"); } catch (e) { print("caught: ", e); }
    output
    {"hp":[10,20],"name":"orc","pos":{"x":1.5}}
20 1.5 false
[1,2.5,"three",true,null]
{"$type":"Hero","$val":{"name":"Vex","hp":12}} -> Vex 12
caught: Expected '"' in JSON

    Nesting is bounded by memory, not by a depth limit. A host record type whose own serialize recurses natively stops at the host thread's stack, or at JAI_MAX_HOST_RECORD_DEPTH (1024) nested records where the stack cannot be asked, with Record nesting depth exceeds the host thread's stack or Maximum record nesting depth (1024) exceeded.

    JSON on the host side​

    The script builtins are functions like any other, so a host that needs plain JSON in C++ calls them through convert_script_function and works with the jai::script_value it gets back:

    C++
    auto eng = jai::engine::make();
jai::stdlib::register_all(eng);
auto parse = jai::convert_script_function<jai::script_value(const std::string&)>(eng->get_variable("from_json"));
auto dump = jai::convert_script_function<std::string(const jai::script_value&)>(eng->get_variable("to_json"));

jai::script_value doc = parse(R"({"name": "orc", "hp": [10, 20], "tag": null})");
std::string name = doc.as<std::map<std::string, jai::script_value>>().at("name").as_string();   // "orc"
std::string text = dump(doc);                                     // {"hp":[10,20],"name":"orc","tag":null}

    A document a script will use goes in as a global (eng->add_global("config", doc)), and a script can hand one back the same way.
