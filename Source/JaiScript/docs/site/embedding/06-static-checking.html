Static Checking (opt-in)​

Typed scripts can fail at load time instead of in a player's hands — exactly as strictly as their declarations ask. The checker is a backend-neutral AST pass (detail/type_checker.hpp + source/implementation/type_checker.cpp, spec in docs/static_checking.md) that runs once per unique source at parse-cache-entry creation — the same hook covers execute(string), jaibite creation/load, hot-reload re-parses, and registration changes. Off by default; the off path costs one branch.

Mode API​

C++
eng->static_checking(jai::check_mode::off | warn | strict);   // default: off
jai::check_report r = eng->check(source);                     // parse (cached) + check, ANY mode
const jai::check_report& d = eng->last_check_diagnostics();   // last checked execute/bite
  • off — zero behavior change, no diagnostics collected.
  • warn — diagnostics collected and retrievable; execution proceeds.
  • strict — any error-severity diagnostic makes execute() / jaibite() / jaibite_load*() throw jai::static_check_error before anything runs; what() is the full accumulated, location-sorted, deduplicated listing (cap 100), compiler style with source lines and carets.

Verified live (hosts/staticcheck.cpp):

(The warn demo puts the bad assignment in an if (false) branch: the checker is flow-insensitive so it still flags it, while the runtime never reaches it — showing that warn collects but never gates.)

check_diagnostic fields: severity, line, column, message, related_line/column. Diagnostics are mode-independent; mode only decides whether errors gate execution. Warning severity never gates. Every behavior in this section is pinned by a dedicated test suite.

Two rules worth calling out (both pinned by tests):

  • Compound assign follows C++ rules: typed x op= rhs behaves as x = T(x op rhs), so int x; x += 2.5 is fine (truncates) and x += "s" errors. var targets stay dynamic.
  • Typed fields are real: field initializers, member stores (obj.field = v, bare field = v in methods, inherited fields) all check against the declared type — matching the runtime's typed-field enforcement.

Other checked surfaces (each pinned by tests):

  • Calls — when the callee resolves statically: script functions/ctors/methods get arity (with defaults) + per-arg assignability; overloads error only if NO overload matches. Host C++ functions are checked through engine::host_function_signatures — arity across overloads (variadic = anything) and only per-arg certainties (note the C++ boundary has no numeric→string conversion, unlike script string slots). Callables held in variables: unchecked.
  • Returns — must be assignable to the declared return type; a value from a void function errors; bare return; from a typed fn is a warning, not an error; coroutines exempt.
  • Identifiers — undeclared = error, resolved against scopes, class members (inherited included), top-level two-pass declarations (forward references work), any name declared anywhere in the script, per-call instance variables, and the engine's full registration surface. Scripts containing include/import downgrade undeclared-identifier to warning.
  • Members — unknown field/method on a fully known class = error (reads and writes); any unresolvable ancestor opens the class to silence; builtins/subscripts/namespaces lenient; enum member existence IS checked.
  • Recovery — an erroring expression assumes its declared type, so one bad line yields one diagnostic, not a cascade.

The false-positive contract​

A program that runs clean and does not genuinely violate declared types must produce ZERO error diagnostics. Everywhere the static story is uncertain the checker goes silent (var, unknown/open classes, element types, includes, callable variables, host object conversions). Enforced mechanically: a standing gate feeds the checker 200 differential-fuzzer-generated programs — any program that executes cleanly must check clean.

This is the guarantee that makes strict deployable on a real codebase: turning it on can only reject scripts that were already broken.

jaibite stamping​

Bites created/executed under warn/strict carry diagnostics (bite.checked_clean(), bite.check_diagnostics()); save() stamps a checked-clean bit; on load the stamp is trusted only when the registration fingerprint matches, else the bite is re-checked against the loading engine (strict throws at load). Checked once — re-create to re-check. Details in the jaibite chapter.

Cost and staleness​

Zero when off. When on: one AST walk per unique source (parse-order cost, cached beside the parse), re-run only when the registration surface changes (add_function/add_global/add_class/register_template_type bump an epoch); executes with per-call instance variables re-check fresh per call. New source text (hot reload) = new cache entry = fresh check.

Deployment pattern​

The type ladder makes rollout incremental: leave prototype scripts on var (never flagged), declare types where you want enforcement, run warn in dev builds to collect diagnostics, and promote to strict in CI or at asset-bake time (eng->check(source) needs no mode and is the batch-validation entry point — it throws parse_error only if the source doesn't parse).
