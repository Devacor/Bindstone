Embedding & Engine Guide

How to put JaiScript inside a C++ engine: the two-line quickstart, binding classes, choosing a backend, precompiled .jaibite bites, safety rails for untrusted script, static checking, hot reload, serialization, coroutine hosting, signals, and the honest performance numbers. All host snippets were compiled and run against the real library.

The embedding model is settled for 1.0; the exact C++ signatures may still change in a 0.x release. Stability has both lists.

  1. Embedding Quickstart

    Build the library into your project with CMake, make an engine, run a string or a file, call script functions and read state back, register a function, bind a live C++ variable, and the three ways a script can fail.

  2. dynamic_binder: Binding C++ Classes

    Declare a field once and it is reflected, script-visible and serialized; then the fluent binder chain underneath, verb by verb, and static binders for plain structs and templates.

  3. Backends: Interpreter vs VM

    One AST, two interchangeable backends held to byte-identical behavior; when each wins and how to A/B them.

  4. jaibite: Parse Once, Ship Precompiled

    Parse once, run many; the automatic .jaibite disk cache, and shipping precompiled scripts by hand.

  5. Safety Rails

    Host-controlled filesystem access and custom named permissions: default-on file access, default-off custom grants, and requirements that survive aliases and reflection. Configure budgets, memory caps, overflow and recursion limits, and understand why an engine is not a process sandbox.

  6. Static Checking

    Strict by default: typed mistakes and undeclared names fail the load, before a statement runs. warn and off are the opt-downs, per engine or per region, plus extern, casts, program-wide checking, and the precision map of what still fails at run time.

  7. Hot Reload

    Redefining a class migrates every live instance in place: the migration rules, the hook, and code on the live stack.

  8. Serialization

    to_json/from_json in script; a Cereal-shaped archive framework in C++; the binder chain doubles as the polymorphism declaration.

  9. Coroutine Hosting

    Coroutine handles from script and from C++: resume, done, the frame-loop pattern and the native handle.

  10. Signals & Observable Properties

    Gameplay is event-shaped: firing and receiving signals from C++, the three routes a signal takes to become script-connectable (auto-bound, one binder line, or a named type), and observable values that announce their own changes.

  11. Performance Notes

    What the VM does for you (fused superinstructions, typed arrays, in-language parallelism), what idiomatic-fast code looks like, the honest cost model, and real measured numbers: microbenchmarks vs Lua/Squirrel/ChaiScript and two whole games.

  12. Debugging

    JaiScript ships a step-debugger core (breakpoints, pause, inspect/edit variables, step, resume) on both backends, a VS Code DAP attach, and a syntax-highlighting extension. It costs nothing until a session attaches.

  13. Script-Extensible Objects: extend

    A script class can derive a bound C++ class, and the script decides which object becomes which class: extend(object, Class) re-classes a host-owned object in place; every road back into script hands back the layer; hybrids serialize as themselves.

  14. Editor Support: the Language Server

    jaiscript_lsp answers the editor from the engine's own parser and strict checker: diagnostics as you type across a whole program (imported files at their own lines), go to definition, references, hover, completion, signature help and rename; the VS Code extension that launches it, and the host profile scripts are checked against.

  15. Math Adapters: Host Vector Types

    One JAI_BIND_* line makes your engine's own vector, point or color struct cross every binding as a script math value.
