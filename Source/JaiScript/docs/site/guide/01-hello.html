    Hello & Basics​

    JaiScript is a C++-flavored embedded scripting language: snake_case, hot-reloadable, zero static state, and shipped with two interchangeable backends (a tree-walking interpreter and a bytecode VM) that are kept at full test parity. Every example in these docs was executed on both backends; unless a divergence is called out, the output shown is identical on each.

    Running a script from C++​

    C++
    #include <jaiscript/core/engine.hpp>
#include <jaiscript/stdlib/stdlib.hpp>

auto eng = jai::engine::make();                 // shared_ptr<engine>
// eng->set_backend(jai::backend_type::vm);     // optional: bytecode VM (before first execute)
jai::stdlib::register_all(eng);                 // formatted print, format, to_string, type_of, to_json, ...
jai::script_value r = eng->execute("2 + 2");
int v = r.as_int();                             // 4

    Three things to know from the start:

    1. The last expression's value is the result of execute(). No return needed at top level.
    2. set_backend() must be called before the first execute() (forbidden after).
    3. The checker runs first, and it is strict by default. A typed mistake it can see (or an undeclared name) throws out of execute() before any statement runs. eng->static_checking(jai::check_mode::warn) opts down to reporting; see the Type Ladder. Chapter 13 collects the whole story.

    Try it from a terminal​

    You don't need a host program to follow this guide. The build produces a standalone runner, jaiscript: hand it a file and it runs it. Building it is one CMake target, from the repository root:

    shell
    cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build --target jaiscript_runner

    The executable lands in build/bin/jaiscript (the target is jaiscript_runner because the library owns the name jaiscript). With that on your path:

    shell
    jaiscript hello.jai            # run a file, then exit
jaiscript                      # interactive REPL (:help inside)
jaiscript --watch hello.jai    # re-run the file every time you save it

    Three flags matter for the rest of these docs:

    FlagWhat it does
    --backend=vm|interpWhich backend executes the script. The runner defaults to vm; interp is the tree-walking interpreter. Both must produce the same answer. Running a script twice, once per backend, is how these pages are checked.
    --check=strict|warn|offThe static checker's mode. Default strict: typed mistakes and undeclared names fail the load before anything runs. warn prints them and runs anyway; off skips the walk.
    --budget=NSeconds of wall clock per execute. An overrun ends the run with a terminal error the script cannot catch (the host sees an exception; see Control Flow). Default 0: unlimited.

    The runner's defaults are not the engine's. An embedded jai::engine starts on the interpreter and enforces a 1.0 second execution budget per execute(). The runner starts on the VM with no budget at all, because an infinite loop in a script you are editing is your own business. Static checking is strict in both.

    One convention to know before you compare output. When a block on these pages ends in == result: …, that line is the value of the script's last expression: what execute() hands back to a host. The runner does not echo it after a file run (an int result becomes the exit code; the REPL echoes every non-null result), so wrap the last expression in print(...) if you want to see it in a terminal. Everything above that line is print output and matches character for character. Two more shapes you will meet: a block that ends in == error: … shows the message the host would receive from an uncaught error (the runner prints it to stderr and exits 1), and a block that starts jaiscript: static check failed: is the runner's own listing when the checker stops a load before anything runs.

    Values and literals​

    jaiscript
    auto i = 42;            // integer (64-bit)
auto f = 3.14;          // float (double)
auto s = "hello";       // string
auto c = 'x';           // char
auto b = true;          // bool
auto n = null;          // null
print(type_of(i), " ", type_of(f), " ", type_of(s), " ", type_of(c), " ", type_of(b), " ", type_of(n));
print("hex: {}, binary: {}, exponent: {}", 0xFF, 0b1010, 2.5e3);
i + f;
    output
    int float string char bool null
hex: 255, binary: 10, exponent: 2500.000000
== result: 45.140000

    Integers are 64-bit (int64), floats are doubles. Hex (0xFF) and binary (0b1010) integer literals work, as do exponent floats (2.5e3). Strings support the usual escapes (\n, \", \\) plus \xNN byte escapes (see Containers & Strings). Which rung each of these declarations sits on (and why auto here is not "dynamic") is the next chapter.

    Comments and the implicit result​

    jaiscript
    // single-line comment
/* multi-line
   comment */
auto x = 10; // trailing comment
x * 2;  // the last expression's value is what execute() returns
    output
    == result: 20

    print and format​

    A bare engine ships a basic print (arguments concatenate; no {} substitution); jai::stdlib::register_all upgrades it in place to the formatted version shown below and registers format. Both are variadic host functions: the canonical example of variadics, which live on the host side (see Functions & Lambdas).

    jaiscript
    print("plain string");
print("several", " ", "args", " ", "concatenate");
print("sequential: {} + {} = {}", 2, 3, 2 + 3);
print("positional: {1} before {0}", "cart", "horse");
print("literal {{braces}} in a formatted call: {}", true);
auto msg = format("format() returns: {}", 99);
print(msg);
print("no newline ", skip_newline);
print("continues the line");
    output
    plain string
several args concatenate
sequential: 2 + 3 = 5
positional: horse before cart
literal {braces} in a formatted call: true
format() returns: 99
no newline continues the line
== result: null

    Rules:

    • print(value). One argument: printed as-is (no {} processing).
    • print(fmt, args...). If the first argument contains {} or {n} placeholders, it is treated as a format string: {} consumes the next argument, {0}/{1} are positional (0-based over the args after the format string), {{/}} escape braces.
    • print(a, b, c). If the first argument has no placeholders, all arguments are concatenated.
    • Trailing skip_newline suppresses the newline; skip_flush suppresses newline and flush.
    • format(...) follows the same rules but returns the string instead of printing.

    Note: brace escaping ({{) only applies on the format path (multiple arguments with placeholders). A single-argument print("{{x}}") prints the braces literally.

    Stringifying values​

    to_string(x) converts any value to a string; floats print with six decimals (3.14 → "3.140000"). For containers, to_string prints only a tag ([array], [map]). Use to_json(x) when you want the contents:

    jaiscript
    auto nums = [1,2,3];
print(nums);
print(to_json(nums));
print(to_json({"a": 1}));
    output
    [array]
[1,2,3]
{"a":1}

    type_of(x) returns one of: null bool int float char string array map function object reference weak_ptr, except for a class instance, which answers its own class name.
