The Type Ladder​

Pick your strictness per variable: prototype loosely with var, lock things down with explicit types as the code matures — in the same file, with no rewrite. JaiScript has three rungs of typing strictness for variables (and class fields):

DeclarationMeaning
int x = 5; (any explicit type)Enforced. The variable holds this type forever; assignments convert if compatible, error if not.
auto x = 5;Inferred, then enforced. The initializer's type is inferred once, then locked — from that point auto behaves exactly like the explicit type. auto is not dynamic.
var x = 5;Dynamic. Any type may be assigned at any time.

Enforced types reject incompatible assignments​

jaiscript
int x = 5;
x = 12;          // fine, still an int
x = "oops";      // typed variables reject incompatible assignment
output
== error: Type mismatch in assignment: Type mismatch

auto locks on first use​

jaiscript
auto x = 5;      // auto infers int, then enforces it
x = 2.9;         // float assigned to locked-int: converts (truncates toward zero)
print("x = {} ({})", x, type_of(x));
auto y = 1.5;    // locked to float
y = 2;           // int widens to float
print("y = {} ({})", y, type_of(y));
output
x = 2 (int)
y = 2.000000 (float)

An incompatible type is still an error:

jaiscript
auto x = 5;
x = "hello";     // locked to int: string is not convertible
output
== error: Type mismatch in assignment: Type mismatch

An uninitialized auto x; locks on its first assignment. Assigning null to a locked variable does not un-lock it.

var is genuinely dynamic​

jaiscript
var y = 5;
print("y is {} ({})", y, type_of(y));
y = "now a string";
print("y is {} ({})", y, type_of(y));
var mixed = [1, "two", 3.14, true];
print("mixed[1] = {}", mixed[1]);
mixed = {"even": "a map now"};
type_of(mixed);
output
y is 5 (int)
y is now a string (string)
mixed[1] = two
== result: map

Container homogeneity follows the ladder: auto nums = [1, 2, 3] locks a homogeneous array; var containers may be heterogeneous and may be reassigned to a different container kind entirely.

Conversion table (typed / locked-auto targets)​

What a typed (or locked-auto) target accepts, and what it does with it:

Target ← SourceResult
float ← intwidens (3 → 3.0)
int ← floattruncates toward zero (3.99 → 3, -3.99 → -3)
bool ← numerictruthiness (5 → true, 0 → false)
string ← int/float/...stringified (5 → "5")
int ← booltrue → 1, false → 0
int/float ← stringerror (no implicit parse; use "42".to_int())
class T ← same class or derivedallowed (upcast); parent → child, siblings, or same-shape unrelated classes are rejected
class T ← class with matching conversion ctor / assignment operatorconverts
jaiscript
float f = 3;         // int -> float widens
print("f = {} ({})", f, type_of(f));
int i = 3.99;        // float -> int truncates toward zero
print("i = {} ({})", i, type_of(i));
int j = -3.99;
print("j = {}", j);
bool b = 5;          // numeric -> bool is truthiness
print("b = {}", b);
string s = 5;        // int -> string coercion on typed target
print("s = {} ({})", s, type_of(s));
output
f = 3.000000 (float)
i = 3 (int)
j = -3
b = true
s = 5 (string)

Compound assignment: typed targets convert C++-style, var keeps the dynamic result​

The rule is two-sided:

  • On a typed (or locked-auto) target, a op= b computes like C++ and converts the result back to the target's type. int i = 7; i /= 2 → 3; i += 0.5 → 7 (7.5 truncated back).
  • On a var target, the stored value is whatever the operation produces — the variable may change type.
jaiscript
int i = 7;
i /= 2;              // C++-style on typed target: stays int
print("int 7 /= 2 -> {} ({})", i, type_of(i));
i = -7;
i /= 2;              // truncation is toward zero
print("int -7 /= 2 -> {}", i);
float f = 7.0;
f /= 2;
print("float 7.0 /= 2 -> {}", f);
auto a = 7;          // auto locked to int behaves like int
a /= 2;
print("auto(int) 7 /= 2 -> {} ({})", a, type_of(a));
var v = 7;           // var keeps dynamic behavior: result may change type
v /= 2;
print("var 7 /= 2 -> {} ({})", v, type_of(v));
output
int 7 /= 2 -> 3 (int)
int -7 /= 2 -> -3
float 7.0 /= 2 -> 3.500000
auto(int) 7 /= 2 -> 3 (int)
var 7 /= 2 -> 3 (int)

(var v = 7; v /= 2 gives 3 because 7 / 2 is integer division; the type difference shows with a float operand:)

jaiscript
int i = 7;
i += 0.5;
var v = 7;
v += 0.5;
print("int: {} ({})  var: {} ({})", i, type_of(i), v, type_of(v));
output
int: 7 (int)  var: 7.500000 (float)

The compound-assignment conversion also applies to typed class fields, typed array elements, and by-ref targets.
