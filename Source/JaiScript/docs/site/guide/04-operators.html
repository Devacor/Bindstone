    Operators & Arithmetic​

    The full C++ operator set with C++ precedence, minus the undefined behavior: integer overflow raises a catchable error instead of wrapping silently, division by zero raises on ints and floats, and nothing in the arithmetic core is UB.

    The table​

    CategoryOperatorsNotes
    Arithmetic+ - * / %int op int stays int (7 / 2 → 3); any float operand promotes
    Unary- ! ~ ++ --++/-- in both prefix and postfix form
    Compound assign= += -= *= /= %=typed targets convert C++-style (see Type Ladder). Bitwise compounds (&= |= ^= <<= >>=) are deliberately absent. Spell them out (f = f | m); flag-heavy code reads fine without them.
    Comparison== != < > <= >= <=><=> returns -1 / 0 / 1; 1 == 1.0 is true; == is memberwise on arrays, maps and class values (below)
    Logical&& || !short-circuit
    Bitwise& | ^ ~ << >>on integers
    Ternary?:right-associative
    Member/index. -> [] ?. ::-> is a synonym for . (values and handles alike), ?. is null-safe (see Kitchen Sink), :: reaches statics/namespaces
    Castcast<T>(e) cast<T&>(e) cast<shared_ptr<T>>(e)the explicit typed boundary: copy, reference, handle. See Type Ladder

    String + concatenates ("a" + "b"), and + with a string operand stringifies the other side ("a" + 5 is "a5"). += onto a string is stricter: it appends strings and chars, and raises on anything else. Write s += to_string(n) when you mean it. Comparison on strings is lexicographic. char operands promote to int (unsigned, 0–255) in every numeric context (see below).

    Arithmetic, precedence, inc/dec​

    jaiscript
    print("7 / 2   = {}", 7 / 2);         // int / int stays int
print("7.0 / 2 = {}", 7.0 / 2);       // any float operand promotes
print("7 % 3   = {}", 7 % 3);
print("2 + 3 * 4 = {}", 2 + 3 * 4);   // usual precedence
auto x = 5;
print("x++ = {}, then x = {}", x++, x);
print("--x = {}", --x);
-x;
    output
    7 / 2   = 3
7.0 / 2 = 3.500000
7 % 3   = 1
2 + 3 * 4 = 14
x++ = 5, then x = 6
--x = 5
== result: -5

    Comparisons, <=>, short-circuit​

    jaiscript
    print("3 <=> 7  = {}", 3 <=> 7);      // spaceship: -1 / 0 / 1
print("7 <=> 7  = {}", 7 <=> 7);
print("9 <=> 7  = {}", 9 <=> 7);
print("\"a\" < \"b\" = {}", "a" < "b");
print("1 == 1.0 = {}", 1 == 1.0);
auto side_effects = 0;
function tick() { side_effects += 1; return true; }
auto r = false && tick();             // short-circuit: tick never runs
print("side_effects = {}", side_effects);
true || tick();
side_effects;
    output
    3 <=> 7  = -1
7 <=> 7  = 0
9 <=> 7  = 1
"a" < "b" = true
1 == 1.0 = true
side_effects = 0
== result: 0

    Float ordering uses a total order (NaN included) so values remain valid map keys. == and <=> are kept mutually consistent by design.

    Evaluation order is a contract​

    In a call, the callee expression is evaluated before any argument, and arguments go left to right. Binary operators evaluate their left operand first. This is the C++17 rule, it holds on both backends, and it is the order errors surface in too: if the callee and the first argument both fail, you see the callee's error.

    jaiscript
    function a() { print("argument a"); return 1; }
function b() { print("argument b"); return 2; }
function add(x, y) { return x + y; }
function pick() { print("callee"); return add; }
print("sum = ", pick()(a(), b()));
    output
    callee
argument a
argument b
sum = 3

    Why it matters: a callee expression that reads a global runs before an argument that changes it, and a side effect in argument two never precedes one in argument one. You can rely on that, in either backend, rather than hoping.

    Each argument also takes its value when it is evaluated, as in Lua, Python and JavaScript. A later argument that writes a variable, an element or an object an earlier argument read does not change what the callee receives. A reference parameter binds the storage itself, so it sees the write:

    jaiscript
    var scores = [10, 20, 30];
function bump() { scores[1] = 99; return 1; }
function add(x, y) { return x + y; }
function add_ref(int& x, y) { return x + y; }
print("by value:     ", add(scores[1], bump()));
scores[1] = 20;
print("by reference: ", add_ref(scores[1], bump()));
    output
    by value:     21
by reference: 100

    Bitwise​

    jaiscript
    print("6 & 3  = {}", 6 & 3);
print("6 | 3  = {}", 6 | 3);
print("6 ^ 3  = {}", 6 ^ 3);
print("~0     = {}", ~0);
print("1 << 4 = {}", 1 << 4);
print("32 >> 2 = {}", 32 >> 2);
auto flags = 0b0001;
flags = flags | 0b0100;    // spelled-out form (see the compound-assign note above)
flags;
    output
    6 & 3  = 2
6 | 3  = 7
6 ^ 3  = 5
~0     = -1
1 << 4 = 16
32 >> 2 = 8
== result: 5

    Chars promote like C++​

    A char operand enters every binary numeric context (arithmetic, bitwise, and comparisons) as an integer in 0–255, always unsigned (signed char is a binary-data footgun this language opts out of). s[i] reads a char from a string, so byte-level parsing is ordinary arithmetic:

    jaiscript
    var s = "abc";
print("'z' - 'a'  = {}", 'z' - 'a');
print("s[1] == 'b': {}", s[1] == 'b');
print("s[0] == 97:  {}", s[0] == 97);
print("s[0] + 0   = {}", s[0] + 0);
print("'a' & 0x7F = {}", 'a' & 0x7F);
type_of('a' + 1);
    output
    'z' - 'a'  = 25
s[1] == 'b': true
s[0] == 97:  true
s[0] + 0   = 97
'a' & 0x7F = 97
== result: int

    Promotion never crosses into the string domain: 'a' == "a" is false, and char + string concatenates as text. And there is no implicit int→char either: type_of('a' + 1) is int, and char c = 65 is a type error. The char↔int door is cast<T> (cast<char>(n) for an int in 0..255, cast<int>(c) for the code point), with to_char(n) as the stdlib function form of the same range-checked rule, and \xNN literals for bytes you know at write time:

    jaiscript
    char c = cast<char>(65);          // int -> char, range-checked 0..255
int  n = cast<int>('a');          // char -> int: the code point
print(c, " ", n, " ", cast<string>('z') + "!", " ", cast<char>("q"));
print(to_char(66));               // the stdlib function form of the same rule
try { var bad = cast<char>(256); } catch (e) { print("caught: ", e); }
    output
    A 97 z! q
B
caught: Cannot cast 'int' to 'char'

    The byte-work recipes (s[i] - '0', little-endian words, out += to_char(b)) are in Containers & Strings.

    Checked overflow: raises, never wraps, never UB​

    The default build policy is JAISCRIPT_CHECKED_OVERFLOW ("safe by default"): overflowing + - *, unary -, and INT64_MIN / -1 raise a catchable run-time error. The alternative build policy (JAISCRIPT_WRAP_ON_OVERFLOW) wraps two's- complement instead. Either way, integer arithmetic is never undefined behavior. Internally it is computed in unsigned. engine::throw_on_overflow() reports which policy the build uses.

    jaiscript
    auto big = 9223372036854775807;   // INT64_MAX
try {
    big = big + 1;                // checked overflow raises, never wraps or UB
} catch (e) {
    print("caught: {}", e);
}
big;
    output
    caught: Integer overflow in '+'
== result: 9223372036854775807

    Note the value is untouched after the failed operation. ++/-- are covered by the same policy, as are the intermediate results of compound assignments.

    Division by zero​

    Both integer and float division by zero raise a catchable error (floats do not produce IEEE infinity):

    jaiscript
    try {
    auto x = 1 / 0;
} catch (e) {
    print("int:   caught {}", e);
}
try {
    auto y = 1.0 / 0.0;    // float division by zero also raises (no IEEE inf)
} catch (e) {
    print("float: caught {}", e);
}
"still running";
    output
    int:   caught Division by zero in integer operation
float: caught Division by zero in float operation
== result: still running

    Equality: memberwise values, pointer-compared handles​

    == and != compare values memberwise, the way C++ containers do: arrays element by element, maps entry by entry in key order, class instances field by field, each stopping at the first difference and short-circuiting on a size or class mismatch. A class that defines operator== takes precedence, for itself and wherever it appears as an element or a field. A shared_ptr handle compares like std::shared_ptr, by pointer: two new objects with equal fields are not equal, a handle equals itself and its aliases. Identity for everything else is a separate question, asked with same_object(x, y): references resolve to their referents, handles to the object they share, and containers and instances are the same object only when they are one allocation. Primitives and strings carry no identity, so same_object compares them as values.

    jaiscript
    class Stats { int hp = 10; array<int> buffs = [1, 2]; Stats() {} }
Stats a = Stats();
Stats b = Stats();                 // a second value with the same fields
Stats c = Stats(); c.buffs.push(3);
print("values:  {} {}", a == b, a == c);
print("arrays:  {} {}", [1, [2, 3]] == [1, [2, 3]], [1, 2] == [1, 2, 3]);
print("maps:    {}", {"x": 1, "y": 2} == {"y": 2, "x": 1});
var h1 = new Stats();
var h2 = h1;                       // a var copy of a handle shares it
var h3 = new Stats();              // a different object with equal fields
print("handles: {} {}", h1 == h2, h1 == h3);
print("identity: {} {} {}", same_object(a, b), same_object(h1, h2), same_object(a, a));
    output
    values:  true false
arrays:  true false
maps:    true
handles: true false
identity: false true true

    Map keys compare under the map's own ordering, so {1: "a"} and {1.0: "a"} hold different keys and are not equal even though 1 == 1.0. Ordering operators stay off containers and instances: [1] < [2] raises Invalid operands for < operator. Value nesting past 200 levels raises Cannot compare: the values nest deeper than 200 levels; a cycle cannot arise, since a value cannot contain its owner and handles compare by pointer.

    Operator overloading​

    Script classes define operators as methods, with class instances or even primitives on the right-hand side. C++-bound classes get the same treatment through dynamic_binder (see Embedding). One detail worth knowing: an operand that flows into your operator arrives as written. A char is not promoted on the way in.

    jaiscript
    class Vec {
    int x = 0; int y = 0;
    Vec(int px, int py) { x = px; y = py; }
    Vec operator+(Vec other) { return Vec(x + other.x, y + other.y); }
    bool operator==(Vec other) { return x == other.x && y == other.y; }
    Vec operator*(int k) { return Vec(x * k, y * k); }
}
auto a = Vec(1, 2);
auto b = Vec(3, 4);
auto c = a + b;
print("a + b = ({}, {})", c.x, c.y);
print("equals: {}", c == Vec(4, 6));
auto d = a * 3;
print("a * 3 = ({}, {})", d.x, d.y);
    output
    a + b = (4, 6)
equals: true
a * 3 = (3, 6)
