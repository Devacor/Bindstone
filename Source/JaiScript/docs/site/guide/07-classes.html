Classes​

Script classes: fields with initializers (run in declaration order), constructors with overloading and : this(...) delegation, inheritance with super, statics, and hot reload with instance migration. All methods are virtual; overriding requires the explicit override keyword. Remember from Value Semantics: instances are values — assignment copies; use shared_ptr<T> for handle semantics.

Fields, constructors, implicit self​

jaiscript
class Creature {
    string name = "anonymous";
    int health = 100;
    int max_health = health;

    Creature(string n) { name = n; }

    void take_damage(int amount) {
        health -= amount;
        if (health <= 0) { print("{} died", name); }
    }

    auto describe() { return name + " (" + to_string(health) + "/" + to_string(max_health) + ")"; }
}
auto goblin = Creature("goblin");
goblin.take_damage(30);
print(goblin.describe());
goblin.take_damage(80);
goblin.describe();
output
goblin (70/100)
goblin died
== result: goblin (-10/100)

max_health = health works because field initializers run top-to-bottom in declaration order. Methods access fields directly (implicit self); construction is a plain call — Creature("goblin"), **no new keyword**. private: / public: section labels parse (C++ style), but access is not currently enforced — see INTENT_QUESTIONS. (pinned: language/script_class_tests.cpp, language/test_cat_class_syntax.cpp)

Constructor overloading and : this(...) delegation​

jaiscript
class Point {
    int x = 0;
    int y = 0;
    Point() : this(0, 0) {}
    Point(int v) : this(v, v) {}
    Point(int px, int py) { x = px; y = py; print("main ctor ({}, {})", px, py); }
}
auto a = Point();
auto b = Point(3);
auto c = Point(1, 2);
b.x + c.y;
output
main ctor (0, 0)
main ctor (3, 3)
main ctor (1, 2)
== result: 5

Inheritance: super(...), super::, explicit override​

jaiscript
class Cat {
    int a = 0;
    Cat(int v) { a = v; }
    auto speak() { return "meow " + to_string(a); }
}
class Tiger : Cat {
    Tiger() : super(5) {}
    auto speak() override {
        return "ROAR! (base said: " + super::speak() + ")";
    }
}
auto t = Tiger();
print(t.speak());
Cat c = t;
type_of(c);
output
ROAR! (base said: meow 5)
== result: object

Redefining a base method without override is an error — the message is explicit:

output
== error: Method 'speak' shadows base class method. Use 'override' keyword if this is intentional

Assigning a derived instance to a base-typed variable is allowed; the reverse (parent to child), siblings, and structurally-identical unrelated classes are rejected. *(pinned: language/override_tests.cpp, override_edge_cases.cpp; semantics/strong_types_tests.cpp class_inheritance_child_to_parent_allowed, class_type_sibling_classes_rejected, class_type_unrelated_classes_with_same_fields_rejected)*

Typed fields are enforced (new)​

Fields follow the same type ladder as variables: explicit types enforce and convert; var fields stay dynamic; auto fields lock on their initializer.

jaiscript
class Stats {
    int hp = 10;
    var anything = 0;
}
auto s = Stats();
s.hp = 3.9;
print("hp = {} ({})", s.hp, type_of(s.hp));
s.anything = "free";
print("anything = {}", s.anything);
try {
    s.hp = "not a number";
} catch (e) {
    print("caught: {}", e);
}
s.hp;
output
hp = 3 (int)
anything = free
caught: Type mismatch in assignment
== result: 3

Enforcement covers direct assigns, implicit-this assigns in methods/ctors, compound assigns, inherited fields, the C++ set_field API, and JSON round-trips. *(pinned: semantics/strong_types_tests.cpp typed_field_direct_assign_converts, typed_field_implicit_this_and_ctor_convert, typed_field_compound_converts, typed_field_inheritance_enforced, typed_field_set_field_cpp_api, typed_field_json_roundtrip)*

Statics​

Static fields and methods belong to the class and are reached with ::. Instance constructors/methods see them directly:

jaiscript
class Counter {
    static int count = 0;
    static float PI = 3.14159;
    Counter() { count = count + 1; }
    static int twice_count() { return count * 2; }
}
auto a = Counter();
auto b = Counter();
auto c = Counter();
print("Counter::count = {}", Counter::count);
print("Counter::twice_count() = {}", Counter::twice_count());
Counter::PI;
output
Counter::count = 3
Counter::twice_count() = 6
== result: 3.141590

(pinned: language/static_field_tests.cpp, static_method_tests.cpp — including statics with inheritance; namespaces can override class statics of the same name, see Kitchen Sink)

Hot reload with permissive migration​

Re-executing a class declaration on the same engine reloads the class. Live instances migrate permissively: fields that still exist keep their current values (including still-default ones), brand-new fields get the new defaults, removed fields drop. The two execute() calls below run on one engine (marked //=== execute):

jaiscript
class Config {
    auto version = 1;
    auto name = "default";
}
auto cfg = Config();
cfg.name = "production";
print("before reload: v{} {}", cfg.version, cfg.name);
//=== execute
class Config {
    auto version = 2;
    auto name = "default";
    auto retries = 3;
}
print("after reload:  v{} {} retries={}", cfg.version, cfg.name, cfg.retries);
output
before reload: v1 production
== result: null
after reload:  v1 production retries=3
== result: null

Note version stayed 1 — migration preserves existing per-instance state, it does not re-run initializers for fields that already exist; only the new retries field picked up its default. Methods always come from the newest class definition. Hot reload even works while a function/class on the current call stack is redefined, and suspended method coroutines survive a field-changing reload of their class. *(pinned: language/hot_reload_tests.cpp, hot_reload_correctness_tests.cpp; language/coroutine_tests.cpp method_coroutine_survives_field_changing_reload)*
