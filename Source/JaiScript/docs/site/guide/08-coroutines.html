Coroutines​

Declare with the coroutine keyword; calling one returns a handle instead of running the body. handle.resume() runs to the next yield (returning the yielded value), handle.done() reports completion, and a final return value is delivered by the last resume(). The interpreter implements them by continuation replay, the VM by fibers — behavior is identical. Coroutines turn stateful multi-frame behavior — AI, cutscenes, staged animations — into straight-line code that pauses where it yields.

yield / resume / done​

jaiscript
coroutine int counter() {
    yield 1;
    yield 2;
    return 3;
}
auto c = counter();
print("resume: {}", c.resume());
print("resume: {}", c.resume());
print("done? {}", c.done());
print("resume: {}", c.resume());
print("done? {}", c.done());
output
resume: 1
resume: 2
done? false
resume: 3
done? true

Coroutines take parameters like any function, and yield works inside loops and conditionals. Side effects in a yield expression run exactly once, however the suspension is implemented underneath.

Each call is an independent instance​

jaiscript
coroutine int letters() { yield 1; yield 2; yield 3; }
auto x = letters();
auto y = letters();
print("{} {} {} {}", x.resume(), x.resume(), y.resume(), x.resume());
y.done();
output
1 2 1 3
== result: false

Range-for drives a coroutine​

A range-based for over a handle-producing call resumes it until done, iterating the yielded values:

jaiscript
coroutine int squares(int n) {
    for (int i = 1; i <= n; ++i) { yield i * i; }
}
auto total = 0;
for (auto v : squares(5)) {
    print("got {}", v);
    total += v;
}
total;
output
got 1
got 4
got 9
got 16
got 25
== result: 55

Method coroutines​

Class methods can be coroutines. The suspended body sees this — fields read/write normally across suspensions, and every instance gets independent generators:

jaiscript
class Gen {
    int id = 0;
    Gen(int i) { id = i; }
    coroutine int gen() { yield id; yield id * 2; }
}
auto a = Gen(1);
auto b = Gen(2);
auto ga = a.gen();
auto gb = b.gen();
print("{} {} {} {}", ga.resume(), gb.resume(), ga.resume(), gb.resume());
output
1 2 2 4

Range-for drives method coroutines too, and inherited method coroutines work on derived classes.

Receiver pinning​

The handle pins the receiver alive. Even if the only strong reference to the instance dies with the frame that created it, resuming still sees the fields:

jaiscript
class D {
    int v = 7;
    coroutine int g() { yield v; v = 99; yield v; }
}
function make() {
    auto d = D();
    return d.g();
}
auto h = make();
print("{}", h.resume());
print("{}", h.resume());
h.done();
output
7
99
== result: false

The handle keeps the instance alive for as long as the coroutine is suspended.

Rules and edges​

  • Handles are reference-semantic: copying a handle — into a field, an array/map element, a by-value parameter, another variable — shares the ONE live coroutine; every alias sees the same resume()/done() state. Even deep-copying an instance shares its handle field (a handle references a running computation; there is no meaningful deep copy). This is what lets an AI park its behavior coroutine in a field of its own game object and resume it every tick. Note the deliberate strong cycle when an instance's field holds a handle of its own method (the handle pins the receiver): break it by re-assigning/nulling the field, exactly like any shared structure. static coroutine methods are rejected.
  • Handles resume correctly across separate execute() calls, through by-ref helper params, and from inside running functions without disturbing the caller's frame.
  • A failed resume marks only that handle done.
  • Hot reload: a free coroutine can be redefined while one of its handles is suspended (the old handle keeps the old body), and method coroutines survive field-changing reloads of their class.
  • The execution budget still applies during resume() — and budget errors skip catches inside coroutines too.

The final return through a typed coroutine converts to the declared type on delivery.
