Coroutines​

Declare with the coroutine keyword; calling one returns a handle instead of running the body. handle.resume() runs to the next yield (returning the yielded value), handle.done() reports completion, and a final return value is delivered by the last resume(). The interpreter implements them by continuation replay, the VM by fibers — behavior is identical. (pinned: language/coroutine_tests.cpp, entire suite)

yield / resume / done​

jaiscript
coroutine int counter() {
    yield 1;
    yield 2;
    return 3;
}
auto c = counter();
print("resume: {}", c.resume());
print("resume: {}", c.resume());
print("done? {}", c.done());
print("resume: {}", c.resume());
print("done? {}", c.done());
output
resume: 1
resume: 2
done? false
resume: 3
done? true

Coroutines take parameters like any function, and yield works inside loops and conditionals. Yield expressions have no duplicate side effects on replay (pinned: yield_no_duplicate_side_effects).

Each call is an independent instance​

jaiscript
coroutine int letters() { yield 1; yield 2; yield 3; }
auto x = letters();
auto y = letters();
print("{} {} {} {}", x.resume(), x.resume(), y.resume(), x.resume());
y.done();
output
1 2 1 3
== result: false

Range-for drives a coroutine​

A range-based for over a handle-producing call resumes it until done, iterating the yielded values:

jaiscript
coroutine int squares(int n) {
    for (int i = 1; i <= n; ++i) { yield i * i; }
}
auto total = 0;
for (auto v : squares(5)) {
    print("got {}", v);
    total += v;
}
total;
output
got 1
got 4
got 9
got 16
got 25
== result: 55

Method coroutines (new)​

Class methods can be coroutines. The suspended body sees this — fields read/write normally across suspensions, and every instance gets independent generators:

jaiscript
class Gen {
    int id = 0;
    Gen(int i) { id = i; }
    coroutine int gen() { yield id; yield id * 2; }
}
auto a = Gen(1);
auto b = Gen(2);
auto ga = a.gen();
auto gb = b.gen();
print("{} {} {} {}", ga.resume(), gb.resume(), ga.resume(), gb.resume());
output
1 2 2 4

Range-for drives method coroutines too (pinned: method_coroutine_range_for_drives), and they work on derived classes (pinned: method_coroutine_inherited_on_derived).

Receiver pinning​

The handle pins the receiver alive. Even if the only strong reference to the instance dies with the frame that created it, resuming still sees the fields:

jaiscript
class D {
    int v = 7;
    coroutine int g() { yield v; v = 99; yield v; }
}
function make() {
    auto d = D();
    return d.g();
}
auto h = make();
print("{}", h.resume());
print("{}", h.resume());
h.done();
output
7
99
== result: false

*(pinned: method_coroutine_pins_instance — "the handle keeps the instance alive while suspended")*

Rules and edges​

  • **static coroutine methods are rejected, and a coroutine handle cannot be stored in a class field** (pinned: static_coroutine_method_rejected, coroutine_field_rejected). Real-world pattern: keep the handle in a global/local — the crawler example's boss AI is a coroutine void boss_brain(int boss_id) method whose handle lives in a global slot (examples/crawler/scripts/game.jai: "handles still refuse to live in fields").
  • Handles resume correctly across separate execute() calls, through by-ref helper params, and from inside running functions without disturbing the caller's frame (pinned: coroutine_resume_across_executes_with_redeclare, resume_through_by_ref_helper_param, resume_inside_running_function_keeps_caller_frame).
  • A failed resume marks only that handle done (pinned: failed_resume_marks_only_that_handle_done).
  • Hot reload: a free coroutine can be redefined while one of its handles is suspended (old handle keeps old body), and method coroutines survive field-changing reloads of their class (pinned: free_coroutine_redefine_while_suspended, method_coroutine_survives_field_changing_reload).
  • The execution budget still applies during resume() — and budget errors skip catches inside coroutines too (pinned: execution_budget_tests.cpp budget_terminal_skips_catch_inside_coroutine).

The final return through a typed coroutine converts to the declared type on delivery (pinned: coroutine_final_typed_return_converts).
