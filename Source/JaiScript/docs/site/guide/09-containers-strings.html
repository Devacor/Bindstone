Containers & Strings​

Array literals use [...]; map literals use {key: value, ...}. Builtin methods for arrays, maps, strings, and pointers live in one registry shared by both backends (detail/builtin_methods.hpp, populated by init_builtin_method_registries in interpreter.cpp) — the method lists below are enumerated directly from that registry.

Display tip: to_string(arr) prints just [array] / [map]; use to_json(x) to see contents.

The builtin method registry​

Array methods (20): size push pop empty clear front back index_of has contains first last length slice filter sort reverse remove remove_if join

Map methods (14): size empty clear contains erase keys values has get length remove remove_if filter to_array

String methods (37): length size empty at front back substr find rfind find_first_of find_last_of find_first_not_of find_last_not_of contains starts_with ends_with count to_int to_float split — and the in-place mutators to_lower to_upper trim trim_left trim_right pad_left pad_right pad_center replace_first replace_last replace_all insert erase remove_prefix remove_suffix reverse repeat

weak_ptr methods (4): lock expired reset same_as shared_ptr methods (4): reset use_count unique same_as

Arrays​

jaiscript
auto nums = [4, 1, 3, 2];
print("size={} front={} back={}", nums.size(), nums.front(), nums.back());
nums.push(5);
print("after push(5): {}", to_json(nums));
auto popped = nums.pop();
print("pop() -> {}", popped);
nums.sort();                        // sorts IN PLACE
print("sorted: {}", to_json(nums));
nums.reverse();                     // reverses IN PLACE
print("reversed: {}", to_json(nums));
print("index_of(3) = {}, contains(9) = {}", nums.index_of(3), nums.contains(9));
print("slice(1, 3) = {} (a new array)", to_json(nums.slice(1, 3)));
auto evens = nums.filter([](x) { return x % 2 == 0; });   // filter returns new
print("evens: {}, original intact: {}", to_json(evens), to_json(nums));
nums.remove_if([](x) { return x > 2; });                  // remove_if mutates
print("after remove_if(>2): {}", to_json(nums));
["a", "b", "c"].join("-");
output
size=4 front=4 back=2
after push(5): [4,1,3,2,5]
pop() -> 5
sorted: [1,2,3,4]
reversed: [4,3,2,1]
index_of(3) = 1, contains(9) = false
slice(1, 3) = [3,2] (a new array)
evens: [4,2], original intact: [4,3,2,1]
after remove_if(>2): [2,1]
== result: a-b-c

Mutators: push pop clear sort reverse remove remove_if. Everything else returns information or a new array. pop on an empty array raises a catchable error. (pinned: containers/array_tests.cpp, containers/test_array_methods.cpp)

Maps​

jaiscript
auto inventory = {"sword": 1, "potion": 3};
inventory["gold"] = 250;
print("size = {}", inventory.size());
print("has(potion) = {}, has(shield) = {}", inventory.has("potion"), inventory.has("shield"));
print("keys: {}", to_json(inventory.keys()));
print("values: {}", to_json(inventory.values()));
inventory.erase("sword");
print("after erase: {}", to_json(inventory));
print("get with default: {}", inventory.get("shield", 0));
auto rich = inventory.filter([](k, v) { return v > 10; });
print("filter(v > 10): {}", to_json(rich));
print("missing key read: {}", inventory["nothing"] == null);
to_json(inventory.to_array());
output
size = 3
has(potion) = true, has(shield) = false
keys: ["gold","potion","sword"]
values: [250,3,1]
after erase: {"gold":250,"potion":3}
get with default: 0
filter(v > 10): {"gold":250}
missing key read: true
== result: [["gold",250],["potion",3]]

Notes: writing m[key] = v inserts; **reading a missing key returns null and does NOT insert** (the map-read auto-insert bug was fixed and is regression-pinned in language/review_regression_tests.cpp). get(key, default) is the explicit fallback form. Keys are ordered (any script value can be a key — the total ordering of <=> guarantees it). Map filter's predicate takes (key, value). (pinned: containers/map_tests.cpp, containers/test_map_methods.cpp)

Typed containers​

array<T> / map<K,V> enforce element types: pushes/writes convert when compatible (int→float etc.) and reject otherwise, with a descriptive error:

jaiscript
array<int> nums = [1, 2, 3];
nums.push(4.9);          // converts to the element type
print("pushed 4.9 -> {}", to_json(nums));
try {
    nums.push("nope");   // incompatible element rejected
} catch (e) {
    print("caught: {}", e);
}
map<string, int> ages = {"ana": 31};
ages["bo"] = 44;
array<array<int>> grid = [[1, 2], [3, 4]];
grid[1][0] + ages["bo"];
output
pushed 4.9 -> [1,2,3,4]
caught: Cannot push 'string' to array<int>
== result: 47

*(pinned: semantics/container_conversion_tests.cpp, auto_container_conversion_tests.cpp, strong_types_tests.cpp auto_array_push_preserves_type)*

Strings: observers vs mutators​

This is the part that surprises people: JaiScript string methods split into two camps, and the mutating camp modifies the receiver in place and returns self for chaining (deliberate, pinned in stdlib/string_tests.cpp under "Mutating methods (modify in place, return self for chaining)" and "Mutation verification"):

jaiscript
// OBSERVERS return information and leave the string alone:
auto s = "The Quick Fox";
print("length={} find(Quick)={} count(o)={}", s.length(), s.find("Quick"), s.count("o"));
print("contains/starts/ends: {} {} {}", s.contains("Fox"), s.starts_with("The"), s.ends_with("Fox"));
print("substr(4, 5) = {} (s untouched: {})", s.substr(4, 5), s);
print("split: {}", to_json(s.split(" ")));
print("\"42\".to_int() + 1 = {}", "42".to_int() + 1);

// MUTATORS change the string IN PLACE and return self (chainable):
var t = "  hello world  ";
t.trim().to_upper().replace_all("WORLD", "JAI");
print("t is now: [{}]", t);
var padded = "7";
padded.pad_left(3, '0');
print("padded: {}", padded);
var r = "stressed";
r.reverse();
r;
output
length=13 find(Quick)=4 count(o)=1
contains/starts/ends: true true true
substr(4, 5) = Quick (s untouched: The Quick Fox)
split: ["The","Quick","Fox"]
"42".to_int() + 1 = 43
t is now: [HELLO JAI]
padded: 007
== result: desserts

So auto upper = name.to_upper(); **also uppercases name itself**. If you need to keep the original, copy first (auto upper = name; upper.to_upper();) or build a new string with +. find returns -1 when absent; substr(start, len); split() with no argument splits into individual characters (verified: "a b".split() → ["a"," ","b"]). Strings are not subscriptable (s[i] errors) — use s.at(i), which returns a one-character string.

Current caveat (see Value Semantics + INTENT_QUESTIONS): calling a string method through a ref declaration (auto& r = s; r.to_upper();) crashes at the pinned commit — call it on the variable itself, which works fine.

Strings and +​

Concatenation with + returns a new string and is the safe non-mutating way to build text: s = s + "!". Mixed string + number stringifies the number. *(pinned: language/operator_tests.hpp string_concatenation; stdlib/string_tests.cpp)*
