    Containers & Strings​

    Value-semantic arrays, ordered maps, a string type with a deep method set, and byte-level string reads for binary work. Array literals use [...]; map literals use {key: value, ...}. Builtin methods for arrays, maps, strings, and pointers live in one registry shared by both backends, so the lists below cannot drift between them. They are enumerated directly from that registry.

    Display tip: to_string(arr) prints just [array] / [map]; use to_json(x) to see contents.

    The builtin method registry​

    Array methods (20): size push pop empty clear front back index_of has contains first last length slice filter sort reverse remove remove_if join

    Map methods (14): size empty clear contains erase keys values has get length remove remove_if filter to_array

    String methods (52): length size byte_size empty at front back substr find rfind find_first_of find_last_of find_first_not_of find_last_not_of contains starts_with ends_with count compare to_int to_float split lines partition is_digit is_alpha is_alnum is_space is_upper is_lower utf8_chars utf8_length is_valid_utf8 code to_utf8, and the in-place mutators to_lower to_upper trim trim_left trim_right pad_left pad_right pad_center replace_first replace_last replace_all insert erase remove_prefix remove_suffix reverse repeat

    weak_ptr methods (4): lock expired reset same_as shared_ptr methods (5): reset use_count cpp_ref_count unique same_as

    Arrays​

    jaiscript
    auto nums = [4, 1, 3, 2];
print("size={} front={} back={}", nums.size(), nums.front(), nums.back());
nums.push(5);
print("after push(5): {}", to_json(nums));
auto popped = nums.pop();
print("pop() -> {}", popped);
nums.sort();                        // sorts IN PLACE
print("sorted: {}", to_json(nums));
nums.reverse();                     // reverses IN PLACE
print("reversed: {}", to_json(nums));
print("index_of(3) = {}, contains(9) = {}", nums.index_of(3), nums.contains(9));
print("slice(1, 3) = {} (a new array)", to_json(nums.slice(1, 3)));
auto evens = nums.filter([](x) { return x % 2 == 0; });   // filter returns new
print("evens: {}, original intact: {}", to_json(evens), to_json(nums));
nums.remove_if([](x) { return x > 2; });                  // remove_if mutates
print("after remove_if(>2): {}", to_json(nums));
["a", "b", "c"].join("-");
    output
    size=4 front=4 back=2
after push(5): [4,1,3,2,5]
pop() -> 5
sorted: [1,2,3,4]
reversed: [4,3,2,1]
index_of(3) = 1, contains(9) = false
slice(1, 3) = [3,2] (a new array)
evens: [4,2], original intact: [4,3,2,1]
after remove_if(>2): [2,1]
== result: a-b-c

    Mutators: push pop clear sort reverse remove remove_if. Everything else returns information or a new array. pop on an empty array raises a catchable error.

    One thing to notice about the first line: auto nums = [4, 1, 3, 2] is an array<int>. auto infers the element type from a uniform literal and then enforces it, so nums.push("x") would raise. When you want a mixed bag, say so: var or array<var>. The details are under Typed containers.

    Maps​

    jaiscript
    auto inventory = {"sword": 1, "potion": 3};
inventory["gold"] = 250;
print("size = {}", inventory.size());
print("has(potion) = {}, has(shield) = {}", inventory.has("potion"), inventory.has("shield"));
print("keys: {}", to_json(inventory.keys()));
print("values: {}", to_json(inventory.values()));
inventory.erase("sword");
print("after erase: {}", to_json(inventory));
print("get with default: {}", inventory.get("shield", 0));
auto rich = inventory.filter([](k, v) { return v > 10; });
print("filter(v > 10): {}", to_json(rich));
print("missing key read: {}", inventory["nothing"] == null);
to_json(inventory.to_array());
    output
    size = 3
has(potion) = true, has(shield) = false
keys: ["gold","potion","sword"]
values: [250,3,1]
after erase: {"gold":250,"potion":3}
get with default: 0
filter(v > 10): {"gold":250}
missing key read: true
== result: [["gold",250],["potion",3]]

    Notes: writing m[key] = v inserts; reading a missing key returns null and does NOT insert. get(key, default) is the explicit fallback form. Keys are ordered (a var map takes any script value as a key; the total ordering of <=> guarantees it), so iteration order is deterministic: range-for, keys(), values() and serialization walk keys in order on every platform, whatever order they were inserted in. Lookups are hashed, and the order is produced only when something iterates; a loop that inserts a key ahead of its position visits it, and one that erases entries skips them. Note that auto inventory = {…} inferred map<string, int> from its literal, exactly as auto does for arrays, so inventory[5] would raise; see Key types. Map filter's predicate takes (key, value).

    Typed containers​

    array<T> and map<K,V> enforce their element types. A push or a store converts when the value is compatible (int to float, say) and rejects otherwise, with an error that names the container:

    Elements and map values convert between bool and int: false becomes 0, true becomes 1, and an int becomes false only when it is zero. Int/float conversion also applies. Int-to-string requires an explicit to_string(value) or cast<string>(value); float/bool conversion stays rejected. Map keys never coerce.

    shared_ptr<T> and weak_ptr<T> elements admit null. A shared-handle element also takes a live instance of T or a subclass and checks the class of a shared handle. Class values, primitive values and nested containers remain non-nullable.

    jaiscript
    array<int> nums = [1, 2, 3];
nums.push(4.9);          // converts to the element type
print("pushed 4.9 -> {}", to_json(nums));
var bad = "nope"; // a var-sourced value: the checker cannot see it
try {
	nums.push(bad);          // checked at run time
} catch (e) {
	print("caught: {}", e);
}
map<string, int> ages = {"ana": 31};
ages["bo"] = 44;
array<array<int>> grid = [[1, 2], [3, 4]];
print("grid[1][0] + ages[bo] = {}", grid[1][0] + ages["bo"]);
    output
    pushed 4.9 -> [1,2,3,4]
caught: Cannot push 'string' to array<int>
grid[1][0] + ages[bo] = 47

    The checker checks known literal elements and keys, nested literals, typed push arguments and typed subscript stores. A subscript on a declared array<T> or map<K,V> carries its element type into later typed assignments. A var-sourced value is checked at run time and its error is catchable, as above. Bounds, missing keys and computed numeric range failures remain runtime checks. [[warn_mode]] is the explicit way to downgrade a static diagnostic.

    Representation follows the declared type​

    The declared element type is not just a check; it is the storage. array<int> and array<float> are raw int64 and double buffers, always; bool, char, string and class element types get packed buffers of their own. array<var>, and a literal without a spelled element type, is the one form that holds a vector of dynamic values. Moving between the two is an explicit assignment, and a typed array keeps its constraint when a push is rejected. Copying it into var or array<var> explicitly creates a dynamic copy.

    jaiscript
    array<int> nums = [1, 2, 3];         // a raw int buffer
array<var> copy = nums;              // the explicit step to the dynamic form: a copy
copy.push(4);
print("copy: {}  nums: {}", to_json(copy), to_json(nums));
array<float> widened = nums;         // typed to typed converts element by element
print("widened: {}", to_json(widened));
auto guessed = [1, 2, 3];            // auto infers array<int> from a uniform literal
try { guessed.push("s"); } catch (e) { print("caught: {}", e); }
var loose = [1, 2, 3];               // var: dynamic, whatever the literal held
loose.push("s");
print("loose: {}", to_json(loose));
    output
    copy: [1,2,3,4]  nums: [1,2,3]
widened: [1.0,2.0,3.0]
caught: Cannot push 'string' to array<int>
loose: [1,2,3,"s"]

    Three spellings, three intents: array<int> when you know, auto when the literal says it for you (a mixed literal under auto raises Array 'auto' requires homogeneous elements), and var or array<var> when the elements genuinely vary. This is the contract behind the "typed arrays" bullet in the performance notes: a typed loop reads a raw buffer, and a C++ binding can take the buffer without boxing.

    Class-typed arrays admit subclasses​

    array<Base> holds a Base or anything derived from it, and each slot keeps its own class, so a derived element keeps its extra fields inside the base-typed array. array<Derived> converts to array<Base> by value. An unrelated class raises:

    jaiscript
    class Unit { int hp = 10; }
class Archer : Unit { int range = 6; }
class Rock { int mass = 3; }
array<Unit> squad = [Unit(), Archer()];    // a subclass in a Base slot keeps its class
squad.push(Archer());
print("{} units, squad[2] is {}", squad.size(), reflect::type_name(squad[2]));
print("Archer fields survive: range = {}", cast<Archer&>(squad[1]).range);
array<Archer> archers = [Archer(), Archer()];
array<Unit> promoted = archers;             // array<Derived> -> array<Base>, by value
print("promoted: {}", promoted.size());
var rock = Rock();                          // a var hides the class from the checker: the push raises
try { squad.push(rock); } catch (e) { print("caught: {}", e); }
    output
    3 units, squad[2] is Archer
Archer fields survive: range = 6
promoted: 2
caught: Cannot push 'Rock' to array<Unit>

    (type_of and reflect::type_name both name the class an element actually holds: Chapter 12.)

    Key types​

    A map checks its declared key type on every direct store, and keys never coerce: map<string, int> rejects m[5] rather than turning 5 into "5". map<var, V> takes any key. map<auto, V> infers the key type from a uniform literal, and plain auto infers both sides (auto m = {"a": 1} is a map<string, int>); a mixed literal raises Map 'auto' requires homogeneous keys. One gotcha worth knowing before it costs you ten minutes: a typed map declared without an initializer is a typed null, not an empty map, so m[k] = v fails until you assign it {}.

    jaiscript
    map<string, int> ages = {"ana": 31};
try { ages[5] = 1; } catch (e) { print("caught: {}", e); }     // keys never coerce
map<var, int> anything = {};                                   // any key
anything[5] = 1;
anything["five"] = 5;
print("map<var,int>: {}", to_json(anything));
map<auto, int> inferred = {5: 1};                              // auto key: int, from the literal
try { inferred["k"] = 2; } catch (e) { print("caught: {}", e); }
map<string, int> empty;                                        // no initializer: an empty map of its declared type
print("empty.size(): {}", empty.size());
empty["x"] = 1;
print("after assigning a literal: {}", to_json(empty));
    output
    caught: Cannot use 'int' as a key of type 'string'
map<var,int>: {"5":1,"five":5}
caught: Cannot use 'string' as a key of type 'int'
empty.size(): 0
after assigning a literal: {"x":1}

    Every typed declaration without an initializer takes its type's default: containers start empty, numbers at zero, strings empty, and a class type default-constructs (the Type Ladder has the table).

    Strings: observers vs mutators​

    This is the part that surprises people: JaiScript string methods split into two camps, and the mutating camp modifies the receiver in place and returns self for chaining, deliberately:

    jaiscript
    // OBSERVERS return information and leave the string alone:
auto s = "The Quick Fox";
print("length={} find(Quick)={} count(o)={}", s.length(), s.find("Quick"), s.count("o"));
print("contains/starts/ends: {} {} {}", s.contains("Fox"), s.starts_with("The"), s.ends_with("Fox"));
print("substr(4, 5) = {} (s untouched: {})", s.substr(4, 5), s);
print("split: {}", to_json(s.split(" ")));
print("\"42\".to_int() + 1 = {}", "42".to_int() + 1);

// MUTATORS change the string IN PLACE and return self (chainable):
var t = "  hello world  ";
t.trim().to_upper().replace_all("WORLD", "JAI");
print("t is now: [{}]", t);
var padded = "7";
padded.pad_left(3, '0');
print("padded: {}", padded);
var r = "stressed";
r.reverse();
r;
    output
    length=13 find(Quick)=4 count(o)=1
contains/starts/ends: true true true
substr(4, 5) = Quick (s untouched: The Quick Fox)
split: ["The","Quick","Fox"]
"42".to_int() + 1 = 43
t is now: [HELLO JAI]
padded: 007
== result: desserts

    So auto upper = name.to_upper(); also uppercases name itself. If you need to keep the original, copy first (auto upper = name; upper.to_upper();) or build a new string with +. find returns -1 when absent; substr(start, len); split() with no argument splits into individual characters ("a b".split() → ["a"," ","b"]).

    The non-mutating twins live in string::. string::trim(s), string::replace_all(s, from, to), string::repeat(s, n), string::pad_left(s, n, [fill]), string::pad_right(s, n, [fill]), string::to_lower(s) and string::to_upper(s) return a new string and leave the argument alone, the spelling for expressions: print(string::trim(line)). string::join(parts, [sep]) joins an array of strings. The namespace is yours to extend: namespace string { function shout(string s) -> string { return string::to_upper(s) + "!"; } } adds string::shout beside the built-in entries.

    The everyday helpers: s.split(sep, max) stops after max splits (the last element keeps the rest); s.lines() splits on \n and \r\n with no empty last element; s.partition(sep) is [head, sep, tail] ([s, "", ""] when sep is absent); a.compare(b) is -1, 0 or 1; is_digit, is_alpha, is_alnum, is_space, is_upper and is_lower are true when the string is non-empty and every byte is in the ASCII class.

    Bytes and chars: s[i], \xNN, cast<char>​

    s[i] reads a char, and chars promote to integers (0–255, always unsigned) in arithmetic, bitwise, and comparison contexts, so a single byte is plain arithmetic (whole records read through binary data). s.at(i) is the alternative when you want a one-character string instead of a char. Range-for walks a string the same way: for (auto c : s) binds each char by value, in order (auto& raises, since a char is a read, not a cell). Going the other way: \xNN escapes (exactly two hex digits) put literal bytes in source, and cast<char>(n) mints a char from an int, range-checked to 0–255:

    jaiscript
    var s = "Jai\x21";                 // \xNN: exactly two hex digits
print("s = {}", s);
print("s[0] = {} ({})", s[0], type_of(s[0]));
print("byte value: {}", s[0] + 0);            // char + int promotes: 0..255, unsigned
print("as a cast: {}", cast<int>(s[0]));      // the same code point, spelled explicitly
print("digit: {}", "7"[0] - '0');             // the parser idiom
print("sentinel: {}", s[3] == 0x21);          // byte comparisons just work
var word = (s[0] + 0) | ((s[1] + 0) << 8);    // little-endian u16 from two bytes
print("le u16: {}", word);
var out = "";
out += cast<char>(0x4A);                       // int -> char, range-checked 0..255
out += to_char(0x21);                          // the stdlib spelling of the same rule
out += '!';                                    // string += char appends as text
print("built: {}", out);
try { cast<char>(256); } catch (e) { print("caught: {}", e); }
try { s[0] = 'X'; } catch (e) { print("caught: {}", e); }
    output
    s = Jai!
s[0] = J (char)
byte value: 74
as a cast: 74
digit: 7
sentinel: true
le u16: 24906
built: J!!
caught: Cannot cast 'int' to 'char'
caught: Strings are read-only through subscript: use substr()/+ to build a new string

    Note the last line: subscript is read-only: strings mutate through their methods or get rebuilt with +/+=. And the promotion never crosses into the string domain: 'a' == "a" is false, char + string concatenates, and string += int is an error (stringify explicitly if you mean it). High bytes stay unsigned: "\xC3"[0] + 0 is 195, never -61.

    The char door is cast<T>, and only cast<T>. The assignment table has no char row: char c = 65 and int n = 'A' are both load errors under the default strict checking (see Types That Fail Early). To cross deliberately, spell it: cast<int>(c) and cast<float>(c) give the code point, cast<string>(c) the one-character string, cast<char>(n) or cast<char>("a") mint one. Out of range raises the catchable Cannot cast 'int' to 'char' (a longer string, Cannot cast 'string' to 'char'). to_char(n) is the stdlib function form of the same range-checked rule. Chapter 4 covers promotion in full.

    What this doesn't do (and what to use instead): no unary -c/~c on chars (write 0 - c / c ^ 0xFF). Binary payloads live in ordinary strings, read and built by the binary library below.

    Binary data​

    A string is binary-safe: it holds any byte 0–255, NULs included, and read_file / write_file move bytes unchanged, so a file's bytes are a string and a string's bytes are a file. utf8_string is for text. Whole-buffer conversions are one native call each:

    • s.to_bytes(), s.to_bytes(offset), s.to_bytes(offset, count) → an array<int> of 0–255 values (a typed int buffer, the fast lane for hot loops). The range is checked: to_bytes(1, 3) out of bounds for string of size 3. On a utf8_string it gives the UTF-8 bytes.
    • string::from_bytes(bytes) builds a string from an array<int> (every value 0–255, else string::from_bytes expects bytes (0 to 255): element 3 is 256) or an array<char>.

    Reading: binary::reader. s.reader() (or binary::reader(s)) walks the string with a cursor from 0, little-endian until big_endian(); little_endian() switches back, and both return the reader so auto r = s.reader().big_endian(); reads naturally. Every read advances the cursor and names its width:

    • int8() int16() int32() int64() sign-extend; uint8() uint16() uint32() are 0 to 4294967295. There is no uint64(): a script int is an int64, so a value past 263 has no int to land in; int64() reads the same eight bytes as a signed value.
    • float32() widens to the script float, float64() keeps every bit (a NaN's payload, -0.0).
    • text(n) is n raw bytes as a string; bytes(n) is an array<int>.
    • Null-terminated text comes in two forms, each bounded. text_null_terminated(n) reads a fixed n-byte field, the C char[n] convention: the cursor moves exactly n, and the text is the bytes before the first NUL (a lump name "E1M1\0\0\0\0" is "E1M1", a full "TEXTURE1" with no NUL is all eight; bytes after a terminator are not part of the text even when a tool left something there, which trimming trailing NULs would keep). text_null_terminated() reads a C string: the bytes before the next NUL, and the cursor moves past the NUL. Its scan never passes the end of the data or the host's engine::binary_scan_limit (1 MiB unless the host sets it; scripts cannot change it), so no script runs an unbounded scan. When no NUL is in reach it raises and leaves the cursor: Cannot read null-terminated text at position 5: no NUL terminator in the remaining 3 bytes, or at the limit ... no NUL terminator within 1048576 bytes (the engine's binary scan limit; raise it from C++ with engine->binary_scan_limit).
    • seek(pos) and skip(n) move the cursor and return the reader; pos(), size(), remaining() and at_end() ask.

    Reading past the end raises the catchable Cannot read int32 at position 10: 4 bytes wanted, 2 remain and leaves the cursor where it was. A reader is a value: auto r2 = r; copies the cursor, a by-value parameter gets its own copy, a binary::reader& parameter shares it. It reads a snapshot of the string: strings are shared copy-on-write, so making a reader copies nothing, and a later change to the string leaves the reader's bytes as they were.

    Writing: binary::writer. binary::writer w; mirrors the reader: w.int8(v) through w.int64(v), w.uint8(v) through w.uint32(v), w.float32(v), w.float64(v), w.text(s) (raw bytes), w.text(s, n) (exactly n bytes, NUL-padded or truncated; a full-width value has no NUL, the way WAD lump names are stored), w.text_null_terminated(s) (the bytes, then a NUL), w.text_null_terminated(s, n) (an n-byte field that always ends in a NUL: at most n - 1 bytes of s, then NULs; n is at least 1), w.bytes(array<int>), big_endian() / little_endian(). Each returns the writer for chaining. A value that does not fit its width raises and writes nothing: Cannot write 256 as uint8 (0 to 255), and a text holding a NUL cannot be written as null-terminated (Cannot write text_null_terminated: the text holds a NUL at byte 3). w.pos() and w.seek(pos) go back to patch an earlier field in place (a length or an offset known only at the end); w.size() is the byte count and w.to_string() the bytes, ready for write_file(path, w.to_string()).

    Layouts. binary::int8, binary::int16, binary::int32, binary::int64, binary::uint8, binary::uint16, binary::uint32, binary::float32, binary::float64, binary::text(n) and binary::text_null_terminated(n) are width tokens: values that describe an encoding, not language types (a script int is always an int64). Both text tokens read an n-byte field as the bytes before its first NUL; they differ on write: binary::text(n) writes like w.text(s, n) (a full-width value keeps all n bytes), binary::text_null_terminated(n) like w.text_null_terminated(s, n) (always a NUL, n at least 1). A layout names them in order:

    • binary::layout(name, width, ...) builds a reusable layout, validated once; r.unpack(layout) reads its fields in order into a map<string, var>, and r.unpack(name, width, ...) reads an inline one.
    • w.pack(layout, map) writes the map's values in the layout's order; a missing name or a value that does not fit raises before anything is written.
    • r.read(Class, layout) makes a default-constructed instance and fills its fields in declaration order, base class fields first; the field count and each field's kind (int, float, text) must match the widths.

    The order always comes from the arguments, never from a map: maps iterate in key order. The strict checker knows the library: the types, every method's signature and result, an odd name/width pairing or a non-width where a width belongs, and a read(Class, layout) whose class and layout it can see, all reported at load.

    jaiscript
    var ENTRY = binary::layout("pos", binary::int32, "size", binary::int32, "name", binary::text(8));

binary::writer w;                            // a tiny WAD: header, one lump, a directory
w.text("PWAD").int32(1).int32(0);            // id, lump count, directory offset (patched below)
int lump = w.pos();
w.text("hello");
int dir = w.pos();
w.pack(ENTRY, {"pos": lump, "size": 5, "name": "GREET"});
w.seek(8).int32(dir);                        // back to the header to patch the offset
string wad = w.to_string();

var r = wad.reader();
print("{}, lump count {}", r.text(4), r.int32());
r.seek(r.int32());                           // the directory
var e = r.unpack(ENTRY);                     // map<string, var>: name -> value
print("{} at {}: {}", e["name"], e["pos"], wad.substr(e["pos"], e["size"]));

class Entry { int pos; int size; string name; }
Entry first = wad.reader().seek(dir).read(Entry, ENTRY);
print("{} {} {}", first.name, first.pos, first.size);
print(to_json(wad.to_bytes(0, 4)));
print(string::from_bytes([80, 87, 65, 68]));
try { r.int32(); } catch (err) { print("caught: {}", err); }
try { w.uint8(256); } catch (err) { print("caught: {}", err); }
    output
    PWAD, lump count 1
GREET at 12: hello
GREET 12 5
[80,87,65,68]
PWAD
caught: Cannot read int32 at position 33: 4 bytes wanted, 0 remain
caught: Cannot write 256 as uint8 (0 to 255)

    Files. write_file(path, string::from_bytes(b)) and read_file(path).to_bytes() round-trip any bytes exactly: every value 0–255, embedded NULs, \r\n untouched. read_file raises a catchable error for a file that is missing or cannot be read (Cannot read file 'saves/world.dat': not found, ...: not a file, ...: permission denied); an existing empty file reads as "". Ask first when absence is expected: file_exists(path) ? read_file(path) : "" (Where files are).

    UTF-8 text​

    A string is bytes, as in C++: size(), s[i] and substr count bytes, which is O(1) and what binary formats and renderers want. Text in UTF-8 has its own methods, named so they never blur with char (a byte):

    jaiscript
    string s = "héllo 🙂";
print("{} bytes, {} characters", s.size(), s.utf8_length());
for (string ch : s.utf8_chars()) { print("[{}]", ch); }   // each UTF-8 character, as a string
print("{} {}", "é".code(), string::from_code(233));    // Python ord / chr
print(s.is_valid_utf8());

    utf8_chars() never loses text: a byte that starts no valid sequence comes back as its own one-byte element, and is_valid_utf8() (or string::is_valid_utf8(s)) checks first. code() needs a string of exactly one UTF-8 character; string::from_code(n) raises for a surrogate or a value past U+10FFFF.

    utf8_string: text by character​

    utf8_string holds the same bytes as a string and has the same library, but every position is a character: size(), length(), u[i], at, substr, find, insert, erase, the pads, reverse, split("") and range-for count and return characters. A character comes back as a one-character utf8_string; byte_size() still counts bytes.

    jaiscript
    utf8_string name = "Zoë 🙂";
print(name.size());                 // 5: characters
print(name[2]);                     // ë
for (auto c : name) { print(c); }   // Z, o, ë, space, 🙂
print(name.byte_size());            // 9: the bytes underneath
string raw = name;                  // the same bytes, counted as bytes
print(name == raw);                 // true

    Make one by declaring the type, with utf8_string(x), or with s.to_utf8(); a string slot takes a utf8_string back as its bytes. It compares and orders by bytes, so u == s holds for the same text, but as a map key it keeps its own kind (like 1 and 1.0). A + with a utf8_string on either side makes a utf8_string, and every method or string:: function that returns text returns the receiver's kind. Like s[i], u[i] is read-only and a range-for takes characters by value. Case mapping and the character classes stay ASCII, as on a string.

    Character positions are cheap in practice: an all-ASCII text indexes like bytes, the character count is remembered, the last two positions are remembered so a loop over u[i] steps one character at a time, and a long text read at random positions builds a table of every 64th character once. Any write clears these. Parallel bodies read them without writing them.

    Strings and +​

    Concatenation with + returns a new string and is the safe non-mutating way to build text: s = s + "!". Mixed string + number stringifies the number.

    Template strings & format specs​

    Backtick strings interpolate any expression with ${...} (the lexer desugars them to plain string concatenation). A splice can end in a format spec, ${expr:spec}, the most useful part of std::format: [[fill]align][+| ][0][width][.precision][d|x|X|b|f|e|g] (a sign and zero padding for numbers, ${id:05} is 00042, ${-42:05} is -0042, ${d:+} marks non-negatives). This kills the to_string-then-pad dance in HUD code:

    jaiscript
    var name = "Vex";
var hp = 73.5;
var gold = 1234;
print(`${name:<8}|${gold:8}|`);                // strings left-align, numbers right-align
print(`${hp:.1f} ${gold:*>8} ${gold:^8}|`);    // fixed float; fill+align; centered
print(`${gold:x} ${gold:X} ${5:b}`);           // hex / HEX / binary (ints only)
print(`HP ${hp:>6.1f}/${100.0:<6.1f} G${gold:>7} ${name:<12}|`);
var crit = true;
print(`${crit ? "CRIT" : "hit"} for ${(crit ? 150 : 100):>5}|`);  // ternaries still work
try {
    print(`${name:.2f}`);                      // spec/type mismatch: catchable run-time error
} catch (e) {
    print("caught: {}", e);
}
print(format("{:.2f} vs {0:>8}", 3.14159));    // same specs in format()/print placeholders
    output
    Vex     |    1234|
73.5 ****1234   1234  |
4d2 4D2 101
HP   73.5/100.0  G   1234 Vex         |
CRIT for   150|
caught: format spec ':.2f' does not apply to string value
3.14 vs  3.14159

    The rules: .N means fixed (bare or with f; :f alone is 6 decimals), ^ centering puts the odd fill char on the right, and a malformed spec (${x:q}, ${x:#x}) is rejected at lex time with Unsupported format spec ':q' in template string. The spec starts at a top-level : that closes no ternary ?, so ${a ? b : c} stays an expression and ${m["k"]:6} / map-literal colons just work; parenthesize a ternary to give it a spec. Splices desugar to the engine-core builtin format_value(value, "spec"), available on every engine, one shared implementation, so both backends produce byte-identical output and error text.

    Parallel loops: parallel_for and parallel_transform​

    parallel_for runs a loop body over the elements of an array on every core with deterministic results: the same output at every thread count, byte-identical to the serial loop. The loop variable is the element, so auto& mutates it in place. parallel_transform(arr, fn) returns a new array with out[i] = fn(arr[i]); it is the same loop in a different spelling, as the section below shows. thread_count() reports the worker count.

    jaiscript
    var nums = [1, 2, 3, 4, 5, 6, 7, 8];
parallel_for (auto& x : nums) {
    x = x * x;                    // each element mutated in place, across workers
}
print("squares: {}", to_json(nums));

int inc(int v) { return v + 1; }
print("mapped:  {}", to_json(parallel_transform(nums, inc)));
    output
    squares: [1,4,9,16,25,36,49,64]
mapped:  [2,5,10,17,26,37,50,65]

    The zip form walks several arrays of the same length in lockstep, one loop variable per array. Worker n owns segment n of every array, so a pre-allocated array of output structs is written in place: no construction per element, no result marshalling. This is the emitter shape, one input array and one output array of the same length, and the preferred way to produce several values per element.

    jaiscript
    class Body { float x = 0.0; float vx = 0.0; Body() {} Body(float px, float v) { x = px; vx = v; } }
class Sample { float pos = 0.0; bool moving = false; }
array<Body> bodies = [];
array<Sample> samples = [];
for (int i = 0; i < 6; i++) { bodies.push(Body(i * 10.0, i % 3 - 1.0)); samples.push(Sample()); }

parallel_for (auto& b, auto& s : bodies, samples) {   // one loop variable per array, walked in lockstep
    b.x += b.vx * 0.5;                                 // the input mutated in place
    s.pos = b.x;                                       // the pre-allocated output written in place
    s.moving = b.vx != 0.0;
}
for (auto& s : samples) { print(`${s.pos:.1f} ${s.moving}`); }
    output
    -0.5 true
10.0 false
20.5 true
29.5 true
40.0 false
50.5 true

    Arrays of different length, the range itself as a zipped array, or a non-array are load-time errors: parallel_for: zipped array 2 has 1 elements, the range has 3 (zipped arrays must have the same length).

    parallel_transform is that zip. parallel_transform(xs, fn) is parallel_for (auto& x, auto& o : xs, out) { o = fn(x); } over a fresh output of xs.size() slots, and it costs exactly that loop plus the output. When fn only reads its parameter, its body runs inlined in the loop with the parameter bound to the element in place, so there is no call and no copy per element. A fn that mutates its parameter works on a private copy, so the source array is never touched either way. Any result type works, objects included: the returned array holds copies that alias nothing.

    jaiscript
    class Body { float x = 0.0; float vx = 0.0; Body() {} Body(float px, float v) { x = px; vx = v; } }
array<Body> bodies = [];
for (int i = 0; i < 4; i++) { bodies.push(Body(i * 10.0, 1.0)); }

float next_x(Body b) { return b.x + b.vx; }              // reads its parameter: the body runs inlined in the loop
Body stepped(Body b) { b.x += b.vx; return b; }         // mutates its copy: the source is untouched

var xs = parallel_transform(bodies, next_x);
var moved = parallel_transform(bodies, stepped);
print(`${to_json(xs)} moved ${moved[3].x:.1f} source ${bodies[3].x:.1f}`);
    output
    [1.0,11.0,21.0,31.0] moved 31.0 source 30.0

    An optional third argument, parallel_transform(arr, fn, weight_fn), balances chunks by per-element effort (e.g. weigh strings by length):

    jaiscript
    var texts = ["7", "42", "1999", "3", "250"];
int parse_one(string s) {                            // digits -> int, no host calls
    var n = 0;
    for (var i = 0; i < s.size(); i++) { n = n * 10 + (s[i] - '0'); }
    return n;
}
float w(string s) { return s.size(); }               // heavier strings, fatter chunks
var parsed = parallel_transform(texts, parse_one, w);
print("parsed: {}", to_json(parsed));
    output
    parsed: [7,42,1999,3,250]

    Control flow in the body. The body is the loop's body: continue moves to the next element, and so does a return written at the body's top level (iterations are independent, there is nothing to return to). A loop-level break is rejected at load time with parallel_for: 'break' is not allowed in a parallel body (iterations are independent; use 'continue' for the next element). Inside a nested loop or switch, break and continue keep their usual meaning.

    jaiscript
    var words = ["keep", "", "skip", "keep", "", "keep"];
array<int> kept = [0, 0, 0, 0, 0, 0];
parallel_for (auto& w, auto& k : words, kept) {
    if (w == "") { continue; }        // next element
    if (w == "skip") { return; }      // also the next element: the body is the loop's body
    k = w.size();
}
print("{}", to_json(kept));
    output
    [4,0,0,4,0,4]

    Captured reads: the body may read enclosing globals: scalars, strings, and value-semantic containers. Every worker sees the content as of the call (the "barrier"), identical at every worker count. Provisioning is automatic and tiered: a container of primitives or strings touched only by subscript reads is a zero-copy borrow (workers read the shared storage in place; a string read copies its bytes into a worker-owned string); anything else (nested containers, iterated or whole-value reads) is copied once per worker at the barrier and charged to memory_cap. This is what makes the "shared read-only grid" and "shared palette" renderer shapes cheap:

    jaiscript
    var gw = 4;
var grid = [];                       // the shared input: three rows of gw cells
for (var i = 0; i < gw * 3; i++) { grid.push(i); }
int row_sum(int row) {
    var total = 0;
    for (var x = 0; x < gw; x++) { total += grid[row * gw + x]; }   // captured reads
    return total;
}
var row_indices = [0, 1, 2];
var sums = parallel_transform(row_indices, row_sum);   // grid rides along for free
print("row sums: {}", to_json(sums));
    output
    row sums: [6,22,38]

    Writes to enclosing state are errors, always. The elements behind the loop variables are the only things a body may mutate. Assigning to captured state in any shape (g = ..., g[i] = ..., compound stores, g.push(...) (any mutating or unrecognized method on a captured value), var& r = g aliases, passing captured state to a by-reference parameter, or for (auto& v : g)) raises an error like parallel_for: body writes enclosing state 'total' at 3:33. Objects cannot be captured at all (parallel_for: member access reaches captured state 'cfg' (captured reads are read-only, and objects cannot be captured) at 4:45); pass per-element object state through the arrays instead. Host calls outside the pure-math/to_string whitelist, lambdas, class definitions and yield are rejected too. A throwing element fails the whole call with the first error in iteration order, so failures are as deterministic as results. Calls to other script functions (including recursion) and builtin container/string methods are fine.

    Where the output shape is not known up front, the pair idiom still serves: elements shaped [input..., tag] come back from parallel_transform as [tag, outputs...], collected from the result in iteration order. Use captured reads for shared inputs, a zipped output array for per-element results, pairs only for variable-shaped ones.
