    HTML Templates​

    A page is mostly HTML with a few values in it. template(path, a, b, ...) renders a template file: its text is HTML, and every ${...} in it is an expression, spliced in HTML-escaped. The template sees the names you pass it, by reference, and the program's functions and globals, and it is compiled and checked when the script that calls it loads. scoped_template(path, map) renders a template you did not write: it sees only a copy of the map, and nothing it does can reach the program. Both are on every engine; a template file is read under the filesystem privilege (Safety Rails).

    A template file​

    A template is a file, by convention name.spider. Its whole text is the template: there is no backtick around it, a backtick or a backslash in it is the page's own, and only \${ is an escape (it writes ${). Line endings read as \n. A splice takes the format specs a backtick string takes (Template strings & format specs). The path resolves from the file of the script that calls template, as an import's does.

    template — greeting.spider
    <p>Hello, ${name}! You have ${count} new ${count == 1 ? "message" : "messages"} (${ratio:.1f}).</p>
    jaiscript
    string name = "Ada <admin>";
int count = 3;
float ratio = 0.75;
web::html page = template("greeting.spider", name, count, ratio);
print(page);
print(type_of(page), " ", page.to_string().size());
    output
    <p>Hello, Ada &lt;admin&gt;! You have 3 new messages (0.8).</p>
web::html 63

    Each argument after the path is a plain variable name, and the template sees it by that name. Anything else fails the load: template("row.spider", rows[0]) reads template() argument 2 is not a plain variable name: the template sees each argument by its name, so name the value first (auto entry = rows[0];) and pass the name.

    What a template sees​

    A template's splices read like a function body at program scope whose parameters are the names you passed: each name is the caller's variable itself, bound by reference with its declared type, so any call its type allows works inside, and a store through it lands in the caller's variable under that type's rules. The program's functions and globals are there too, and a passed name hides a global of the same name, as a parameter does. The caller's other locals, its class's fields and this are not: a template that names one fails the load.

    template — row.spider
    <tr><td>${rank}</td><td>${player.name}</td><td>${medal(rank)}</td></tr>
    jaiscript
    class Player { string name; int score; Player(string n, int s) { name = n; score = s; } }
string medal(int rank) { return rank == 1 ? "gold" : rank == 2 ? "silver" : "-"; }
array<Player> players = [Player("Vex", 90), Player("Ada", 75), Player("Bo", 60)];
int rank = 0;
for (auto& player : players) {
    rank += 1;
    print(template("row.spider", rank, player));
}
    output
    <tr><td>1</td><td>Vex</td><td>gold</td></tr>
<tr><td>2</td><td>Ada</td><td>silver</td></tr>
<tr><td>3</td><td>Bo</td><td>-</td></tr>

    Because a name is the variable itself, a template that writes one writes the caller's:

    template — tally.spider
    ${seen += 1} of ${total}
    jaiscript
    int seen = 0;
int total = 2;
print(template("tally.spider", seen, total));
print(template("tally.spider", seen, total));
print("seen is now ", seen);
    output
    1 of 2
2 of 2
seen is now 2

    A template is one expression: it has no statements of its own. Choose with ?:, loop with array::map, and put anything longer in a function the template calls or in a smaller template. Use array::map(xs, f) rather than xs.map(f) over a passed array: the dot form maps the array in place (Containers & Strings), and the array is the caller's.

    Escaping and web::html​

    Every splice is HTML-escaped as web::html_escape escapes (The web:: Library): & < > " and ', so a splice is safe in element text and in a quoted attribute. A value's text is the one to_string gives, a class's own to_string() included. What template returns is a web::html: text that is already HTML. A web::html splices as it is, so one template's result spliced into another is not escaped twice, and an array splices its elements one after another, each by the same rule. raw(text), inside a template, is the opt-out: its text splices unescaped.

    template — item.spider
    <li>${item}</li>
    template — list.spider
    <h2>${title}</h2><ul>${array::map(items, item => template("item.spider", item))}</ul>${items}${raw(footer)}
    jaiscript
    string title = "Tom & Jerry";
array<string> items = ["<script>", "fish & chips"];
string footer = "<hr>";
print(template("list.spider", title, items, footer));
    output
    <h2>Tom &amp; Jerry</h2><ul><li>&lt;script&gt;</li><li>fish &amp; chips</li></ul>&lt;script&gt;fish &amp; chips<hr>

    A web::html is a value: copy it, keep it in an array, pass it to a function, return it from a handler. to_string() gives its text and print prints it. A script makes one only with a template: there is no constructor from text, so text becomes HTML only by passing through a splice or through raw in a template you wrote. Escaping is for HTML text and quoted attributes; a value that goes into a URL wants web::url_encode as well, and a template never splices into a <script> or a style safely.

    Checked at load​

    A template with a literal path is compiled where it is called, when that script loads, and checked against the names and types the call passes, like a C++ template where it is instantiated: a misspelled member of a typed value, or a function or global that does not exist, fails the load with the template's own file, line and column.

    template — profile.spider
    <h1>${user.name}</h1>
<p>${user.emial}</p>
    jaiscript
    class User { string name = "Ada"; string email = "ada@example.org"; }
User user = User();
print(template("profile.spider", user));
    output
    jaiscript: static check failed:
profile.spider:2:11: error: no member 'emial' in class 'User'

    A name the template uses that the call does not pass is a global, and fails the load if there is none: use of undeclared identifier 'secret', at the template's line, even when the caller has a local of that name.

    A template render writes at most the host's template output limit, 10 MiB by default: a page that would be longer raises template()'s output passed its 10485760-byte limit: the host raises it with engine::template_output_limit. A script reads the limits with reflect::template_output_limit() and reflect::scoped_template_output_limit() and cannot change them (Safety Rails). A template file is read under the filesystem privilege: with it off, template and scoped_template raise Insufficient privilege: filesystem. where they render, and scoped_template_text, which reads no file, still works.

    Paths known at run time​

    A path that is not a literal is resolved, read, compiled and checked the first time the call renders, then kept: each later render with the same names reuses it. A template that renders itself, a tree drawn by a template that renders each child, goes the same way: the inner call is compiled once, at its first render, and every level after reuses it. Pass the child under the template's own name, since the template sees each value by the name it is given.

    template — tree.spider
    <li>${node["label"]}<ul>${array::map(node["children"], node => template("tree.spider", node))}</ul></li>
    jaiscript
    var node = {"label": "root", "children": [{"label": "a", "children": []}, {"label": "b", "children": [{"label": "c", "children": []}]}]};
print(template("tree.spider", node));
string theme = "tree.spider";
print(template(theme, node).to_string() == template("tree.spider", node).to_string() ? "same" : "different");
    output
    <li>root<ul><li>a<ul></ul></li><li>b<ul><li>c<ul></ul></li></ul></li></ul></li>
same

    A template compiled at run time checks what the call's names cannot tell it: every name it does not pass and every function it calls, at its first render (the check failure is the call's catchable error); a member of a passed value is checked when it is read, since the run-time compile does not see the caller's declared types.

    Hot reload​

    A template file is tracked like an import. A literal path's template is part of the script that calls it, so an edit to the file makes that script load again where an import of it is reached (Modules): its new code is checked first, and an edit that does not check is reported by that import while the program keeps running the version that did. A path known at run time checks the file again at a render once the import window (import_recheck_interval) has passed: an edit that checks renders from then on, and one that does not raises once, where it renders, then the last version that checked renders until the file changes again. A template a template calls is tracked the same way. Nothing needs a restart.

    Templates you did not write: scoped_template​

    scoped_template(path, map) renders a template from a source you do not trust (a user's theme, a page a customer edits) over one value: the map, taken by value, so the template has its own deep copy. Inside, the only name is args, the copy. scoped_template_text(text, map) is the same over a string instead of a file: the two are spelled apart so a path is never mistaken for template text. Both return a web::html.

    jaiscript
    map<string, var> data = {"user": {"name": "<ann>"}, "items": ["tea", "cake"], "total": 7.5};
print(scoped_template_text("Hi ${args.user.name}: ${args.items.size()} items, ${array::map(args.items, i => string::to_upper(i)).join(\", \")}, ${args.total:.2f}", data));
print(to_json(data["items"]));
string untrusted = "${secret}";
try { scoped_template_text(untrusted, data); } catch (e) { print("caught: ", e); }
    output
    Hi &lt;ann&gt;: 2 items, TEA, CAKE, 7.50
["tea","cake"]
caught: parse failed:
<scoped_template_text>:1:3: error: a scoped template sees only args: 'secret' is not available
    ${secret}

    A scoped template may read args and index or read fields into it, use format specs, call any built-in method of a built-in value (a string, an array, a map, a math type) and the engine's string::, array:: and map:: functions, which return copies (${string::to_upper(args.name)}, ${array::map(args.items, i => i.size())}), and write x => expr lambdas for them under the same rules. An in-place method returns nothing, so a template, whose every value is spliced or used, raises the language's error for it (sort changes args.items in place and returns nothing; array::sort(args.items) returns a sorted copy): use the copy twin. It cannot reach anything else:

    refusedthe text
    a globala scoped template sees only args: 'secret' is not available
    a free or global function, or one in any other namespace (a script's own included)a scoped template calls only built-in methods and the string::, array:: and map:: functions: 'leak(...)' is not allowed
    a function valuea scoped template does not call function values: 'call(...)' is not allowed
    rawraw() is not allowed in a scoped template: its output is always escaped
    an assignment, this, new, a cast, a statementa scoped template is one expression over args: an assignment is not allowed
    a method of a class instance or a host objecta scoped template does not call a method of a class instance, a host object or a function: its code could run
    an operator on an instance (an overload)a scoped template does not apply an operator to a class instance, a host object or a function: its code could run
    splicing an instance (its to_string())a scoped template does not splice a class instance, a host object or a function: its code could run
    a built-in method over a value holding an instancea scoped template does not call a built-in method over a class instance, a host object or a function: its code could run
    a host property, or a field with a user accessora scoped template reads the plain fields of a script class instance: 'secret' is not one

    The rules a template's text breaks (a name, a call, raw, a construct) fail it when it is compiled: at load for a literal text or path, at the first render otherwise, with the template's line. The rules about values (an instance reached through args, whose class runs script) are checked as the template runs, since args holds whatever the caller put in it. A shared_ptr in the map is allowed, and reading a plain field through it is too; its methods stay out of reach. A scoped template always escapes, a web::html in the map included. A render writes at most the host's scoped template output limit (1 MiB by default; every splice counts, a nested template's text each time it is spliced): one that would write more raises a scoped template's output passed its 1048576-byte limit: the host raises it with engine::scoped_template_output_limit. It runs under the execution budget (Safety Rails) like any script. A scoped file reloads as a run-time template path does, and a literal one as an import's template does.
