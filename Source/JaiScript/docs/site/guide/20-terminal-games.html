    A Terminal Game in One File​

    The standalone runner, jaiscript, reads the keyboard, reports the terminal's size and plays sound. With print and the language's clocks, that is everything a real-time game needs, and the whole game fits in one .jai file you run with jaiscript game.jai. This chapter builds one: input polling, frame pacing, drawing with ANSI escape codes, sound and saves.

    These functions belong to the runner, not to the language. A C++ host that embeds JaiScript registers its own input, timing and audio (Embedding); the rest of the game code is the same.

    The console surface​

    CallGives
    read_key() -> stringthe next queued key press, without waiting: "" when none is queued, else a name such as "left", "esc", "space" or a lowercase letter
    key_down(name) -> boolwhether the key is held now
    term_cols(), term_rows() -> intthe terminal's size in characters (80 by 25 when it cannot be read)
    env_var(name) -> stringan environment variable, "" when unset: COLORTERM says whether 24-bit colour works
    load_sound(path), play_sound(path) -> Sounda WAV, MIDI or MP3 file to play, or null
    sleep(seconds), time::stopwatchwaiting and measuring, from the language itself (Time)

    The full rules for each, the names read_key returns included, are in the reference's runner host API.

    The whole game​

    Rockfall is a complete game: rocks fall, the @ dodges them with the arrow keys or a and d, and the score counts the rocks that missed. Save it as rockfall.jai and run jaiscript rockfall.jai. The sections below take it apart.

    jaiscript
    // rockfall.jai: dodge the falling rocks. Arrows or a/d move, esc quits.
string ESC = "\x1b";
int cols = term_cols() < 60 ? term_cols() : 60;
int rows = term_rows() < 25 ? term_rows() - 2 : 23;
bool truecolor = env_var("COLORTERM") == "truecolor" || env_var("COLORTERM") == "24bit";

string color(int r, int g, int b) {
    if (truecolor) { return `${ESC}[38;2;${r};${g};${b}m`; }
    return `${ESC}[38;5;${16 + r / 51 * 36 + g / 51 * 6 + b / 51}m`;   // the xterm-256 colour cube
}

class Rock { int x = 0; float y = 0.0; float speed = 8.0; }
array<Rock> rocks;
random rng(7);
int player = cols / 2;
int score = 0;
var crash = load_sound("crash.wav");   // null without the file, or off Windows: the game runs silent

print(ESC + "[?1049h" + ESC + "[?25l" + ESC + "[2J", skip_newline);   // alternate screen, hidden cursor, cleared
time::stopwatch clock;
clock.start();
float step = 1.0 / 30.0;
bool running = true;
while (running) {
    float frame_start = clock.elapsed();

    for (string key = read_key(); key != ""; key = read_key()) {   // every press queued since the last frame
        if (key == "esc") { running = false; }
    }
    if ((key_down("left") || key_down("a")) && player > 0) { player -= 1; }
    if ((key_down("right") || key_down("d")) && player < cols - 1) { player += 1; }

    if (rng.next_int(0, 2) == 0) {
        Rock r;
        r.x = rng.next_int(0, cols - 1);
        r.speed = rng.next_float(6.0, 14.0);
        rocks.push(r);
    }
    for (auto& r : rocks) { r.y += r.speed * step; }
    for (auto& r : rocks) {
        if (r.y >= rows - 1 && r.y < rows && r.x == player) { running = false; }
    }
    int before = rocks.size();
    rocks.filter([](Rock r) { return r.y < rows; });   // keeps what is still falling
    score += before - rocks.size();

    string frame = ESC + "[H" + color(150, 150, 165);   // cursor home: each frame overwrites the last
    for (int y = 0; y < rows; ++y) {
        string line = string::repeat(" ", cols);
        for (auto& r : rocks) {
            if (math::ifloor(r.y) == y) { line[r.x] = '*'; }
        }
        if (y == rows - 1) {
            line = line.substr(0, player) + color(255, 140, 0) + "@" + color(150, 150, 165) + line.substr(player + 1);
        }
        frame += line + "\n";
    }
    frame += ESC + "[0m" + `score ${score}   esc quits` + ESC + "[K";
    print(frame, skip_newline);   // one write per frame, flushed

    float spent = clock.elapsed() - frame_start;
    if (spent < step) { sleep(step - spent); }
}
if (crash != null) { crash.play(); sleep(0.5); }
print(ESC + "[0m" + ESC + "[?25h" + ESC + "[?1049l", skip_newline);   // the main screen back, as it was
print(`You dodged ${score} rocks.`);

    Every frame does the same four things: read the input, update the world, draw it, then wait out the rest of the frame. Nothing in the loop blocks, so the game runs at the same speed whether or not a key is pressed.

    Reading the keyboard​

    The two input calls answer different questions:

    • read_key() returns one press at a time from a queue, in order, and "" once the queue is empty. Drain it every frame with a loop, as Rockfall does, so no press waits a frame behind another. Use it for actions that happen once per press: a menu choice, a jump, esc to quit.
    • key_down(name) says whether a key is held at this moment. Use it for movement, which should continue as long as the key is down and stop when it is released.

    A POSIX terminal sends no key releases. There a key reads as held for half a second after its last press or auto-repeat, and "shift", "ctrl" and "alt" never read as held. On Windows the console reports releases, so a key reads as held exactly while it is down, and read_key also returns "shift", "ctrl" and "alt".

    Frame pacing​

    A stopwatch measures how long the frame took, and sleep waits out the rest of its time slot. The world moves by a fixed step each frame, so its speed does not depend on how fast the machine is:

    jaiscript
    time::stopwatch clock;
clock.start();
float step = 1.0 / 30.0;
for (int frame = 0; frame < 6; ++frame) {
    float frame_start = clock.elapsed();
    // input, update and drawing go here
    float spent = clock.elapsed() - frame_start;
    if (spent < step) { sleep(step - spent); }
}
print(`six frames took at least ${6 * step:.2f} s: ${clock.elapsed() >= 5.5 * step}`);
    output
    six frames took at least 0.20 s: true

    sleep(seconds) takes a float, and zero or less returns at once. A frame that runs long simply skips its sleep. A game that must keep its world speed even when frames run long moves the world by the frame's measured time, clock.delta(), instead of the fixed step.

    Drawing a frame​

    A terminal draws what it is sent, and escape sequences move the cursor and change colours. A game builds each frame as one string and prints it once with skip_newline, which writes the string, adds no newline and flushes, so the frame appears whole. Starting the string with the cursor-home sequence makes each frame overwrite the last, without clearing the screen and flickering:

    jaiscript
    string ESC = "\x1b";
string frame_of(array<string> grid, int score) {
    string result = ESC + "[H";                  // cursor home
    for (auto& row : grid) { result += row + "\n"; }
    return result + `score ${score}` + ESC + "[K";   // [K clears the rest of the line
}
print(to_json(frame_of(["  *  ", "     ", "  @  "], 3)));
    output
    "\u001b[H  *  \n     \n  @  \nscore 3\u001b[K"

    to_json shows the escape character as \u001b; in the string it is the one byte "\x1b". The sequences a game uses most:

    SequenceEffect
    ESC + "[?1049h", ESC + "[?1049l"enter the alternate screen, and leave it: the game draws on a screen of its own, and the shell's text comes back afterwards
    ESC + "[?25l", ESC + "[?25h"hide the cursor, and show it again
    ESC + "[2J", ESC + "[H"clear the screen; move the cursor to the top-left corner
    ESC + "[K"clear from the cursor to the end of the line, so a shorter line leaves nothing of a longer one behind
    ESC + "[38;2;R;G;Bm", ESC + "[48;2;R;G;Bm"24-bit text and background colour, where env_var("COLORTERM") is "truecolor" or "24bit"
    ESC + "[38;5;Nm"one of the 256 xterm colours, which every modern terminal takes: Rockfall's color falls back to it
    ESC + "[0m"back to the default colours

    A game that builds a frame from several print calls ends all but the last with skip_flush, which writes without a newline or a flush, and the last with skip_newline, which flushes them together (Hello & Basics).

    When a game ends, it leaves the alternate screen, shows the cursor and resets the colours. The runner does the same for a script that stops without doing it, through an error or Ctrl+C (Ctrl+C).

    The terminal's size​

    term_cols() and term_rows() are the window's size in characters, read each time they are called. Rockfall reads them once and caps them at a 60 by 23 field; a game that follows a resized window reads them each frame and clears the screen (ESC + "[2J") when they change. A frame one row shorter than the window keeps the last line free, so the terminal never scrolls.

    Sound​

    load_sound(path) opens a WAV, MIDI or MP3 file and returns a Sound at once while the file loads in the background. Load each effect once and play it whenever it is needed; play() restarts it, play(true) loops it and volume(level) sets its level. play_sound(path) loads and plays a sound in one call and lets it finish even when the result is dropped. Every Sound is its own voice, so music and effects play at once.

    Sound plays on Windows and on the site's Play page, in the games and the sandbox alike: the page plays WAV, MP3 and MIDI in the browser. Elsewhere, and for a file that is missing, load_sound returns null, so a game that checks for null, as Rockfall does, runs silent instead of failing. A game can write its own effects: binary::writer builds a WAV file's bytes, and write_file saves them (Binary data).

    Saves and paths​

    read_file and write_file resolve a relative path from the working directory, while import and include resolve from the script's folder. A game that keeps its saves beside its script builds the path from root_script_dir(), and one that keeps them per user builds it from app_data_dir(name) (Where files are). to_json and from_json turn the game's state into text and back, and writing a temporary file then moving it over the old one with move_file keeps a save whole if the game stops halfway through writing it.

    Bigger games​

    The example games are this chapter at full size: GLOOM, GRUBWELL, Gator Quest and JaiDoom all draw to a terminal through one string per frame, and read the keyboard with read_key and key_down; GLOOM, Gator Quest and JaiDoom play sound. Gator Quest also reloads its own scripts while it runs, which Modules shows how to do.
