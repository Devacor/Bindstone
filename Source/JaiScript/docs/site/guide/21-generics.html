    Generics​

    A generic is a class, a function or a method with type parameters: class Stack<T>, T largest<T>(array<T> xs). It is declared once and instantiated at load for each list of type arguments the program uses, and each instance is checked and run exactly as if it had been written by hand with the arguments in place of the parameters. This is C++'s template model.

    • Nothing is boxed and no T exists at run time: after the load, Stack<int> is an ordinary class named Stack<int> and largest<int> an ordinary function. Reflection, serialization, the debugger and both backends see ordinary declarations.
    • Type parameters go after the name, in the angle brackets array<T> already uses. template<typename T> is not a second spelling: it fails the load and names this one.
    • A generic's own text is parsed when its file loads, used or not, so a syntax error in it always fails the load. Its types are checked per instance.

    Generic classes​

    class Name<T, ...> declares one. Name<Args> then stands wherever a class name does: a declaration, a parameter, a field, a base class, new Name<Args>(...), Name<Args>(...), Name<Args>{...}, Name<Args>::member, cast<Name<Args>>, dynamic_cast<Name<Args>>.

    jaiscript
    class Stack<T> {
    array<T> items;
    void push(T item) { items.push(item); }
    T pop() { T last = items[items.size() - 1]; items.pop(); return last; }
    int size() { return items.size(); }
}

class Pair<K, V> {
    K first;
    V second;
    Pair(K k, V v) { first = k; second = v; }   // the bare class name inside is Pair<K, V>
}

Stack<int> numbers;                      // a type, anywhere a type is written
numbers.push(3);
numbers.push(9);
print(numbers.pop(), " ", numbers.size());

auto hp = Pair<string, int>("hp", 10);   // a construction names the arguments
print(hp.first, " = ", hp.second);
print(reflect::type_of(numbers), " / ", reflect::type_of(hp));
    output
    9 1
hp = 10
Stack<int> / Pair<string, int>
    • The class's bare name inside it is the instance. In Pair<K, V>, Pair alone (its constructor, a return type, a field) is Pair<K, V>; another instance is spelled with its arguments, Pair<V, K>.
    • A generic class is not overloaded. One unit declares a class name once: class Dup<T> beside class Dup<K, V> fails the load with generic class 'Dup' is declared with 1 type parameter on line 1 and with 2 type parameters here: a generic class cannot be overloaded by its parameter count, and so does a class beside a generic class of its name. A later unit's declaration replaces the earlier one (Declaring it again).
    • A class's type arguments are always written. A constructor does not deduce them: Pair("hp", 10) fails the load with 'Pair' is a generic class: its type arguments are written, never deduced from a constructor's (Pair<K, V>(...)).
    • A base may be an instance, of the class's own parameters or of fixed types: class Derived<T> : Base<T>, class Ints : Base<int>; a constructor initializer names it the same way, : Base<T>(x).
    • A generic is declared where it stands, as a class or a function is: top-level code runs in order, and a use of Name<Args> above the generic's declaration is the error a plain name gives, 'Box' is used before its declaration (line 3): top-level code runs in order, so declare it above the use or make the use after it. When an instance is declared has the rule.

    Generic functions​

    A function lists its type parameters after its name, in either head; a coroutine and a namespace's function do the same. A call writes the type arguments, largest<int>(scores), or leaves them to deduction.

    jaiscript
    T largest<T>(array<T> xs) {
    T best = xs[0];
    for (auto x : xs) { if (x > best) { best = x; } }
    return best;
}

function smallest<T>(array<T> xs) -> T {          // the trailing-return head: the same thing
    T best = xs[0];
    for (auto x : xs) { if (x < best) { best = x; } }
    return best;
}

coroutine T each<T>(array<T> xs) { for (auto x : xs) { yield x; } }

array<int> scores = [4, 8, 2];
print(largest<int>(scores), " ", smallest<int>(scores));   // the type argument written
print(largest(scores), " ", largest(["fig", "pear"]));     // or deduced from the argument
int sum = 0;
for (auto v : each(scores)) { sum += v; }
print(sum);
    output
    8 2
8 pear
14
    • Overloads. A generic function may share its name with ordinary functions and with other generics. An ordinary function that takes the call wins over a generic, in whichever unit it is declared: this one, a file the program imports, a unit that ran earlier. A namespace's function and a class's method, static or not, win over a generic of their name the same way. Of the generics, those whose type arguments can be found are the candidates. Candidates that find the same type arguments name one instance, and each is an overload of that name: with string show<T>(array<T> xs) beside string show<T>(T x, int n), show<int> is two functions, show<int>(array<int> xs) and show<int>(int x, int n), and the call's value arguments pick between them as between two functions written by hand, whether its type arguments were written (show<int>(5, 1)) or deduced (show(5, 1)). Candidates that find different type arguments name different instances, and the call fails the load: call to 'show' is ambiguous: the generics 'show<T>' (app.jai:1:6) and 'show<T>' (app.jai:2:6) both take it. Generic methods of one name overload the same way.
    • An instance is not a value. function f = largest<int>; fails the load; pass a lambda that calls it, (xs) => largest<int>(xs).
    • < after a name opens type arguments only where a type-shaped run closes on a > that (, { or :: follows; anywhere else it compares, so a < b and both(a < b, c > d) read as they always did. After a variable the parse has seen declared (a local, a parameter, a program-scope variable the unit declares above), which is never a generic, < always compares (Type arguments has the rule in full).

    Deduction​

    A call to a generic function or method may leave out type arguments that its value arguments name. Each parameter whose declared type mentions a type parameter is matched against the argument's load-time type:

    You writeWhat it is
    Tany type: the argument's own (T& deduces as T)
    array<T>, map<K, V>an array or a map of declared element types; a literal of one element type counts ([1, 2] is an array<int>)
    shared_ptr<T>, weak_ptr<T>a handle to a T
    Name<T>an instance of the generic class Name or of the host template Name, or a class that derives from one
    jaiscript
    K first_key<K, V>(map<K, V> m) { for (auto [k, v] : m) { return k; } return K(); }
T unwrap<T>(shared_ptr<T> p) { return p; }
U convert<U, T>(T x) { return cast<U>(x); }
void swap<T>(T& a, T& b) { T t = a; a = b; b = t; }
class Goblin { int gold = 3; }

map<string, int> stock = {"tee": 4};
print(first_key(stock));                    // K = string, V = int, from map<K, V>
shared_ptr<Goblin> g = new Goblin();
print(unwrap(g).gold);                      // T = Goblin, from shared_ptr<T>
print(convert<string>(41) + "!");           // U written, T deduced
int a = 1;
int b = 2;
swap(a, b);                                 // T& deduces as T
print(a, " ", b);
    output
    tee
3
41!
2 1

    The arguments a call writes fill the leading parameters and the rest are deduced, which is why convert lists U first. Deduction never converts: two arguments that give one parameter two types are an error, not a promotion. A null and a function value say nothing of a type and are skipped. A failure is a load error that says what to write:

    jaiscript
    T pick<T>(T a, T b) { return a; }
T make<T>() { return T(); }

pick(1, 2.5);
make();
    output
    jaiscript: static check failed:
<script>:4:12: error: cannot deduce T for 'pick': it is int from argument 1 and float from argument 2
    pick(1, 2.5);
               ^
<script>:5:6: error: cannot deduce T for 'make': no parameter names it; write make<T>()
    make();
         ^

    The other texts: argument 1's type is not known at load (a var, an untyped host result), argument 1 is null, which says nothing of a type, and argument 1 is int, which 'array<T>' does not match. What to write spells the generic's own parameters, with the ones the call did give filled in: for V lookup<K, V>(K key), lookup("hp") ends in write lookup<string, V>(...).

    • A construction has the type it makes, so it deduces like a variable of that type: int(x) and the other primitives, Goblin(), Goblin{}, Box<int>(3), new Goblin() and make_shared<Goblin>() (a shared_ptr<Goblin>), cast<T>(x), a math constructor such as math::vec2(1.0, 2.0), array<int>(3), and a host class's or a host template instance's constructor.
    • A host template deduces like a generic class. For a host that bound Point<int> and Point<float>, T first<T>(Point<T> p) takes either, and T is the argument the instance's name spells (host type arguments).

    Inside an instance​

    Inside an instance a type parameter is its argument. T x;, T(...), T{...}, new T(...), T::member, cast<T>(v), dynamic_cast<T>(v), dynamic_cast<T&>(v), array<T> and a call's f<T>(...) mean what they mean with the argument spelled out, so one text serves a class and a primitive:

    jaiscript
    class Point { int x = 0; int y = 0; Point() {} Point(int a) { x = a; y = a; } }

class Maker<T> {
    static T zero() { return T(); }          // a class default-constructs, a primitive is its zero
    T from(var v) { return T(v); }           // a class's constructor, a primitive's conversion
    T fresh() { T made; return made; }
    array<T> some() { array<T> xs; xs.push(T()); return xs; }
}

print(Maker<int>::zero(), " ", Maker<string>::zero() + "|", " ", Maker<Point>::zero().x);
Maker<int> ints;
Maker<Point> points;
print(ints.from(2.9), " ", points.from(7).y);
print(int(2.9), " ", float(3), " ", string() + "|", " ", bool());
    output
    0 | 0
2 7
2 3.0 | false
    • A primitive constructs by its name. int(), string() and bool{} are the type's zero, and int(x) is cast<int>(x); so are float, char, string and bool. That is what makes T() and T(v) read for every argument.
    • What a type argument may be: int float string bool char, a class, an enum, a math type, array<...>, map<...>, shared_ptr<...>, weak_ptr<...>, function, var, another instance. Never auto, void or a reference (write T& in the generic's own parameter list). A signature type, function<R(A...)>, and coroutine<Y> are not type arguments yet: 'function<int(int)>' is not a type an instance is made with: 'Box<function<int(int)>>'. Inside a generic both are types like any other and may name the parameters (function<T(T)> f); a signature deduces nothing, so a call whose only mention of T is one writes it.
    • What the text asks of an argument is the argument's own rule. dynamic_cast<T>(v) with T = int fails as dynamic_cast<int>(v) does, in that instance only; with T = shared_ptr<Hero> it is dynamic_cast<Hero>(v), the handle the argument already names.
    • A type parameter's name is reserved in its generic: a variable, a parameter, a field or a method named T fails the load ('T' is a type parameter of 'Stack': a declaration cannot reuse its name). A member read, x.T, is no use of the parameter.

    One instance, one class​

    An instance's name is its canonical spelling, the one reflect::type_of, reflect::type_name, reflect::classes(), error texts, stack traces and $type in JSON show: Stack<int>, Pair<string, int>, shop::Shelf<shop::Product>. A class argument is named by its qualified name, so the two spellings below are one class. var as an argument is spelled var (Cell<var>). An instance joins its arguments with a comma and a space, a builtin container with a comma alone (Pair<string, int>, Cell<map<string,int>>), and that is the only spelling ever printed or saved. A name that arrives as text is matched without its whitespace: a $type in JSON or in a binary or base64 archive, the class name reflect::construct and the other reflect:: functions take, a name a host looks a class up by. Pair<string,int>, Pair<string, int> and Pair< string , int > reach one class; case stays significant.

    jaiscript
    namespace shop {
    class Product { string title = "tee"; }
    class Shelf<T> { array<T> items; }
    Shelf<Product> inside;                        // Shelf and Product are the namespace's own
}

shop::Shelf<shop::Product> outside;               // the same class, by its qualified spelling
shop::inside.items.push(shop::Product());
outside = shop::inside;
print(reflect::type_of(outside), " ", outside.items.size());

class Cell<T> { T held; }
class Item { int n = 0; }
Cell<Item> a;                                     // a class argument: a copy copies the Item
Cell<Item> b = a;
b.held.n = 5;
Cell<shared_ptr<Item>> c;                         // a shared_ptr argument: a copy shares it
c.held = new Item();
Cell<shared_ptr<Item>> d = c;
d.held.n = 5;
print(a.held.n, " ", c.held.n);
    output
    shop::Shelf<shop::Product> 1
0 5
    • Value semantics follow the argument. A class argument copies with its holder; a shared_ptr argument shares.
    • Statics are per instance, as in C++: Pool<Goblin>::made and Pool<Orc>::made are two variables.
    • Inside its namespace a generic class answers to its bare name, as any class of the namespace does: in the unit that declares it, in another file of the program that opens the namespace, whichever of the two is imported first, and in a later unit that opens it again (namespace shop { Shelf<Product> more; }). Code in a nested namespace reaches its enclosing namespace's generic class the same way, and using shop::Shelf; names it from outside.
    • Two units that use an instance use one class. Each unit declares the instances its own code names (its jaibite is self-contained and no unit waits for another to run); the second declaration of an instance finds it defined from the same generic and does nothing, so its statics keep their values.
    • An instance exists once a unit that ran names it. Loading data does not make one: from_json of a $type that spells an instance no unit used raises 'Cell<float>' names an instance of the generic 'Cell' that the program never made: name the type where it is loaded, as from_json<Cell<float>>(text) does. from_json<Cell<float>>(text) names it, and so does a variable of the type anywhere in a unit that ran.

    Bounds​

    T : Base requires the argument to be Base or a class that derives from it. A bound is a class and may name the parameters (T : Comparable<T>). It does not change how the body is checked: it moves the error to the use, and says what the generic expects.

    jaiscript
    class Entity { int id = 0; }
class Goblin : Entity { int gold = 3; }
class Orc : Entity { int rage = 9; }

class Pool<T : Entity> {                 // T is Entity or derives from it
    array<shared_ptr<T>> live;
    static int made = 0;                 // one per instance: Pool<Goblin>::made, Pool<Orc>::made
    shared_ptr<T> spawn() { made += 1; live.push(new T()); return live[live.size() - 1]; }
}

int id_of<T : Entity>(T e) { return e.id; }

Pool<Goblin> goblins;
Pool<Orc> orcs;
goblins.spawn();
goblins.spawn();
orcs.spawn();
print(Pool<Goblin>::made, " ", Pool<Orc>::made, " ", id_of(Goblin()));
    output
    2 1 0

    The bound is checked where the instance is asked for, before its body:

    jaiscript
    class Entity { int id = 0; }
class Pool<T : Entity> { array<shared_ptr<T>> live; }

Pool<int> numbers;
    output
    jaiscript: static check failed:
<script>:4:5: error: Pool<int>: 'int' does not derive from 'Entity', which T requires
    Pool<int> numbers;
        ^

    Generic methods​

    A method lists type parameters like a function. Its instance is a real method of the class: it reads this, the class's private members and its other methods, and static works as for any method. A generic class may declare generic methods of its own.

    jaiscript
    class CartForm { string sku; int count = 0; }

class Request {
    string body = "{\"sku\": \"tee\", \"count\": 2}";
    T json<T>() { return from_json<T>(body); }      // T forwards to a host's type argument
    static T make<T>() { return T(); }
    T twice<T>(T x) { return x + x; }
}

Request req;
CartForm form = req.json<CartForm>();               // never deducible here: T is only the result
print(form.sku, " x", form.count);
print(Request::make<CartForm>().count, " ", req.twice(4), " ", req.twice("ab"));
    output
    tee x2
0 8 abab

    A generic method is not virtual (a member template cannot be in C++ either). The instance is chosen by the receiver's class as the load knows it: a variable's declared class, a reference's, the class of another unit's declared global. A derived class's generic of the same name hides the base's, and override on a generic method is an error.

    jaiscript
    class Base { string who<T>() { return "base"; } }
class Derived : Base { string who<T>() { return "derived"; } }

Derived d;
Base& as_base = d;
print(d.who<int>(), " ", as_base.who<int>());
    output
    derived base

    A receiver whose class the load does not know (a var) cannot pick an instance: cannot instantiate 'json<CartForm>': the receiver's class is not known at load. Give it a typed variable or a typed reference. A call that leaves its type arguments to deduction loads, since a var may hold any class, and fails where it runs with the same advice: Base::twice is a generic method: its instance is picked where the call is written, from the receiver's class, which is not known there; give the receiver a typed name (Base x = ...) or cast it (cast<Base&>(x).twice(...)).

    The class may stand below the call. A function above the class, or above the import that brings it, may call its generic method: the method's instance is declared the moment its class is (When an instance is declared). A call that runs before then finds no class, as a call of a plain method would: Class 'Oracle' not found for a static call, No constructor found for class 'Oracle' where it would make one. A class declared again keeps the instances its callers declared.

    jaiscript
    int ask(Oracle o) { return o.answer<int>(3); }      // above the class: its instance waits for it

class Oracle {
    int base = 4;
    T answer<T>(T x) { return x + base; }
}

print(ask(Oracle()));
    output
    7

    When an instance is declared​

    An instance is declared the moment everything it is built on is declared: its generic, every class its type arguments name, its base classes, and for a generic method's instance the class it belongs to. When all of those exist as the unit starts (they came from imports that already ran, or are builtin types), that moment is the start of the unit. No place is computed from the uses, so it does not matter how the instance is first named: a type, a construction, a call, a cast, a dynamic_cast, a type argument, a function's or a lambda's body, another instance's text.

    jaiscript
    int seed() { return 5; }
class Shelf<T> {
    static int made = seed();          // runs when the instance is declared
    T item;
}
print(reflect::classes().contains("Shelf<Book>"));    // Book is not declared yet: Shelf<Book> waits for it
class Book { string title = "Dune"; }
print(reflect::classes().contains("Shelf<Book>"), " ", Shelf<int>::made);
auto shelf = Shelf<Book>();              // an expression names it first; the type below changes nothing
Shelf<Book> other;
print(shelf.item.title, " ", other.item.title);
    output
    false
true 5
Dune Dune
    • Its declaration runs at that moment, as a class written at that point would: the initializer of a static runs then and sees what is declared above it (seed above), a base class is looked up then, and nothing declared further down exists yet. A static's initializer that reads a global declared below the generic fails as it would in a plain class there.
    • The order rule is the one plain names have. A use in top-level code names the generic and its argument classes, so it stands below their declarations: above one, a construction or a call is a load error with the plain text ('Box' is used before its declaration (line 3): ..., 'Item' is used before its declaration (line 4): ..., 'twice' is called before its declaration (line 2): ...), and a typed declaration is a run-time error, as it is for a plain class, that says what the instance waits for ('Holder<int>' is not declared yet: it waits for 'Holder' where the plain class is No constructor found for class 'Plain'). A function's instance is declared the moment its generic is: a function above the generic may call it, and a call that runs before the generic's declaration has run fails where a call of a plain function declared below does, with 'twice<int>' is not declared yet: it waits for 'twice' where the plain one is Undefined variable 'twice'.
    • A class may derive from an instance of itself, class Num : Comparable<Num>: the instance is declared as that class's declaration begins.
    • An instance that still waits says what for, whatever reaches it: a typed declaration, a construction, new or a container's element in a function that runs above class Book, reflect::construct("Shelf<Book>") and from_json of that $type all raise 'Shelf<Book>' is not declared yet: it waits for 'Book'. The text is the same on both backends.

    Errors in an instance​

    An error inside an instance is reported at the generic's own file and line, with a note that names the instance and where it was asked for; nested instances add one note per level. Each instance reports what its own arguments break, and an instance that is sound reports nothing:

    jaiscript
    class Box<T> {
    T item;
    int length() { return item.size(); }
}

Box<string> words;
Box<int> count;
    output
    jaiscript: static check failed:
<script>:3:32: error: int has no member 'size'
    in Box<int>, instantiated at <script>:7:4
        int length() { return item.size(); }
                                   ^

    Modules, hot reload and jaibite​

    A generic is visible to every unit of the program, like a function: the units a root reaches through import and include are gathered before any is checked, and a unit that ran earlier in the engine counts too.

    jaiscript
    import "stack.jai";

Stack<string> names;
names.push("ann");
print(names.items.size(), " ", Stack<string>::made, " ", reflect::type_name(names));
print(to_json(names));

    with stack.jai:

    jaiscript
    class Stack<T> {
    array<T> items;
    static int made = 0;
    Stack() { made += 1; }
    void push(T item) { items.push(item); }
}
    output
    1 1 Stack<string>
{"$type":"Stack<string>","$val":{"items":["ann"]}}
    • Hot reload. A generic's file is part of every module that instantiates it, as a template file is part of the module that renders it: an edit to the generic re-runs those modules (their classes and functions replace the old ones in place, their top-level statements run again). A broken edit is reported and the old code keeps running.
    • jaibite. A unit's jaibite holds the instances it uses as ordinary declarations, and a generic as its tokens, so a loaded generic still instantiates. A unit that instantiates a generic another file declares keeps no jaibite cache, like a unit with a spliced include: its freshness would know only its own file.
    • Declaring it again. An edit to a generic's file is the generic declared again: the instances the engine holds are made again as the file runs, and each module that runs again finds its instances made and resets nothing (Declaring it again).

    Declaring it again​

    A generic's name is declared, declared again and clashes as a class's name does. A later unit that declares it (a later execute, its file loaded again after an edit, another file) replaces the earlier declaration, and nothing asks for the engine to start over.

    Every instance the engine holds is made again from the new text, where the new declaration stands, whatever the unit names. An object that lives takes the new methods and gains the new fields, a function compiled before the change calls the new body, and a field or a static that keeps its name keeps its value: what a class declared again does.

    jaiscript
    class Box<T> { T v; static int made = 0; Box() { made += 1; } int get() { return 1; } }
Box<int> a;
a.v = 5;
int use() { Box<int> x; return x.get(); }
print(a.get(), " ", use());
import "again.jai";                 // another unit declares Box again and names no instance
print(a.get(), " ", use(), " ", a.v, " ", Box<int>::made);

    with again.jai:

    jaiscript
    class Box<T> { T v; int extra = 7; static int made = 0; Box() { made += 1; } int get() { return 3 + extra; } }
    output
    1 1
10 10 5 3
    • Top-level code runs in order: above the new declaration the earlier instance still answers, below it the new one, as with a class declared twice in a unit.
    • A generic function and a generic method follow the same rule: the instances their callers hold are made again when the generic is declared again (a method's when its class is). A generic function declared with other value parameters is another overload beside the first, as for a plain function, and the first one's instances stay. An instance belongs to the declaration it was made from: of two overloads that both made show<int>, the one declared again makes its own show<int> again and leaves the other's.
    • An instance the new declaration cannot make keeps the declaration it has, and the unit's check warns, naming it and the reason: another count of type parameters, a bound its argument no longer meets, a body that does not check for its arguments. 'Box<int>' keeps its earlier declaration: this declaration of 'Box' cannot make it: 'Box' takes 2 type arguments, not 1. The objects of that instance keep working; naming it in new code is the ordinary error for the same reason, and a later declaration that can make it does.
    • One name is one class. class Box<T> beside class Box in one unit fails the load at the second of them: class 'Box' is declared without type parameters on line 1 and with 1 type parameter here: a class and a generic class cannot share a name. From a later unit the later declaration takes the name. A class declared under a generic class's name leaves that generic's instances as they are, with the warning above (... cannot make it: 'Box' takes no type arguments: it is not a generic class). A generic class declared under a class's name leaves the class to the code and the objects that use it already, and the bare name then names no class wherever a class's name can stand in new code: a declared type (a variable's, a parameter's, a result's, a field's, a handle's or a container's element), a type argument, new, cast, dynamic_cast, a base class, a braced construction Box{}, a static member Box::made and the name as a value. Each is 'Box' is a generic class: name its type arguments (Box<T>), the error a bare generic name gives anywhere; a namespace's generic class gives it by its qualified name too (shop::Box::made).
    • Two files that each declare a generic class of one name do what two files that declare one class do: the one that runs later replaces the other.
    • A unit that made instances again keeps no jaibite cache: what it declared rested on what the engine held.

    Limits and what is not here​

    • Instantiation nests at most 64 deep: class A<T> { A<array<T>> next; } fails the load with generic instantiation nests more than 64 deep and the first links of the chain, not a hang. A note under an error spells an instance's name of more than 80 characters by its two ends (in A<array<array<arra ... >>>>, instantiated at ...).
    • A class's members are made with it, so that an instance is the class as written by hand, to reflection and to a var receiver alike. A member that names an instance of its own generic built from the instance itself would therefore ask without end, and fails the load at the first step, where the member stands: for class List<T> { List<List<T>> chunks() { ... } }, List<int> reports 'List<int>' would need 'List<List<int>>' and so on without end: the member 'chunks' names an instance of 'List' built from the instance itself; a class's members are made with it and a generic function only where it is called, so write it as one outside the class: chunks<T>(List<T> self). The generic function it names, List<List<T>> chunks<T>(List<T> self), is made only for the calls the program writes.
    • Each of these is a load error with its own text, not a silent gap: default type arguments (<T = int>), specialization (class Stack<int>), non-type parameters (<int N>), variadic parameters (<T...>), generic lambdas (use auto parameters), deducing a class's arguments from its constructor, an instance as a function value, and a generic declared inside a function body.
    • Type arguments go on a generic's name only. On any other type they fail the load once, wherever the type stands, with what the name is: 'Hero' takes no type arguments: it is not a generic class, ... it is a host class, not a host template, ... it is an enum, 'int' takes no type arguments: it is a builtin type.
    • A generic class or function may not take the name of a template the host bound (host type arguments), since Point<int> spells the host's class: 'Point' is a host template: a generic cannot take its name. A generic class may not take the name of a class the host bound, as no script class may: cannot declare class 'Sprite': the host binds a C++ class of that name; give the script class another name, or derive from it (class Other : Sprite). A generic function may, as a plain function may, and a generic method's name is its class's own.
