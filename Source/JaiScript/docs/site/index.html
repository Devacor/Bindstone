Fluent C++ scripting.

Auto-Binding: Script/Serialize/Reflect
Rock solid hot reload.
Typesafe with an escape hatch.

Declare a property once in C++ and scripts can read it, write it and save it, with no glue code. Edit a script while the game runs: classes reload in place and the world keeps its state.

Scripts read and copy like C++. Two independent backends (a tree-walking interpreter and a bytecode VM) print the same output and error text, byte for byte, and every standalone sample on this site runs on both.

One declaration, no glue

A C++ class opts in once. Every JAI_PROPERTY is a single declaration that makes the field reflected, script-visible and serialized, so there is no binding table or serializer to keep in sync:

C++
class Spawner : public jai::property_owner<Spawner> {
public:
    JAI_PROPERTY((std::string), id, "north-gate");   // scripted and saved
    JAI_PROPERTY((int64_t), level, 1);
    JAI_SIGNAL_PROPERTY(void(int64_t), onWave);      // script-connectable, saved too
    void spawn_wave();
};

static jai::registrar<Spawner, void> _regSpawner("Spawner",
    [](jai::dynamic_binder<Spawner>& b) {
        b.method("spawn_wave", &Spawner::spawn_wave);   // a method is one line
    });

Scripts then use it as if it were written in script: auto s = Spawner(); s.level = 3;, s.onWave.connect(...) with a script receiver, and the same object saves to JSON or binary. The Dynamic Binder walks the whole class through: scripted, reflected, serialized and hot-reloaded with its state intact.

Get JaiScript

JaiScript builds from source in a few minutes. You need git, CMake 3.25+ and a C++20 compiler:

  • Windows: Visual Studio 2022 or newer with the C++ workload
  • macOS: the Xcode command line tools
  • Linux: GCC 11 or Clang 14

The installer clones JaiScript into a folder of your own, builds the runner in Release and puts its bin folder on your PATH. Run it again to update and rebuild.

macOS, Linux, WSL

shell
curl -fsSL https://jaiscript.com/install.sh | sh

Windows PowerShell

PowerShell
irm https://jaiscript.com/install.ps1 | iex

Windows CMD

CMD
curl -fsSL https://jaiscript.com/install.cmd -o install.cmd && install.cmd && del install.cmd

Not sure which Windows shell you have? PowerShell's prompt shows PS C:\; CMD's shows C:\.

When it finishes, open a new terminal and run jaiscript --version. If the command isn't found, the install folder isn't on your PATH yet: see Fix your PATH. The installer also prints the line that starts Gator Quest, an open-world terminal RPG written in JaiScript.

Read the scripts before you run them: install.sh, install.ps1 and install.cmd.

  • They install to ~/.jaiscript, or %LOCALAPPDATA%\jaiscript on Windows. Options pick the folder, a release, a compiler or a generator.
  • --no-modify-path leaves your PATH alone: curl -fsSL https://jaiscript.com/install.sh | sh -s -- --no-modify-path.
  • None of them asks for sudo or administrator rights.

One line with git and CMake

This line clones the repository, builds the runner in Release and starts Gator Quest. It uses CMake's default generator (Visual Studio on Windows, Makefiles elsewhere), builds in parallel, and runs unchanged in bash, zsh, PowerShell 7 and CMD, with no developer prompt and no Ninja.

shell
git clone --depth 1 https://github.com/Devacor/jaiscript.git && cmake -P jaiscript/tools/install/build_runner.cmake && cmake -E chdir jaiscript build/bin/jaiscript examples/gatorquest/scripts/gatorquest.jai

Two lines to hello

C++
auto e = jai::engine::make();
e->execute("print(\"hello\");");

Yes, really two lines: a bare engine ships a basic print. JaiScript is a static lib plus headers, with no global interpreter state. One more line, jai::stdlib::register_all(e);, adds the formatted {} print and the standard library (math, containers, JSON). Every sample on this site assumes it: the standalone runner registers it for you, and the two-line host needs that line first.

The embedding chapters take it from there:

  • bind a C++ class in a fluent chain
  • connect host signals to script

Here is what the language itself looks like:

jaiscript
var anything = 5;            // dynamic — the explicit, visible opt-out
anything = "now a string";   // fine; you asked for this

class Hero {
    int hp = 10;
    void heal(int amount) { hp += amount; }
}
function bump(int& x) { x += 1; }   // mutation is visible at both ends

auto h = Hero();
h.heal(5);
bump(h.hp);            // fields and elements bind by reference too
print("hp = {}", h.hp);
output
hp = 16

No host yet? The repository ships a standalone runner. Save the script above as hello.jai and run jaiscript hello.jai.

  • Strict checking and the VM backend are the defaults.
  • jaiscript alone is a REPL, and jaiscript --watch hello.jai re-runs on every save.
  • Building the runner is one CMake target; its flags are on the reference page.
  • A web application is a host away too: jai_spider app.jai spins the app over HTTP, with SQLite, cookie sessions, static files and the spider:: client, and applies each saved edit to the next request (jai_spider).

Coming from another language

The Language Bridges start from what you already write. Each one sets JavaScript, C++ or C# beside JaiScript idiom by idiom, then runs the habits that get a different answer.

Moving C++ code off Cereal, Boost.Serialization, Boost.Signals2, ChaiScript, sol2, Squirrel, pybind11, nlohmann::json, Qt properties, RTTR or a coroutine scheduler? The Code Migrations map each library's calls to JaiScript's and convert real code.

The seven pillars

01The type ladder

int x is enforced. auto x is inferred, then enforced. var x is dynamic: a choice you can see in a diff, not a default you fall into.

The static checker is always on and always strict. Typed code gets its errors at load, before a statement runs; var opts out (like TypeScript's any, but designed in); and [[warn_mode]] lets a region's errors through as warnings.

The Type Ladder →

02Value semantics, references by declaration

Assignment, parameters and returns copy. Nothing aliases at a distance: a function can change your data only when its signature says &.

Saves are deterministic, nothing mutates behind your back, and to_json of any value means what you think it means.

Value Semantics →

03Two implementations, one executable spec

A tree-walking interpreter and a bytecode VM must agree byte for byte, error text included. More than 4,700 tests run against both, and a differential fuzzer files a bug whenever they disagree, so semantics cannot rot silently.

The one documented exception is recursion depth: the backends cap it differently, and the VM reuses a bare self tail call's frame.

Backends →

04Zero global state

No statics, no singletons: every value carries its engine. Two engines on two threads need no locks, and tests cannot contaminate each other.

In-language parallelism (parallel_for, parallel_transform, deterministic at any worker count) falls out of this property instead of fighting it.

Quickstart →

05Hot reload that never bricks

Redefine a class mid-session and live instances migrate: fields keep their values, changed types convert permissively, and new fields take their initializers. Migration never fails.

A source that does not parse or check simply does not load, and the old class keeps running. Code already running when the reload lands, a suspended coroutine included, finishes on the version it started with. The dungeon crawler reloads its own scripts mid-game the moment you save one, and keeps the run.

Hot Reload →

06Safe at the boundary, by construction

Beyond the core builtins, a script can only touch what the host registered: the binding surface is the allowlist.

Checked integer overflow, catchable recursion limits and an execution budget are on by default. A memory cap is one call, and so is switching off the core's file loading (include, import), which is on by default. A hostile script cannot catch-and-swallow its way past the budget or the cap.

Untrusted scripts are a configuration, not a rewrite, though this is not an OS sandbox.

Safety Rails →

07Parse once, run anywhere

engine->jaibite(source) parses once and runs many times, and save("level.jaibite") ships it precompiled: symbols relocate on load, so one file serves any engine.

Even a naive execute(str) in a loop pays the parse once, through the source cache.

Who it's for

Anyone embedding scripting in a C++ engine who wants:

  • iteration speed: hot reload and script classes
  • safety rails a host can tighten in a few calls
  • types that scale from prototype (var) to production (int, checked strictly) within the same file
  • a language whose behavior is enforced by two implementations arguing with each other

It was built alongside a real 2D game engine, hardened by adversarial review and differential fuzzing, and dogfooded by building real, playable things in it. The source is MIT-licensed, and Stability lists what is settled before 1.0 and what may still change.

Shipping a game or a tool with JaiScript inside? A small line in its credits, such as “Scripted with JaiScript”, would be lovely to see. It is a request, not a condition: the MIT license is the only term that applies.
