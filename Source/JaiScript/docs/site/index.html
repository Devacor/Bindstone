JaiScript

An embedded scripting language for C++ engines: C++-flavored syntax, script classes with hot reload, coroutines, gradual typing — and two interchangeable backends kept at full behavioral parity, so the semantics are enforced by implementations arguing with each other rather than a document nobody reads.

Two lines to hello

C++
auto e = jai::engine::make();
e->execute("print(\"hello\");");

It compiles as part of your project — a static lib plus headers, no global interpreter state anywhere. Bind a C++ class in a fluent chain, hand the script a budget and a memory cap, and iterate with hot reload:

jaiscript
int hits = 0;          // enforced — assigning a string is an error
auto name = "Jai";     // inferred, then enforced — locked to string
var anything = 5;      // dynamic — the explicit, visible opt-out
anything = "now a string";   // fine; you asked for this

class Hero {
    int hp = 10;
    void heal(int amount) { hp += amount; }
}
function bump(int& x) { x += 1; }   // mutation is visible at both ends

auto h = Hero();
h.heal(5);
bump(h.hp);            // fields and elements bind by reference too
print("hp = {}", h.hp);
output
hp = 16

The seven pillars

01The type ladder

int x is enforced. auto x is inferred, then enforced. var x is dynamic — a choice you can see in a diff, not a default you fall into. The optional static checker maps onto it exactly: typed code gets compile-time errors, var opts out — like TypeScript's any, but designed-in.

The Type Ladder →

02Value semantics, references by declaration

Assignment, parameters, and returns copy. Nothing aliases at a distance; a function cannot mutate your data unless its signature says &. Deterministic saves, no spooky mutation, and to_json of any value means what you think it means.

Value Semantics →

03Two implementations, one executable spec

A tree-walking interpreter and a bytecode VM, required to agree byte-for-byte — including error text — enforced by 1,500+ tests run against both, plus a differential fuzzer that files a bug whenever they disagree. Semantics cannot rot silently.

Backends →

04Zero global state

No statics, no singletons; every value carries its engine. Two engines on two threads need no locks, tests cannot contaminate each other, and the planned parallel story falls out of this property instead of fighting it.

Quickstart →

05Hot reload that never bricks

Redefine a class mid-session and live instances migrate: fields keep values, changed types convert permissively, new fields take their initializers. The reload always succeeds, because iteration speed is the point. The roguelike reloads its own scripts mid-game on a keypress.

Hot Reload →

06Safe at the boundary, by construction

A script can only touch what the host registered — the binding surface is the allowlist. Checked integer overflow, catchable recursion limits, an execution budget and a memory cap that a hostile script cannot catch-and-swallow its way past. Untrusted scripts are a configuration, not a rewrite.

Safety Rails →

07Parse once, run anywhere

engine->jaibite(source) parses once, executes many, and save("level.jaib") ships precompiled — symbols relocate on load, so one file serves any engine. Even naive execute(str) in a loop pays the parse once via the source cache.

The honest tradeoffs

  • Copies cost. Value semantics means passing a big structure by value deep-copies it. The idiom is & parameters for anything heavy — cheap by design. If you write Python-shaped code expecting reference semantics, your first hour will surprise you; read Value Semantics first and it won't.
  • Call-dense recursion is slower than Lua today (~5× on a fib microbenchmark). Most game scripts are loop- and method-shaped, where the gap is small to none — the register-window VM redesign that closes it is on the roadmap, not a hope.
  • Two backends cost maintenance. That's the price of the executable spec, and shared semantic kernels are steadily shrinking the duplicated surface.
  • Some behaviors are still under design review. Writing these docs from the test suite surfaced 13 of them — they're documented as observed, not papered over: Open Questions.

Who it's for

Teams embedding scripting in a C++ engine who want iteration speed (hot reload, script classes), safety rails on by default, types that scale from prototype (var) to production (int + strict checking) within the same file, and a language whose behavior is enforced by two implementations arguing with each other. It was built alongside a real engine (MutedVision / Bindstone), hardened by adversarial review and differential fuzzing, and dogfooded by building real, playable things in it.
