One declaration, no glue

Bind a class once: scripts use it, saves store it, the editor reflects it.

C++
class Spawner : public jai::property_owner<Spawner> {
public:
    JAI_PROPERTY((std::string), id, "north-gate");   // scripted and saved
    JAI_PROPERTY((int64_t), level, 1);
    JAI_SIGNAL_PROPERTY(void(int64_t), onWave);      // script-connectable, saved too
    void spawn_wave();
    void spawn_wave(int64_t count, bool elite);       // overloaded in C++
};

static jai::registrar<Spawner, void> _regSpawner("Spawner",
    [](jai::dynamic_binder<Spawner>& b) {
        b.method("spawn_wave", [](Spawner& s) { s.spawn_wave(); })   // a lambda picks the overload
         .method("spawn_elites", [](Spawner& s, int64_t count) { s.spawn_wave(count, true); });
    });

Each JAI_PROPERTY is the field, its script binding, its save key and its reflection, so the four never drift apart.

C++
// turret.h comes from a library you can't edit
struct Turret {
    std::string name = "north";
    int64_t ammo = 10;
    void fire();
    void aim(float yaw, float pitch);
};

// your binding file: the class stays untouched
static jai::registrar<Turret, void> _regTurret("Turret",
    [](jai::dynamic_binder<Turret>& b) {
        b.constructor<>()
         .property("name", &Turret::name)   // scripted and saved
         .property("ammo", &Turret::ammo)
         .method("fire", &Turret::fire)            // a method is one line
         .method("aim", [](Turret& t, double yaw) {    // a lambda adapts any signature
             t.aim(float(yaw), 0.0f);
         });
    });

Third-party and engine types bind from the outside, with the same script access and saves keyed by the property names.

Either way, script sees a native class (auto t = Turret(); t.ammo = 3;) and the same object saves to JSON or binary. The Dynamic Binder walks a class through being scripted, reflected, serialized and hot-reloaded with its state intact.

Two lines to hello

C++
auto e = jai::engine::make();
e->execute("print(\"hello\");");

A static library plus headers, with no global state. jai::stdlib::register_all(e); adds formatted print, math, containers and JSON; every sample on this site assumes it.

var anything = 5;            // dynamic — the explicit, visible opt-out

class Hero {
    int hp = 10;
    void heal(int amount) { hp += amount; }
}
void bump(int& x) { x += 1; }       // mutation is visible at both ends

auto h = Hero();
h.heal(5);
bump(h.hp);            // fields and elements bind by reference too
print("hp = {}", h.hp);

No host yet? Save it as hello.jai and run jaiscript hello.jai. jaiscript alone is a REPL, and --watch re-runs on every save (the runner, its flags). For the web, jai_spider app.jai serves the app over HTTP and applies each saved edit to the next request.

The seven pillars

01The type ladder

int x is enforced, auto x inferred then enforced, var x dynamic. The checker is always on: a typed mistake stops the load, before anything runs.

02Value semantics

Assignment, parameters and returns copy. Your data changes only where a signature says &.

03Two implementations, one spec

An interpreter and a VM agree byte for byte, error text included, held there by 4,700+ tests and a differential fuzzer.

Backends →

04Zero global state

Every value carries its engine. Two engines on two threads need no locks, and parallel_for gives the same answer at any worker count.

05Hot reload that never bricks

Live instances migrate and keep their fields. A file that doesn't check doesn't load, and the old code keeps running.

Get JaiScript

git, CMake 3.25+ and a C++20 compiler: Visual Studio 2022 or newer with the C++ workload, the Xcode command line tools, or GCC 11 / Clang 14.

macOS, Linux, WSL

shell
curl -fsSL https://jaiscript.com/install.sh | sh

Windows PowerShell

PowerShell
irm https://jaiscript.com/install.ps1 | iex

Windows CMD

CMD
curl -fsSL https://jaiscript.com/install.cmd -o install.cmd && install.cmd && del install.cmd

It clones JaiScript, builds the runner in Release and puts it on your PATH; run it again to update. Then open a new terminal and run jaiscript --version.

What the installer does, its options, and fixing your PATH

Read the scripts before you run them: install.sh, install.ps1 and install.cmd. Not sure which Windows shell you have? PowerShell's prompt shows PS C:\; CMD's shows C:\. The installer also prints the line that starts Gator Quest, an open-world terminal RPG written in JaiScript.

  • They install to ~/.jaiscript, or %LOCALAPPDATA%\jaiscript on Windows. Options pick the folder, a release, a compiler or a generator.
  • --no-modify-path leaves your PATH alone: curl -fsSL https://jaiscript.com/install.sh | sh -s -- --no-modify-path.
  • None of them asks for sudo or administrator rights.

Fix your PATH

If jaiscript --version isn't found, the install folder isn't on your PATH yet:

SystemAdd the runner's folder to your PATH
macOS, Linux, WSLAdd export PATH="$HOME/.jaiscript/bin:$PATH" to ~/.zshrc, ~/.bashrc or ~/.profile, whichever your shell reads, then open a new terminal.
WindowsOpen Start, search for environment variables, choose Edit environment variables for your account, select Path, then Edit, New, and enter %LOCALAPPDATA%\jaiscript\bin. Then open a new terminal.

One line with git and CMake

shell
git clone --depth 1 https://github.com/Devacor/jaiscript.git && cmake -P jaiscript/tools/install/build_runner.cmake && cmake -E chdir jaiscript build/bin/jaiscript examples/gatorquest/scripts/gatorquest.jai

It clones, builds the runner in Release and starts Gator Quest, in bash, zsh, PowerShell 7 or CMD, with no developer prompt and no Ninja. The runner is jaiscript/build/bin/jaiscript; run the middle command alone to build again.

Toolchain presets

Pick a toolchain

The one-line build uses CMake's default generator (Visual Studio on Windows, Makefiles elsewhere) and builds in parallel. Each preset below configures a Release tree in build-<preset> and builds everything (the library, the runner, the test suite and the examples) into build-<preset>/bin:

  1. cmake --preset <preset>
  2. cmake --build --preset <preset>. Add -j 8 on Makefiles, which otherwise build one file at a time, and --target jaiscript_runner for the runner alone.

Who it's for

Anyone embedding scripting in a C++ engine who wants hot reload and script classes, safety rails a host tightens in a few calls, types that scale from var to strictly checked int within the same file, and behavior enforced by two implementations arguing with each other.

Built alongside a real 2D game engine, hardened by adversarial review and differential fuzzing, and dogfooded on real, playable things.
