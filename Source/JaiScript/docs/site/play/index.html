Play in the Browser​

Three of the example games, running in this page. The JaiScript engine is compiled to WebAssembly and runs the same scripts the standalone runner runs, so what you play here is the game the runner plays: same frames, same seeds, same state hashes.

What runs here​

The page downloads the engine (the library and the runner's console builtins, built with Emscripten) and the game's .jai files, then runs the game's drag-drop shim, the file you would drop onto the runner. The VM compiles the scripts in the page; nothing is precompiled and nothing runs on a server. A terminal emulator draws the game's escape codes, and your keys reach the script's key_down and read_key.

The engine runs in a worker, where a script's sleep() sleeps as it does in the runner. A browser that cannot share memory with the worker runs it on the page's own thread instead, where every sleep() hands control back to the page; that build is slower. Sound stays off in the browser. WebAssembly runs the VM a few times slower than a native Release build: GLOOM and GRUBWELL keep their frame rate, and the demo reel, which draws every pixel of every scene, plays its heavier scenes slower than in a terminal.

To run your own code, open the sandbox.
