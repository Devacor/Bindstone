    Full API signatures

    The complete callable reference for core builtins, standard-library registrations, and the standalone runner. Each entry shows arguments, defaults, result, effects, and availability. Host applications may register additional APIs.

    Reference overview · Machine-readable catalog

    Reading signatures

    These signatures use documentation notation, rather than declaration syntax: name(argument: type = default) -> result. T, K, V, and R stand for element, key, value, and callback-result types. number means int or float, text means string or utf8_string, and Self means the receiver's text type. An or joins accepted types; it does not introduce a script union type. Optional callback indices appear in brackets. Signal type names describe a host-bound family.

    Effects: observe reads; copy returns new values; mutate changes the receiver; advance changes a cursor or coroutine; callback may execute script; filesystem, network, output, and audio affect the host environment. Receiver text mutators return text for chaining. Core APIs exist on every engine; stdlib APIs require their registration; runner additions are provided by jaiscript.exe.

    Sorting arrays

    values.sort() sorts the receiver in place using the language's <. A class's explicit operator< takes precedence; when absent, operator<=> supplies the comparison with zero. values.sort(predicate) uses a boolean predicate: true means the left item comes before the right. Equal items may be reordered. The receiver method returns no value; array::sort(values[, predicate]) returns a sorted copy. Default numeric sorting groups all NaNs last and treats signed zeros as equivalent; an explicit predicate supplies its own ordering.

    jaiscript
    array<int> values = [3, 1, 2];
values.sort();
print(to_json(values));
values.sort((a, b) => a > b);
print(to_json(values));
    output
    [1,2,3]
[3,2,1]

    Typed integer, floating, boolean, byte, char, and string buffers use native sorting without per-element boxing or script comparisons when ordinary built-in ordering applies. Generic values and user comparisons use a temporary snapshot, committing the ordering after comparisons succeed. Comparison errors propagate; callback side effects are not rolled back. The predicate and element order should be a strict weak ordering that does not mutate the compared values or ordering rule; a predicate that breaks this still leaves a permutation of the elements, in an unspecified order. This is a C++-style boolean comparator, rather than JavaScript/C#'s signed comparison result.

    Builtin booleans, vectors, arrays and maps have an order. Records use their explicit < or <=> operator; otherwise choose a predicate. For example, flags.sort((a, b) => !a && b) orders false before true; points.sort((a, b) => a.x < b.x) orders by x. Sorting is O(n log n); user callback cost is additional, and callback paths use O(n) temporary storage.
