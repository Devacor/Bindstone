    Errors and Diagnostics​

    Diagnostics as you read them​

    An error has one of two shapes, and the shape says when it happened: a static listing before anything runs, or a run-time text that catch sees.

    The static listing (before anything runs)​

    jaiscript
    int x = 5;
x = "hello";                  // typed to typed: the load fails, nothing runs
print("never printed");
    output
    jaiscript: static check failed:
<script>:2:3: error: cannot assign 'string' to 'x' declared 'int' (declared at 1:5)
    x = "hello";                  // typed to typed: the load fails, nothing runs
      ^

    The shape is FILE:LINE:COL: error: MESSAGE, then the source line, then a caret.

    PartRule
    FILEThe unit's resolved path (the root file, an import, an include); <script> for source text handed to execute().
    MessageLowercase, except the few that reuse a run-time text and keep its capital (Cannot access private member 'x' of class 'C', Cannot access private constructor of class 'C'). One about a declared name ends with (declared at LINE:COL).
    A failed loadHands the host one jai::static_check_error whose what() is the whole listing (sorted by location, deduplicated, capped at 100). Nothing has executed.
    WarningsShadowing, a copying cast: the same shape with warning:; they never stop the load. The runner lists them under --warnings; a host reads them from last_check_diagnostics().
    A syntax errorThe same shape under parse failed:, thrown as jai::parse_error. The parser lists every syntax error in source order (it resumes after each); no check runs until the source parses.

    Run-time errors (what catch sees)​

    jaiscript
    var dynamic = "hello";        // var: the checker cannot see what it holds
try {
    int x = dynamic;          // so this fails at run time, where catch sees it
} catch (e) {
    print("caught: {}", e);
}
    output
    caught: Cannot initialize 'x' (declared int) with string

    Run-time texts lead with the action that failed, or with the builtin or member that refused it; names are quoted. catch (e) receives an error that reads as the text alone. An uncaught error's what() on the host side is the same text alone, with no category or location appended (only an error raised without a text of its own reads as its category's name). Every text is byte-identical on both backends.

    Error kinds​

    A caught error's e.kind is one of the error_kind:: names (each is a string holding its own name), decided by the error's code, so a script tells errors apart without reading their text:

    KindErrors
    error_kind::null_receivera member read or a call through null
    error_kind::no_membera member or static member the value does not have
    error_kind::namean undefined variable or class
    error_kind::not_callablea call of a value that is not a function
    error_kind::argumentsan argument count, a constructor or an overload that does not match, an ambiguous call
    error_kind::typea typed slot, parameter, return, element, key or cast that refuses the value
    error_kind::arithmeticinteger overflow, division or modulo by zero, a non-numeric operand
    error_kind::boundsan array or string index out of range
    error_kind::key_not_founda read of a map key that is not there
    error_kind::containeran element taken from an empty array
    error_kind::referencea reference, handle or capture that cannot bind
    error_kind::limitthe call-depth cap, the memory cap's first raise
    error_kind::hostan exception a C++ function raised: a host function or a library builtin
    error_kind::otherevery other run-time error
