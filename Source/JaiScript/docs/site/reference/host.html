    Engine API quick reference​

    The embedding surface used across the embedding chapters; each row links to the chapter with the compiled-and-run example.

    Engine lifecycle & execution: Quickstart​

    APIWhat it does
    jai::engine::make()create an engine (always a shared_ptr<engine>; no global state anywhere)
    jai::stdlib::register_all(eng)opt-in stdlib: formatted print, format, to_string, to_json, time::, reflection and other optional helpers. Math, array transforms, text and binary primitives are engine core; a bare engine also has basic print + format_value
    eng->execute(src)run a script; returns jai::script_value (last expression's value). Under strict checking a rejected script throws jai::static_check_error before anything runs
    r.as<T>() / as_int() / as_float() / as_string() / as_bool()convert results
    eng->execute_file(path)run a file; every node is attributed to its canonical path (listings, traces, breakpoints) and a .jaibite in the .cache folder beside it caches the parse
    eng->start(src) / start_file(path) / start(callable, args)run a script as a suspendable run: each sleep hands back a jai::script_run whose resume() continues it once wake_at() has passed (Suspendable runs)
    eng->get_variable(name) / has_variable(name) / has_function(name)read a global back (a function is a value too)
    fn.as_function()(args)call a script function from C++; returns checked_result<script_value> (eng->format_error(r) for its text); an uncaught script throw arrives as jai::script_exception. Wrap in engine::external_call_guard only when a script is running
    jai::convert_script_function<Sig>(fn)a typed std::function over a script function; a script error or an uncaught script throw inside it throws jai::runtime_error to the C++ caller (a host function called from script hands it back to the script as that call's error)
    v.as<std::vector<T>>() / as<std::map<K, V>>() / as_array() / unchecked_array_node()->for_each(eng, f)containers back into C++: typed arrays and maps copy out, as_array() views an array<var> only, for_each walks any array kind
    eng->set_backend(jai::backend_type::interpreter)choose the tree-walking interpreter (the bytecode VM is the default), before the first execute (forbidden after), in a program that links jaiscript_interpreter
    eng->set_output_stream(s)redirect print(); nullptr restores std::cout
    eng->set_script_error_handler(fn)sink for script errors nothing can catch (a destructor failing at engine teardown)
    eng->format_stack_trace() / last_stack_trace()script stack of the most recent failure

    Registering the host surface: Quickstart, dynamic_binder​

    APIWhat it does
    eng->add_function(name, lambda)typed host function; repeated names build an overload set resolved by argument types. A non-const T& parameter writes the callee's final value back into the script lvalue argument (a variable, field, element, map value, static, C++ property or vector component v.x) through that slot's own store rule; a literal or temporary argument is a copy. A std::shared_ptr<T> or std::weak_ptr<T> parameter takes null as an empty handle, and a std::weak_ptr<T> parameter takes a live shared_ptr or weak_ptr handle as one to the same object
    eng->add_variadic_function(name, fn)receives the raw std::vector<script_value>. For print-shaped functions and optionals
    eng->add_host_direct(name, arity, invoke, target)an entry over the arguments where they are, for the function name holds at this call: a VM call site calls invoke(target, args, arity) for arity non-reference arguments instead of the function, which takes every other call. See A direct entry for a hot host function
    eng->add_global(name, value)copy a value in
    eng->add_global_ref(name, var)live binding (cpp_bound) to a C++ primitive/string. Script reads and writes the real variable
    eng->make_value(v) / make_null() / make_array() / make_map()value factories (every script_value carries its engine); make_value of a script_value hands it back, and as<script_value>() is the value itself
    jai::dynamic_binder<T>(*eng, "Name")fluent class binding: .constructor<Args...>() .method(...) .property(...) .static_method(...) .static_property(...) .base_class<B>() .build()
    .method("+", &T::operator+)operator overloading by token name (+ - * / % & | ^ << >> == != < <= > >= <=>, unary - + ~, [], (), =). The script rules apply: <=> supplies the relational operators and ==, != falls back to negated ==, and an operator counts for an operand only when one of its overloads takes it
    .property("child", &T::child, jai::skip_type_check)opt out of registration-order validation for circular dependencies
    extend(object, Class) (script)give a host-owned object a script class over its C++ class or one of its bases, in place; idempotent, re-derives for another class. See Script-Extensible Objects
    eng->extend(obj, "Class")the same from C++; add_global, make_object and every other entry hand script the object's layer, extended before or after
    eng->script_layer(*obj) / script_layer_detach(obj)the object's live layer / drop it (fields returned as JSON)
    obj->script_layer_to_json() / script_layer_from_json(s)script_extensible (every property_owner): the layer's {"$type", "$script"} state, out and back

    Safety rails: Safety Rails​

    APIWhat it does
    eng->execution_budget(seconds)wall-clock cap per execute()/next(); default 5.0 s, 0 disables. Overrun is terminal. Script catch cannot swallow it
    eng->execution_step_budget(checks)clock-free twin for deterministic gates: at most checks budget checks (one per 1024 back-edges and call entries) per host entry, then the same terminal error; default 0 (off)
    eng->memory_cap(bytes)approximate high-water per top-level execute: first raise is catchable and denies in place, second raise is terminal; 0 = unlimited
    eng->max_call_depth(jai::backend_type::vm, n)the recursion cap per backend (interpreter 256, VM 250,000 by default); overrun is the catchable recursion error
    eng->throw_on_overflow()reports the build's integer-overflow policy (checked = default)
    jai::debug::listen(*eng, port) / conn->listening() / conn->error()the VS Code (DAP) listener; a taken port does not throw, listening() is false and error() says why
    eng->add_include_path(dir)search roots for script include/import (first added wins on collisions)
    eng->confine_paths({dirs})opt-in: include, import, resolve_path and file_data open only files under these folders, and no .cache is written beside a source outside them; empty (the default) opens any readable path (Safety Rails)
    eng->reset_import(path) / reset_imports() / is_imported(path) / get_imported_files()import-cache management
    eng->set_import_behavior(mode)file_timestamp (default) / once / always
    eng->import_recheck_interval(seconds)how often a reached import asks the filesystem whether its module changed: at most once per window (default 0.2 s); 0 checks on every reach (tests that write a file and import it at once). The script builtin import_recheck_interval(s) sets the same
    eng->hot_reload_reporting(true) / hot_reload_reports() / clear_hot_reload_reports()off by default. On, every field operation a class reload performs on live instances, and every saved value a load converts or cannot fit into its field, aggregates into std::vector<jai::field_migration_report> rows (class_name, field_name, old_type, new_type, outcome: preserved / converted / reset / added / removed, count across instances) until cleared
    eng->disable(jai::filesystem) / enable(...) / is_enabled(...) / register_privilege("name")the filesystem privilege (on by default) and custom named permissions; a host function registered with a final requirement (add_function(name, fn, {"app.edit"})) raises Insufficient privilege: app.edit. while it is off

    Time source: Quickstart, Time​

    APIWhat it does
    eng->time().source(monotonic, wall, sleep)replace the clock every time:: call reads: monotonic and wall providers return std::chrono::nanoseconds (wall = since the Unix epoch, UTC), sleep takes a duration; an empty provider selects the system one. The engine reads a provider only inside a time:: call, plus the monotonic one at each host entry once a loaded program names time::execute_elapsed
    eng->time().monotonic_now() / wall_now() / sleep_for(d)the same providers from C++ (one read each); eng->time() is declared in <jaiscript/core/engine_time.hpp>
    eng->engine_elapsed() / execute_elapsed()what time::engine_elapsed() and time::execute_elapsed() answer

    Static checking & precompiled scripts: Static Checking, jaibite​

    APIWhat it does
    eng->check(src)parse (cached) + check without running, returns jai::check_report, the tooling entry point
    eng->last_check_diagnostics()report from the last checked execute/bite (warnings included)
    eng->type_proofs(bool)default on. The checker's walk also stamps type proofs that let both backends skip conversions it has shown to be identities; every proof sits behind a run-time guard, so type_proofs(false) is observationally identical (same values, output and error text), just slower. Leave it on
    eng->parameter_alias(bool) · eng->local_alias(bool)default on. A by-value parameter or local that is provably only read binds the argument or source itself instead of a copy (Choosing a strategy); off copies every time, observationally identical, for a differential check
    eng->jaibite(src)parse once → engine-bound handle; bite.execute() skips the parse (VM also caches the compiled chunk). Checked at creation in warn/strict (strict throws there); bite.checked_clean() / bite.check_diagnostics() expose the result
    bite.save(path) / save_bytes()ship the parsed AST as .jaibite, stamped with the build's format version (jai::detail::k_jaibite_version); loading another version fails with jaibite: unsupported format version N (expected M) (the automatic disk cache just reparses instead)
    eng->jaibite_load(path) / jaibite_load_bytes(b)load into any engine. Symbols re-intern, one file serves both backends. A bite whose registration fingerprint differs from this engine's is re-checked at load against this engine's surface
    bite.registration_mismatch()flags a registered-surface difference between saving and loading engines. Advisory, covers every registration form incl. zero-arg and variadic functions; loads never hard-fail on it
    eng->jaibite_cache(bool) / jaibite_cache()automatic disk cache for file-based loads (default ON): include/import/execute_file keep .cache/foo.jai.jaibite beside foo.jai, the folder made when missing. A cache loads only for the exact source text it records (size + hash) and a matching registration fingerprint, whatever the files' mtimes; anything else reparses and rewrites it. A cache is written to a temporary file and renamed into place; writes are silent best-effort, tried once per source text (jaibite_cache_write_failures() counts them)
    eng->jaibite_cache_directory(dir, root) / jaibite_cache_directory()every cache below dir at the source's path relative to root (outside it, or with no root, the source's own path); a valid .cache beside the source still loads, never rewritten. For read-only bundles; empty restores the default
    eng->jaibite_cache_path(source)the cache file the engine writes for source (empty for a .jaibite source)

    Command-line runner​

    jaiscript is the reference embedding and the quickest way to run anything on this site. It is built by the jaiscript_runner target (on by default), lands in build/bin/, and always registers:

    • the full stdlib, the web:: library
    • the spider:: HTTP client (WinHTTP on Windows, sockets elsewhere, the network permission granted)
    • file IO (read_file, write_file, file_exists, delete_file, move_file, dir_exists, make_dirs, list_dir, writable_dir, plus Download, zip_entries and zip_extract)
    • a small console-game surface (A Terminal Game in One File: read_key, key_down, term_cols, term_rows, env_var, and sound: load_sound, play_sound, stop_sounds; clocks are the standard library's time::)
    • two socket classes, NetServer and NetChannel, and net_host_name and net_local_addresses

    Enough that the example shims and JaiDoom run on it unmodified. Full notes: tools/jaiscript/README.md.

    InvocationWhat happens
    jaiscript file.jai [-- args...]run the file as a suspendable run (each sleep returns to the runner, which waits on the engine's clock and resumes it) and exit.
    • The exit code is the script's trailing int expression if there is one, 1 on a script error, 2 on a usage error (an unknown flag, a missing or malformed value).
    • Only 0 to 255 survive as an exit code everywhere: an int outside that range exits with its low byte (300 exits 44, -1 exits 255) on every platform.
    • Everything after -- is the global ARGS.
    • Dropping a .jai onto the executable does the same and pauses before closing.
    jaiscript -e "source" [-e ...] [-- args...]run the source text and exit, as a file run runs a file's text.
    • Several -e run in order in one engine (declarations carry over, the first error stops the run).
    • The exit code is the last source's int result, 1 on a script error.
    • Nothing prints unless the source prints (jaiscript -e "print(1 + 2)"); the REPL is the mode that echoes values (echo 1 + 2 | jaiscript).
    • Combines with the flags below. include/import resolve from the working directory.
    • A script file or --watch alongside is a usage error.
    jaiscripta REPL with a persistent engine: :load, :reset, :backend vm|interp|vm-reference, :time on|off, :help, :quit. Piped input (echo 1 + 2 | jaiscript) exits 1 when any input failed, else 0
    jaiscript --watch file.jaire-run the file on every save, in a fresh engine each time (a program that keeps its world reloads with a guarded import in its loop instead: Reloading from a running program)
    FlagMeaning
    --backend=vm|interp|vm-referenceexecution backend (default vm); both must agree, so the other one is your second opinion. vm-reference is the VM with every optimization off (engine::vm_reference_mode)
    --warningslist the checker's warnings on stderr before the script runs (typed mistakes and undeclared names always fail the load)
    --workers=Nthe worker count of parallel_for, parallel_transform and parallel_reduce (default: the engine's own)
    --budget=Nexecution budget in seconds per execute; default 0 = unlimited (the embedded default of 5.0 s is deliberately lifted in a runner)
    --timeprint wall time per run
    --debug / --debug-port=Nstand up the DAP debug listener on localhost (VS Code attaches to it) and name the port it bound on stderr. --debug-port=N listens too, trying port N first (default 52477, probing upward in steps of 10). Without either, nothing listens
    --pause / --no-pauseforce or suppress the "press Enter to close" hold after a file run
    --version / --help
    --benchmark-main=Nrun the file once as a warm-up, then call its main() N times (a repeatable timing loop)
    --no-param-alias / --no-local-aliasturn off the read-only copy elision for by-value parameters / locals, so every one copies (results never change; a tool for measuring and for bisecting)
    --no-proofsrun without type proofs, typed ops or cell blocks: the general form, with the same results
    --miss-every=Nthe VM misses at every Nth plain cell instruction, exercising the flush at every position (a build configured with JAISCRIPT_MISS_INJECTION)
    --disasm=FILE / --manifest=FILEwrite every chunk the VM compiles to FILE: readable listings, or exact semantic manifests
    --coverage=FILEthe VM's execution-coverage census at exit (a build configured with JAISCRIPT_VM_COVERAGE)
    --selftestrun the runner's built-in smoke tests and exit

    Ctrl+C. Ctrl+C or Ctrl+Break on Windows, and SIGINT, SIGTERM or SIGHUP on Linux and macOS, end the runner at once, in every mode the REPL included.

    • The script stops where it is, without running its destructors, and the exit code is 130 (on Linux and macOS the signal itself ends the process, so the shell reports 130, 143 or 129).
    • A signal the runner was started with ignored (nohup, a background job) stays ignored.
    • Before it exits the runner gives the terminal back, following what the script printed. On a terminal it resets the colours, shows the cursor and leaves the alternate screen only where the script changed them. It does the same when a script ends or fails without undoing them. The input mode, and on Windows the console mode and code pages, come back too.
    • A pipe or a file receives none of it.

    A script that must stop itself in time has the execution budget (--budget=N).

    The runner's host API​

    The runner registers these on every engine it builds. A host embedding JaiScript has none of them unless it registers its own. The calls that name a file (the file functions, Download.start, load_sound and play_sound) run under the engine's filesystem privilege. An engine with it disabled raises Insufficient privilege: filesystem. at the call. Download.start reaches the network too and needs the network privilege as well. Signatures and effects are also in the API reference under the standalone runner.

    Locations (executable_dir(), root_script_dir(), current_script_dir(), resolve_path(name), app_data_dir(name) and the rest) are language builtins on every engine, described in Modules. A script that builds its paths from them runs the same from any working directory.

    Files and foldersBehavior
    a relative pathresolves from the working directory, while import and include resolve from the script's folder: a path built from root_script_dir() names the same file from any working directory
    read_file(path) -> stringthe file's bytes exactly (binary mode; "" for an empty file). A file that is missing or unreadable raises Cannot read file '<path>': <reason>
    write_file(path, text) -> boolwrites the bytes exactly, creating missing folders; false when it cannot
    file_exists(path), dir_exists(path) -> boolwhether the path names something, or a folder
    delete_file(path) -> boolremoves the file; false when nothing was removed
    move_file(from, to) -> boolreplaces to; false when from is not a file. On one volume the replacement is a single operation, so a reader sees the old file or the new one (the last step of a safe save: write save.tmp, then move it over save.txt); across volumes it copies, then removes the source
    make_dirs(path) -> boolcreates the folder and its parents; true when the folder exists afterwards
    list_dir(path) -> array<string>the folder's entry names, sorted; empty for a folder that cannot be read
    writable_dir(path) -> boolcreates the folder if missing, then writes and removes a probe file: whether the folder can take a save
    zip_entries(zip) -> array<string>, zip_extract(zip, entry, dest) -> boola zip archive's entry names, and one entry written to dest with its CRC-32 verified
    Download()an asynchronous download the script polls from its own loop. start(url, path) begins it (http or https; false with error() set when it cannot begin). pump() returns true once it is done; success() and error() give the outcome, received(), total() (-1 until known) and fraction() the progress, cancel() stops it. A failed transfer leaves no partial file
    Console gamesBehavior
    read_key() -> stringthe next key press, without waiting: "" when none is queued, else "up", "down", "left", "right", "enter", "esc", "tab", "space", "backspace", a lowercase letter, a digit or a punctuation character (on Windows also "shift", "ctrl" and "alt")
    key_down(name) -> boolwhether the named key is held now: a letter, a digit, "space", an arrow, "enter", "esc", "tab", and on Windows "shift", "ctrl" and "alt". A POSIX terminal sends no key releases, so there a key reads as held for half a second after its last press or auto-repeat, and the modifiers never read as held
    term_cols(), term_rows() -> intthe console window's size in characters (80 by 25 when it cannot be read)
    env_var(name) -> stringan environment variable's value, "" when it is unset: env_var("COLORTERM") is "truecolor" or "24bit" in a terminal that takes 24-bit colour
    SoundBehavior
    load_sound(path) -> Soundopens a WAV, MIDI or MP3 file and returns at once while the file preloads in the background, so a long song is ready by the time it plays. The file's first bytes name the format (RIFF/WAVE, MThd, an ID3 tag or an MPEG frame); a header it does not recognize falls back to the extension (.wav, .mid, .midi, .mp3). null for a missing file or another format
    s.play(), s.play(true) -> boolstarts the sound from the beginning, looping forever with true, and returns at once; playing a Sound that is already playing restarts it. false once the file proved unplayable (its data did not decode)
    s.stop(), s.playing() -> boolstops it; playing() is true from play() until stop(), stop_sounds() or the end of a sound played once
    s.volume(level)sets the level, 0.0 to 1.0 (clamped); a Sound starts at 1.0
    s.format() -> string"wav", "midi" or "mp3"
    play_sound(path), play_sound(path, true) -> Soundload_sound then play, for a sound fired and forgotten: it plays to its end (or forever, looped) even when the result is dropped, and the result stops it. null as load_sound
    stop_sounds()stops every Sound

    Every Sound is its own voice: music in one, ambience in another and effects in the rest all play at once, mixed.

    • A Sound loaded once and played again is the way to fire an effect many times, since loading a file costs more than playing it.
    • A loaded Sound closes when the last variable holding it lets go (a copy of a Sound is the same sound).
    • No call waits on the audio device: one audio thread opens and drives the devices, so a frame loop never stalls on a sound.
    • Sound plays on Windows and on the site's Play and Sandbox pages. Elsewhere load_sound and play_sound return null, so a script that checks for null, as it does for a missing file, runs unchanged, silent.
    jaiscript
    var music = load_sound("theme.mid");
var hit = load_sound("hit.wav");
if (music != null) { music.volume(0.6); music.play(true); }   // loops until stopped
if (hit != null) { hit.play(); }                               // again and again, each restarting it
play_sound("door.wav");                                        // fire and forget
    NetworkingBehavior
    NetChannel()one framed TCP connection: listen(port) waits for one peer, connect(host, port) dials one, send(bytes) queues a packet, pump() moves the bytes and fires the signals, close() drops the connection; connected() and status() ("idle", "listening", "connecting", "connected", "closed: <reason>", "error: <reason>") report its state
    NetServer()many framed TCP clients on one port: listen(port), send(id, bytes), broadcast(bytes) (the count of clients it reached), pump(), kick(id), client_count(), listening(), close(). Client ids count up from 1 and are never reused by one server
    net_host_name() -> string, net_local_addresses() -> array<string>this machine's name and its IPv4 addresses, loopback left out: what a player hosting a game tells the others to type

    A packet is one send's bytes, delivered whole and in order: on the wire each packet is a 4-byte big-endian length, then the bytes. Neither class runs a thread. The sockets do not block, and the signals fire only inside pump(), on the script's own call stack, so a game calls pump() once a frame.

    • A NetChannel fires on_connect(), on_packet(bytes) and on_disconnect(reason).
    • A NetServer fires on_client_connect(id), on_client_packet(id, bytes) and on_client_disconnect(id, reason).
    • A disconnect's reason is "closed by peer", "recv error", "send error", "oversized frame" (a length over 64 MiB) or, for a server's client, "kicked".
    • Packets that arrived ahead of a close are delivered before its disconnect.

    NetChannel.connect is asynchronous. It returns false only when the attempt fails at once (the host name does not resolve, the socket cannot be made), with the reason in status(). Otherwise it returns true while the connection is still being made, and the outcome arrives later through pump(): on_connect() when the peer accepts, on_disconnect("connect refused") when it does not. Packets sent before then wait in the queue and go out once the connection is made.

    Performance rules of thumb: Backends, Performance​

    rulewhy
    Reuse enginesengine creation dwarfs a small script's execution; a warm engine executes a cached script orders of magnitude faster than it can be created
    Prefer jaibite for anything run more than onceparse once, execute many. The handle skips the parse entirely (the VM also caches the compiled chunk)
    Repeated execute(string) is already cheapan LRU source cache (64 entries) means identical strings skip the parse
    The VM backend is the fast one for hot loopsloops fuse into superinstructions; the interpreter remains the reference for debugging
    Pass heavy things by &, declare hot containers with an element typea by-value copy of a big structure deep-copies it; array<int> / array<float> are raw buffers and skip the per-element boxing

    Every cost claimed above is quantified. One page, one machine, one protocol: Performance.
