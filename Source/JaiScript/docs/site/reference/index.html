    Reference​

    The lookup page. The guide teaches the language and the embedding chapters teach the host API; this page is where you come back to when you already know the shape of a thing and need the exact rule, the exact spelling, or the exact error text. The tables point back at the chapters that show each rule running, and the Documents section at the end indexes the specification files themselves.

    Two conventions, used everywhere below. A handle is a shared_ptr<T>; a reference is a T&. And the checker means the static checker that runs before any script executes. It is on, in strict mode, unless the host turns it down.

    Operators​

    From Operators & Arithmetic:

    CategoryOperatorsNotes

    Overflowing + - *, unary -, and INT64_MIN / -1 raise a catchable runtime error in the default build (JAISCRIPT_CHECKED_OVERFLOW). Integer arithmetic is never undefined behavior. Integer and float division by zero raise a catchable error (no IEEE infinity). When you want wraparound on purpose, math::wrap_add / wrap_sub / wrap_mul say so.

    char operands promote to int (unsigned, 0..255) under arithmetic, bitwise, and comparison operators: 'a' == 97 is true, 'z' - 'a' is 25, and s[i] > 127 is an unsigned high-bit test (byte 0xC3 is 195, never -61). There is no implicit int→char: type_of('a' + 1) is "int". A char converts only through an explicit cast: cast<char>(n) (range-checked 0..255), cast<int>(c), cast<string>(c), cast<char>("a"), or through the stdlib function form to_char(n), or a \xNN literal.

    Overloading on script classes. A class declares C++'s overloadable set less && || , -> new delete and !: binary + - * / % & | ^ << >> < > <= >= == != <=>, unary - + ~ (told apart from the binary form by the parameter count), =, [] and (), each as a method (Vec operator+(Vec o)). An operator runs only when its (left) operand is an instance whose class chain declares it; every other operand keeps the builtin meaning. a op= b is a = a op b through operator op (there is no operator op=); != without an operator!= negates operator==; relational operators use <=> when the class does not declare the requested operator. Truthiness is bool to_bool(): if (v) calls it and !v negates it, and declaring operator! is the parse error operator! cannot be declared: !v is !to_bool(v); declare bool to_bool(). operator() makes an instance callable (v(1, 2)); the checker still holds a function slot to functions and null, so a callable instance goes in wrapped in a lambda. Chapter: Operators & Arithmetic.

    Type conversions​

    An example before the table. Every one of these is the same rule applied to a different slot:

    jaiscript
    class Meters { float v = 0; Meters(float x) { v = x; } }
class Reading { int raw = 0; Reading(int r) { raw = r; } int to_int() { return raw * 10; } }
Meters m = 3;              // one-step converting constructor
int n = Reading(4);        // to_int() on the way into an int slot
float f = 7;               // widens
int t = 3.99;              // truncates toward zero
bool b = 5;                // truthiness
string s = 42;             // anything -> string
print("{} {} {} {} {} {}", m.v, n, f, t, b, s);
var nul = null;
Meters typed_null = nul;   // null is a typed null in any object slot
print("{}", typed_null == null);
    output
    3.0 40 7.0 3 true 42
true

    (A float prints as the shortest text that reads back to the same value, keeping .0 on a whole number; template strings and {} placeholders take format specs: ${f:.1f}.)

    One table. The same conversion rules govern declarations (int x = e), assignment (x = e), by-value parameters, return values, instance and static field stores, and the element boundary of typed arrays and maps. A conversion is always one step: a converting constructor or a to_X() method runs, but never chains (X.to_int() followed by C(int) is not implicit).

    When a mismatch is caught. If both sides are visibly typed (int x = "s", a string returned from a function declared -> int, an unrelated class into a typed field), the checker reports it and the load fails before a single statement runs. If the value came through var (or any other slot the checker treats leniently), the same rule runs at run time and raises a catchable error with the texts in Diagnostics. Both cases are the same table; only the moment differs.

    Compound assignment. On a typed (or locked-auto) target, a op= b computes like C++ and converts the result back to the target's type (int i = 7; i /= 2 → 3; i += 0.5 → 7; i += "s" is an error). On a var target the stored value is whatever the operation produces. A compound on a missing map key starts from the value type's default (map<string, int> m; m["x"] += 5 stores 5). The value of an assignment expression is what the destination stored (auto r = (i = 3.9) is int 3).

    The typed boundary and the escape hatches​

    Three spellings let you say, precisely, where you are stepping outside what the checker can see. None of them loosens anything else.

    cast<T>(e), cast<T&>(e), cast<shared_ptr<T>>(e)​

    jaiscript
    class Base { int b = 1; }
class Derived : Base { int t = 0; }
class Holder { Base p = Derived(); }     // a Derived, held through a Base-typed field

print("{} {} {}", cast<int>('a'), cast<char>(97), cast<string>('z'));
char c = cast<char>(65);                 // `char c = 65;` would be a load error

auto h = Holder();
cast<Derived&>(h.p).t = 5;               // alias the same object: the store lands
print("{} {}", c, cast<Derived&>(h.p).t);

shared_ptr<Derived> sp = new Derived();
shared_ptr<Base> sb = cast<shared_ptr<Base>>(sp);   // share it, don't copy it
sb.b = 42;
print("{}", sp.b);

var v = Base();
try { Derived d = cast<Derived>(v); } catch (e) { print("caught: {}", e); }
    output
    97 a z
A 5
42
caught: Cannot cast 'Base' to 'Derived'
    FormYieldsNotes
    cast<T>(e)what T tmp = e; would holda class target is a value copy when e's class is T or derives from it (the copy keeps e's class); primitives take the conversion table above (cast<int>(2.7) is 2). Casting a handle or a reference this way copies the instance. The checker warns and suggests the other two forms
    cast<T&>(e)a reference to the same objectmember reads and stores go through. This is the fix under strict checking when a subtype's member is reached through a base-typed receiver: cast<Derived&>(h.p).t = 5. The cast itself is an lvalue whose declared type governs the store: cast<int&>(x) += 2.5 leaves an int in x, even when x is a var
    cast<shared_ptr<T>>(e)a handle sharing the instancean upcast of a handle without a copy
    cast<int>(c) / cast<float>(c)the code point, 0..255the char↔int door, one direction
    cast<string>(c)the one-character string
    cast<char>(e)a charfrom an int in 0..255 or a string of exactly one character; anything else raises Cannot cast 'int' to 'char' / Cannot cast 'string' to 'char'

    The operand is never checked against T statically. That is the point of a cast. A class mismatch raises the catchable Cannot cast 'X' to 'T' where X is the object's run-time class; null passes the value and handle forms (you get a typed null) and fails the reference form (Cannot cast 'null' to 'T&'). A T that names no class is a load error. Chapter: The Type Ladder.

    extern​

    extern declares a name that exists outside the program (a host global bound after load, a function the running instance registers, a value another engine injects) so that the checker counts it as declared instead of reporting use of undeclared identifier. At run time it declares nothing: the name resolves when it is used, and a use while nothing defines it raises 'name' is declared extern but never defined (an 'inline' declaration creates it) (extern function: without the parenthesis). inline T name; is the C++17 inline variable: one variable shared by every unit that declares it, created with its initializer or its type's default by the first to run and adopted by the rest (a later unit's initializer does not run again). Inline and plain declarations of one name never mix: a plain declaration of an inline variable raises 'x' is already defined inline; declare it 'inline int x;' to share it, and an inline declaration of another unit's plain variable raises 'x' is already defined (not inline) in <file>; declare every definition 'inline' to share it. When the checker sees both units it reports the plain declaration at load, with the first text.

    using ns::name; (a comma list: using game::spawn, game::cost;) makes the rest of the file read name as ns::name, for any namespace. It is a parse-time rewrite: file-local, not transitive through imports or includes, and the name cannot be declared again in that file. There is no using namespace.

    SpellingMeaning to the checker
    extern function log_to_host;a callable of unknown signature: calls are unchecked
    extern int frame; / extern shared_ptr<Game> G;typed: member access, assignments and conversions are checked exactly as for a declared variable of that type
    extern config;untyped: behaves like var

    An extern name travels with the program: every unit the root imports sees it. It is also the idiom for a shared leaf that reaches into a module only some programs import. In a program that does import the module, the declaration is inert and the real definition wins.

    [[warn_mode]] and [[strict_mode]]​

    jaiscript
    extern function log_to_host;   // the host registers this later: calls are unchecked
extern int frame;              // typed: reads and stores are checked as an int
extern config;                 // untyped: behaves like var

int total = 0;
try {
    [[warn_mode]] total = "oops";        // this one statement is only warned about...
} catch (e) {
    print("run time: {}", e);            // ...so the mistake surfaces here instead
}
print("{}", total);
    output
    run time: Cannot assign string to 'total' (declared int)
0

    The two attributes set the checker's mode for a region of one file. They compose, the innermost wins, and the engine's mode is the default everywhere else. Where the attribute sits decides what it covers:

    PositionCovers
    first declaration of a file ([[warn_mode]]; at the top; a leading comment is fine)the whole unit
    first statement of a block (a function, method or lambda body, an if/while/for body, a bare { })the whole block, nested bodies included
    before any other statementthat one statement's own subtree; a nested function or lambda body inside it keeps the enclosing mode

    In a warn region every error is reported as a warning (still collected, still visible through engine->check()) and an undeclared identifier is accepted as unknown; nothing is proven from it. In a strict region errors gate the load, even inside a warn-mode engine. Under engine mode off the attributes do nothing. The runtime never changes: both backends treat the attribute as nothing, so a warn region's type mistakes raise at run time exactly as they would have without a checker, which is what the example shows. A unit's mode says nothing about the units it imports. warn_mode and strict_mode are the only attribute names; anything else is a parse error.

    Language rules in one place​

    The contractual one-liners: the things both backends are tested to agree on, byte for byte.

    RuleWhere to read more
    Checking is strict by default. A typed-to-typed mismatch or an undeclared identifier fails the load; warn and off are the opt-downs, per engine (static_checking) or per region ([[warn_mode]]). Only a var-sourced value can still fail at run time, where try/catch sees it.Static Checking
    One conversion table for declarations, =, by-value parameters, returns, instance and static field stores and container elements; one step, never chained.above
    Program closure. A file whose import/include paths are literals is the root of a program: every unit those paths reach is gathered and checked before anything runs, names and class models cross units, and import order does not matter for names. A dynamic-path import(expr) keeps undeclared identifiers at warning severity in that unit.Modules
    Evaluation order is contractual: the callee is resolved before any argument is evaluated, and arguments go left to right, each taking its value when it is evaluated. (pick()(arg("left", 1), arg("right", 2)) records callee left right on both backends.) An assignment t = e or t op= e evaluates e before every part of the target (a member's receiver, a subscript's container and index): C++17.Functions
    Captures are exhaustive. [] captures nothing and [x] only x; using an unlisted local of the enclosing function is the parse error Lambda capture list does not capture enclosing local 'n'; name it or use [=] or [&]. [=]/[x] copy at creation, [&]/[&x] share the variable (and outlive its frame), [x = e] initializes the lambda's own x, [this] captures the instance. A program-scope name is never captured by default: the lambda reads it when it runs. An anonymous function(...) expression is the JavaScript closure: it captures as [&].Functions
    Methods are called or bound. obj.heal without a call is an error ('heal' is a method of Player; call it with player.heal() or bind it with reflect::bind(player, "heal")), at load when the checker knows the receiver. reflect::bind(obj, "name") is the method as a callable that holds the object. A builtin method read without a call raises the same way ('push' is a method of array; call it with arr.push() or wrap the call in a lambda).Classes
    Typed returns are required. Under strict checking a function declared to return a primitive, a string or a reference must return on every path: 'f' declared to return 'int' may reach the end of its body without returning.Strict checking
    Declarations without an initializer take their type's default: a class default-constructs, int 0, float 0.0, bool false, string "", containers empty, a math vector zero; var stays null. A class that declares no constructor takes aggregate initialization: Pt p{1, 2}, Pt{1, 2}, Pt(1, 2) fill the instance fields in declaration order (bases first), the rest keep their initializers.Classes
    Access control is two levels. public: for everyone; private: (and its synonym protected:) for the declaring class and every class derived from it. Members start public. Outside that family: Cannot access private member 'x' of class 'C'.Classes
    == is memberwise on heavy values. Arrays elementwise, maps entrywise, instances of one class fieldwise (a user operator== first); handles compare by pointer; same_object(x, y) is identity. contains, index_of, has and switch cases use the same ==.Operators
    A return conversion is part of the return statement. It fails inside the callee, at the return's line, with the callee as the top frame; a try around the return catches it there, and uncaught it surfaces in the caller.Return-type rules
    Static fields enforce their declared type and are spelled Class::name (bare name inside the class's own methods). Class.name is not a spelling. Statics are inherited names, as in C++: a subclass sees its bases' statics bare and Derived::name names them.Statics
    User accessors win. If a class (or an ancestor) declares _get_x / _set_x, obj.x reads and writes through them instead of the synthesized accessors; a bare x inside the class's methods is the backing field, so an accessor can read its own field without recursing.Name resolution
    Coroutine spellings. coroutine prefixes every function form: coroutine int g(), coroutine g() -> int, coroutine function g() -> auto, coroutine function g(), and bare coroutine g(), at top level and as methods (static ones too). Not inside namespaces; there are no coroutine lambdas.Coroutines
    C++ property references bind the member. Passing a bound property (f(this.value), f(obj.value)) to a & parameter reads and writes through the host getter and setter, like any field lvalue.Value Semantics
    Value semantics; references by declaration. Assignment, parameters and returns copy. & parameters, auto&, for (auto& x : ...) and shared_ptr<T> (new T(...) is sugar for it) are the spelled-out ways to alias.Value Semantics
    Integers are checked, shifts wrap. + - * and unary - raise on overflow; << discards high bits by contract; math::wrap_* is explicit wraparound arithmetic.Operators
    Shadowing is legal and warned about. A local shadowing a field or an outer local is a warning whenever the checker runs (strict or warn); warnings never gate.Functions
    switch breaks by default; write fallthrough; to fall through. do { } while (c); is C++'s: continue reaches the condition.Control Flow
    let is var, and words from other languages (const, virtual, delete, goto, extends, ===, function*, &x, a typed catch) are parse errors that name the JaiScript spelling.Language Bridges
    Reading a missing map key returns null and does not insert; m[k] = v inserts; get(k, default) is the explicit fallback.Maps
    String mutators mutate the receiver (to_upper, trim, …) and return it for chaining; + never mutates.Strings
    Budget and memory cap are terminal. The execution budget cannot be caught by script; the memory cap gives one catchable raise, then goes terminal.Safety Rails
    The .jaibite format is at version 35. The automatic disk cache silently reparses a sibling of another version or of another source text; an explicit jaibite_load of another version fails with jaibite: unsupported format version 26 (expected 34). Proofs are never serialized and are re-derived on load.jaibite

    Diagnostics as you read them​

    There are two shapes of error, and knowing which one you are looking at tells you when it happened.

    The static listing (before anything runs)​

    jaiscript
    int x = 5;
x = "hello";                  // typed to typed: the load fails, nothing runs
print("never printed");
    output
    jaiscript: static check failed:
<script>:2:4: error: cannot assign 'string' to 'x' declared 'int' (declared at 1:5)
    x = "hello";                  // typed to typed: the load fails, nothing runs
       ^

    The shape is FILE:LINE:COL: error: MESSAGE, then the source line, then a caret. FILE is the unit's resolved path for a file (the root file, an import, an include) and <script> for source text handed to execute(). The message is lowercase and names the declaration it conflicts with. Under strict mode the host sees one jai::static_check_error whose what() is the whole listing (sorted by location, deduplicated, capped at 100), and nothing has executed. Warnings (shadowing, a copying cast) use the same shape with warning: and never stop the load. The runner lists them under --check=warn, and a host reads them from last_check_diagnostics() in strict or warn mode (off collects nothing). Common messages:

    MessageMeaning
    cannot assign 'string' to 'x' declared 'int' (declared at 8:3)a typed store the table rejects
    cannot initialize 'c' declared 'char' with 'int'the same at a declaration (char c = 65)
    use of undeclared identifier 'G'no declaration anywhere in the program; extern if the host provides it
    no member 'zz' in class 'Vec2'the receiver's class is fully known and has no such field or method: cast<T&> if it lives on a subtype
    'fib' expects 1 argument(s), got 2 / argument 1 of 'fib': cannot pass 'string' to 'n' declared 'int'arity and per-argument checks against a callee the checker can see

    Run-time errors (what catch sees)​

    jaiscript
    var dynamic = "hello";        // var: the checker cannot see what it holds
try {
    int x = dynamic;          // so this fails at run time, where catch sees it
} catch (e) {
    print("caught: {}", e);
}
    output
    caught: Cannot initialize 'x' (declared int) with string

    pop on an empty array raises a catchable error. filter takes a one-arg lambda and returns a new array; remove_if mutates. The callback helpers pass the element, or the element and its index to a two-parameter callback; a T& element parameter is the element itself. map returns an array<T> when its callback declares T; find returns a copy or null, find_index an index or -1; reduce(f) without an initial value raises on an empty array; insert(i, v) takes i from 0 to size(). A typed array (array<int>) checks every store against its element type; array<var>, and a literal with no spelled element type, holds anything.

    Maps (14)​

    kindmethods
    observerssize empty contains has get keys values length to_array
    return a new mapfilter (predicate takes (key, value))
    mutate in placeclear erase remove remove_if

    Writing m[key] = v inserts; reading a missing key returns null and does NOT insert. get(key) returns null for a missing key; get(key, default) supplies an explicit fallback. Keys are ordered; any script value can be a key (the total ordering of <=> guarantees it). A declared key type is enforced on stores (map<string,int> m; m[5] = 1 raises); keys never coerce.

    Strings (37 core)​

    s[i] indexes bytes and returns a char, which promotes to an unsigned int (0..255) in numeric contexts, so s[i] + 0 reads a byte value, s[i] - '0' is the digit-parse shape, and s[i] == 0x1A is a byte test. s.at(i) returns a one-character string instead. s[i] = c replaces byte i and s[i] = text replaces it with the whole text (s[i] += text reads, concatenates and writes back); on a utf8_string, u[i] reads and replaces character i. Bytes are minted with cast<char>(n) or to_char(n) (both range-checked 0..255; out += cast<char>(b) is the binary-writer shape) and with \xNN escapes (exactly two hex digits; "\x00" embeds a real NUL). find returns -1 when absent; split() with no argument splits on whitespace and drops empty pieces (split(string::whitespace) is the same); split(sep) keeps empties; split("") splits into characters; explode is its synonym.

    kindmethods
    observers (leave the string alone)length size empty at front back substr find rfind find_first_of find_last_of find_first_not_of find_last_not_of contains starts_with ends_with count to_int to_float split
    in-place mutators (modify the receiver, return self for chaining)to_lower to_upper trim trim_left trim_right pad_left pad_right pad_center replace_first replace_last replace_all insert erase remove_prefix remove_suffix reverse repeat

    The mutator camp is the surprise: auto upper = name.to_upper(); also uppercases name itself. This is deliberate: returning the receiver makes chained pipelines like s.trim().to_lower() allocation-free, and value semantics keeps the mutation local to that one variable. Copy first if you need the original, or build new strings with + (which never mutates), or call the string:: function of the same name (string::to_upper(s) returns a new string).

    The standard library adds text helpers on top of the core table: lines partition compare code explode byte_size utf8_length utf8_chars is_valid_utf8 to_utf8 (a utf8_string), and the binary doors to_bytes([offset], [count]) (an array<uint8>) and reader() (a binary::reader). A utf8_string answers the same method names in characters.

    include vs import​

    From Modules:

    include "f.jai"import "f.jai"
    Runsevery time it is evaluatedwhen first reached, then again when its file changed (checked in passes: import_recheck_interval, default 0.2 s)
    Scopeexecutes in the current scopemodule declaration
    Expression?yes: var cfg = include "config.jai"; evaluates to the file's last expressionthe statement form never (auto x = import ... is a parse error); the call form import("f.jai") is a bool: true when a module ran
    Dynamic pathsyes: include(expr)yes: import(expr)
    Checked how?a literal path joins the program closure: its names and classes are known to every unit and checked before anything runs; a dynamic path cannot be gathered, so that unit's undeclared identifiers drop to warnings
    Idiomforcing a re-run: hot reload of rules/content mid-gamedeclaring your module graph at the top of each file

    #include "x.jai" is accepted (the # is ignored for C++ muscle memory). Persistent state goes in a module you only import and never include, so a reload can't wipe it.

    Every file-based load also maintains a sibling jaibite disk cache (foo.jai → foo.jaibite): a sibling recording the exact source text (size + hash) and a matching registration fingerprint loads instead of parsing; any other text reparses and refreshes the sibling, whatever its mtime. Parse-level and side-effect-free: it never changes whether a file runs. Silent on write failure; eng->jaibite_cache(false) disables.

    Import modes (engine::import_behavior)​

    ModeBehavior
    file_timestamp (default)Re-runs a module when its file's (modification time, size) stamp or a file its last run included changed, checked in engine-wide passes at most once per import_recheck_interval (0.2 s by default; 0 checks on every reach). A module whose file disappears raises Failed to open import file once, then waits until the file is back. The hot-reload-friendly default
    onceImport exactly once; ignore later file changes
    alwaysTreat import as include (runs every time)

    Command-line runner​

    jaiscript is the reference embedding and the quickest way to run anything on this site.     Performance rules of thumb: Backends, Performance​

    rulewhy
    Reuse enginesengine creation dwarfs a small script's execution; a warm engine executes a cached script orders of magnitude faster than it can be created
    Prefer jaibite for anything run more than onceparse once, execute many. The handle skips the parse entirely (the VM also caches the compiled chunk)
    Repeated execute(string) is already cheapan LRU source cache (64 entries) means identical strings skip the parse
    The VM backend is the fast one for hot loopsloops fuse into superinstructions; the interpreter remains the reference for debugging
    Pass heavy things by &, declare hot containers with an element typea by-value copy of a big structure deep-copies it; array<int> / array<float> are raw buffers and skip the per-element boxing
