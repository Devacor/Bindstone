From Operators & Arithmetic:

Overflowing + - *, unary -, and INT64_MIN / -1 raise a catchable runtime error in the default build (JAISCRIPT_CHECKED_OVERFLOW) — integer arithmetic is never undefined behavior. Integer and float division by zero raise a catchable error (no IEEE infinity).

char operands promote to int — unsigned, 0..255 — under arithmetic, bitwise, and comparison operators: 'a' == 97 is true, 'z' - 'a' is 25, and s[i] > 127 is an unsigned high-bit test (byte 0xC3 is 195, never -61). There is no implicit int→char: type_of('a' + 1) is "int"; mint bytes explicitly with to_char(n) or \xNN.

Type conversions (typed / locked-auto targets)​

From The Type Ladder — mirrors enforce_type_compatibility:

Target ← SourceResult
float ← intwidens (3 → 3.0)
int ← floattruncates toward zero (3.99 → 3, -3.99 → -3)
bool ← numerictruthiness (5 → true, 0 → false)
string ← int/float/...stringified (5 → "5")
int ← booltrue → 1, false → 0
int/float ← stringerror (no implicit parse; use "42".to_int())
class T ← same class or derivedallowed (upcast); parent → child, siblings, or same-shape unrelated classes are rejected
class T ← class with matching conversion ctor / assignment operatorconverts

On a typed (or locked-auto) target, a op= b computes like C++ and converts the result back to the target's type (int i = 7; i /= 2 → 3; i += 0.5 → 7). On a var target, the stored value is whatever the operation produces.

Writing m[key] = v inserts; reading a missing key returns null and does NOT insert. get(key, default) is the explicit fallback form. Keys are ordered; any script value can be a key (the total ordering of <=> guarantees it).

Strings (37)​

s[i] indexes bytes and returns a char, which promotes to an unsigned int (0..255) in numeric contexts — so s[i] + 0 reads a byte value, s[i] - '0' is the digit-parse shape, and s[i] == 0x1A is a byte test. s.at(i) returns a one-character string instead. Bytes are minted with to_char(n) (range-checked 0..255; out += to_char(b) is the binary-writer shape) and \xNN escapes (exactly two hex digits — "\x00" embeds a real NUL). find returns -1 when absent; split() with no argument splits into individual characters.

kindmethods
observers (leave the string alone)length size empty at front back substr find rfind find_first_of find_last_of find_first_not_of find_last_not_of contains starts_with ends_with count to_int to_float split
in-place mutators (modify the receiver, return self for chaining)to_lower to_upper trim trim_left trim_right pad_left pad_right pad_center replace_first replace_last replace_all insert erase remove_prefix remove_suffix reverse repeat

The mutator camp is the surprise: auto upper = name.to_upper(); also uppercases name itself. This is deliberate — returning the receiver makes chained pipelines like s.trim().to_lower() allocation-free, and value semantics keeps the mutation local to that one variable. Copy first if you need the original, or build new strings with + (which never mutates).

include vs import​

From Modules:

include "f.jai"import "f.jai"
Runsevery time it is evaluatedat most once per engine (mode-dependent)
Scopeexecutes in the current scopemodule declaration
Expression?yes — var cfg = include "config.jai"; evaluates to the file's last expressionnever — auto x = import ... is a parse error
Dynamic pathsyes: include(expr)yes: import(expr)
Idiomforcing a re-run: hot reload of rules/content mid-gamedeclaring your module graph at the top of each file

#include "x.jai" is accepted (the # is ignored for C++ muscle memory). Persistent state goes in a module you only import and never include, so a reload can't wipe it.

Every file-based load also maintains a sibling jaibite disk cache (foo.jai → foo.jaibite): strictly newer by mtime + matching registration fingerprint loads instead of parsing; an edited source is always newer, so it reparses and refreshes the sibling. Parse-level and side-effect-free — it never changes whether a file runs. Silent on write failure; eng->jaibite_cache(false) disables.
