    Library Reference​

    Full API signatures: arguments, defaults, results, effects, and availability for builtins, standard-library functions, and the standalone runner.

    Builtin methods​

    From Containers & Strings. One registry serves both backends, so the lists below are the same on each.

    Arrays (31)​

    a.filter(f) keeps the elements f accepts in a itself and returns nothing, so auto b = a.filter(f); is an error (the text). remove_if drops the ones its predicate accepts. The copying forms are the array:: functions: array::slice, array::filter, array::map, array::concat, array::append, array::sort and array::reverse return a new array and leave their argument alone.

    • pop on an empty array raises a catchable error.
    • The callback helpers pass the element, or the element and its index to a two-parameter callback. A T& element parameter is the element itself.
    • a.map(f) keeps a's element type (results convert into it). array::map returns an array<T> when its callback declares T.
    • find returns a copy or null, find_index an index or -1.
    • reduce(f) without an initial value raises on an empty array.
    • insert(i, v) takes i from 0 to size().
    • A typed array (array<int>) checks every store against its element type. array<var>, and a literal with no spelled element type, holds anything.

    Maps (14)​

    kindmethods
    observerssize empty contains has get keys values length to_array
    change in place, return nothingclear filter (predicate takes (key, value); keeps the accepted entries, while map::filter(m, f) returns a new map)
    change in place, return what they tookerase remove (whether the key was there) remove_if (the count)

    Writing m[key] = v inserts or overwrites. Reading a missing key raises (Key "k" not found in map) and never inserts, on every map: a plain read, a compound or increment, a reference bound to the entry. contains(key) asks; get(key) returns null for a missing key; get(key, default) supplies an explicit fallback. Keys are ordered; any script value can be a key (the total ordering of <=> guarantees it). A declared key type is enforced on stores (map<string,int> m; m[5] = 1 raises); keys never coerce.

    Strings (38 core)​

    s[i] indexes bytes and returns a char, which promotes to an unsigned int (0..255) in numeric contexts. So s[i] + 0 reads a byte value, s[i] - '0' is the digit-parse shape, and s[i] == 0x1A is a byte test.

    • s.at(i) returns the same char, a negative i counting from the end. On a utf8_string, u.at(i) returns character i as text.
    • s[i] = c replaces byte i and s[i] = text replaces it with the whole text (s[i] += text joins the char with the text, then stores it).
    • A char beside a string compares and joins as its one-character text (s[i] == "x", s + 'c').
    • On a utf8_string, u[i] reads and replaces character i.
    • Bytes are minted with cast<char>(n) or to_char(n) (both range-checked 0..255; out += cast<char>(b) is the binary-writer shape). They are also minted with \xNN escapes in a quoted or backtick string (exactly two hex digits; "\x00" embeds a real NUL).
    • A raw string is R"(text)" or R"delim(text)delim" (a delimiter of up to 16 characters, none a space, parenthesis, backslash or quote). It holds its text with no escapes, a line ending inside as one \n.
    • find returns -1 when absent.
    • split() with no argument splits on whitespace and drops empty pieces (split(string::whitespace) is the same). split(sep) keeps empties; split("") splits into characters; explode is its synonym.

    A mutator returns nothing, so its result cannot be used: auto upper = name.to_upper(); and the chain s.trim().to_lower() are errors (the text). Call each mutator as a statement, build new strings with + (which never mutates), or call the string:: function of the same name (string::to_upper(s) returns a new string; the pairs).

    Every engine also has text helpers beyond the core table: lines partition compare code explode byte_size utf8_length utf8_chars is_valid_utf8 is_digit is_alpha is_alnum is_space is_upper is_lower to_utf8 (a utf8_string), and the binary doors to_bytes([offset], [count]) (an array<uint8>) and reader() (a binary::reader). A utf8_string answers the same method names in characters, except to_utf8.

    What a bare engine has. jai::engine::make() alone runs the whole language with these builtins:

    • a print that concatenates its arguments, and template strings with format specs (format_value)
    • the builtin container and string methods and their array:: forms
    • math:: (functions, vectors, colors, wrap_*), regex, and binary:: readers and writers with string::from_bytes
    • same_object, extend, thread_count, parallel_transform and parallel_reduce, sleep
    • the location builtins (executable_dir, file_data, resolve_path and the rest)

    jai::stdlib::register_all adds the formatted print, format, to_string, type_of, JSON and binary serialization, the string:: functions, to_char, random, time::, crypto:: and reflect::. web:: and spider:: are separate opt-ins.
