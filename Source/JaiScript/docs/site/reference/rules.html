    Language Rules​

    Operators​

    From Operators & Arithmetic:

    CategoryOperatorsNotes
    Arithmetic+ - * / %int op int stays int (7 / 2 → 3); any float operand promotes. + on a string joins text, and a char beside it joins as its character. A number, bool or null beside a string is an error (to_string(x) or `${x}` makes it text)
    Unary+ - ! ~ ++ --+ is the identity on a number, a char (promoted to its int) and a math value (a copy). - also negates a math value. ~ takes an int only; ++/-- in prefix and postfix form, on every lvalue (elements, map entries, members)
    Assignment= += -= *= /= %= &= |= ^= <<= >>=typed targets convert C++-style; x op= y is x = x op y with x evaluated once, and the right side runs before any part of the target. Every C++ lvalue is a target: a call returning T&, a conditional of lvalues, (a = b) = c, ++x = v, cast<T&>(e)
    Comparison== != < > <= >= <=><=> returns -1 / 0 / 1; 1 == 1.0 is true. A char beside a string compares as its one-character string (s[i] == "x"). Ordinary numeric comparisons with NaN follow IEEE (false and unequal). <=> groups all NaNs last and treats signed zeros as equivalent
    Logical&& || !short-circuit; !v on a class instance is !to_bool(v) (an instance whose class declares no bool to_bool() is true)
    Bitwise& | ^ ~ << >>on integers; shifts operate on the 64-bit pattern (<< discards high bits by contract, >> is arithmetic), and the count must be 0..63
    Null?? ??=a ?? b: a unless null, else b (evaluated only then); a ??= b stores only into a null a
    Ternary?:right-associative
    Function(params) => expr (params) => { ... } x => expran arrow function: a function expression that closes over its scope by reference, like function(...)
    Castcast<T>(e) cast<T&>(e) cast<shared_ptr<T>>(e)cast is a keyword. See the typed boundary
    Member/index. [] ?. ::?. is null-safe: a null in front of it skips the rest of the chain. a?.b.c is null when a is, and still raises when b is null: write a?.b?.c. :: reaches statics and namespaces (Class::name is the only static spelling; Class.name is not one)

    Overflowing + - *, unary -, and INT64_MIN / -1 raise a catchable runtime error in the default build (JAISCRIPT_CHECKED_OVERFLOW). Integer arithmetic is never undefined behavior. Integer / and % by zero raise a catchable error; with a float operand they are IEEE (an infinity or NaN). When you want wraparound on purpose, math::wrap_add / wrap_sub / wrap_mul say so.

    char operands promote to int (unsigned, 0..255) under arithmetic, bitwise, and comparison operators. 'a' == 97 is true, 'z' - 'a' is 25, and s[i] > 127 is an unsigned high-bit test (byte 0xC3 is 195, never -61). There is no implicit int→char: type_of('a' + 1) is "int". A char converts only through an explicit cast: cast<char>(n) (range-checked 0..255), cast<int>(c), cast<string>(c), cast<char>("a"), or through the stdlib function form to_char(n), or a \xNN literal.

    Overloading on script classes. A class declares an operator as a method (Vec operator+(Vec o)). An operator runs only when its (left) operand is an instance whose class chain declares it; every other operand keeps the builtin meaning. Chapter: Operators & Arithmetic.

    • The declarable set is C++'s overloadable set less && || , -> new delete and !. That is binary + - * / % & | ^ << >> < > <= >= == != <=>, unary - + ~ (told apart from the binary form by the parameter count), =, [] and (), each as a method.
    • a op= b is a = a op b through operator op (there is no operator op=).
    • = into an existing object (a slot declared the class, a var) runs operator= when an overload takes the value, else the implicit memberwise copy. Initialization copy-constructs.
    • != without an operator!= negates operator==. Relational operators use <=> when the class does not declare the requested operator.
    • Truthiness is bool to_bool(): if (v) calls it and !v negates it. Declaring operator! is the parse error operator! cannot be declared: !v is !to_bool(v); declare bool to_bool().
    • operator() makes an instance callable (v(1, 2)). The checker still holds a function slot to functions and null, so a callable instance goes in wrapped in a lambda.

    Keywords​

    The reserved words. None of them names a variable, a parameter, a program-scope function or a class; a qualifier or a member declaration makes one a name (keyword member names):

    WordIntroduces
    int float bool char string voidthe scalar types and the no-result return type
    var let autoa dynamic variable (let is a synonym of var); a variable that takes its initializer's static type (The Type Ladder)
    array map shared_ptr weak_ptrthe container and handle types, written with their arguments: array<int>, map<string, int>, shared_ptr<T>
    functiona function declaration (function f(a) { ... }), an anonymous function expression (a [&] lambda), and the callable-or-null slot type (function cb = null;)
    consta variable, parameter or field set once and then only read (const)
    class nocopya class; nocopy class C is one whose instances cannot be copied
    public private protectedaccess labels in a class body; protected is a synonym of private, which admits the class and its subclasses
    static overridea member of the class rather than of an instance (C::s); a method that replaces a base class's method
    this superthe receiver inside a method; the base class (: super(args) in a constructor's initializer list, super::m() in a method)
    newnew T(args): one shared object, a shared_ptr<T>; make_shared<T>(args) is the same expression
    enum namespacea scoped enumeration (E::v); a named scope (ns::x) (Kitchen Sink)
    if else while for break continue returncontrol flow; for is the C-style loop and the range form for (auto x : xs)
    switch case default fallthrougha switch; a case breaks by default, fallthrough; continues into the next one, and a case with no statements shares the next label's body
    try catch throwexceptions: catch (Type e) clauses in order, then catch (e) for everything; e is the thrown value and error names a run-time error (Control Flow)
    coroutine yielda coroutine declaration (coroutine prefixes any function spelling); a value handed out by it (Coroutines)
    parallel_fora data-parallel loop (Parallel loops)
    castcast<T>(e), cast<T&>(e), cast<shared_ptr<T>>(e) (below)
    include importtextual inclusion of a file; a module, its own unit (Modules). #include "x" is include "x" (and #import is import): a # begins nothing else, but a #! shebang on the first line
    extern inlinea name defined outside the program; a program-scope variable every declaring unit shares (below)
    true false null nullptrthe literals; nullptr is a synonym of null

    Words with a meaning only in one position, and names everywhere else:

    • operator (an operator declared in a class, operator+)
    • using (using ns::name; at the start of a statement)
    • do (do { } while (c); when a { follows)
    • double (a synonym of float where a type is read)
    • utf8_string (the text type, where a type is read)
    • uint8 and int8 (an array's element type only)
    • the attributes [[warn_mode]] and [[strict_mode]]
    • hot_reload_migrate (reserved for the reload hook at a file's top level)

    Words from other languages (goto, virtual, delete, constexpr, ...) are not reserved. Where one would fail to parse, the error names the JaiScript spelling (the table below).

    Type conversions​

    An example before the table. Every one of these is the same rule applied to a different slot:

    jaiscript
    class Meters { float v = 0; Meters(float x) { v = x; } }
class Reading { int raw = 0; Reading(int r) { raw = r; } int to_int() { return raw * 10; } }
Meters m = 3;              // one-step converting constructor
int n = Reading(4);        // to_int() on the way into an int slot
float f = 7;               // widens
int t = cast<int>(3.99);   // a float enters an int only through cast
bool b = 5;                // truthiness
string s = to_string(42);  // text only: stringify explicitly
print("{} {} {} {} {} {}", m.v, n, f, t, b, s);
    output
    3.0 40 7.0 3 true 42

    (A float prints as the shortest text that reads back to the same value, keeping .0 on a whole number, with inf, -inf and nan for the values no digits spell (every NaN prints nan, a format spec included, whatever produced it). Template strings and {} placeholders take format specs: ${f:.1f}.)

    One table. The same conversion rules govern declarations (int x = e), assignment (x = e), by-value parameters, return values, instance and static field stores, and the element boundary of typed arrays and maps. A conversion is always one step: a converting constructor or a to_X() method runs, but never chains (X.to_int() followed by C(int) is not implicit).

    floatfloat; int (widens); bool; an object with to_float()
    boolbool, int, float, null, an objecttruthiness (5 → true, 0 → false). A string, an array or a map into a declared bool is a load error (!s.empty()); conditions keep truthiness for all of them
    enum Ea value of Estarts at its first value. An int or another enum's value is an error; cast<E>(n) converts an int that is one of its values, and an int out of a var enters when it is one. var v = E::a holds the int
    string / utf8_stringeither text kind (a utf8_string's bytes, a string's characters); a char (its one-character text); an object with to_string()int, float, bool, null and containers are errors (no implicit stringify): write to_string(x) or `${x}`, the display text of Printing values

    array<T> / map<K,V>an array / a mapelement and key types are checked on every store: by the checker where it sees both types (cannot push into 'array<int>': expected 'int', got 'string'), at run time otherwise (Cannot store string in array<int>, Cannot push 'string' to array<int>). Map keys never coerce numerically, and a char key and its one-character string are one key (stored as the declared key type)
    class Cthe same class; a derived class (upcast); a shared_ptr handle to C or a derived class. A parent, a sibling, or an unrelated class with the same shape is rejected; so are arrays, maps and functions.     shared_ptr<T>a handle to T or a subclass; a T value (construct-and-share); nullthe pointee is enforced: shared_ptr<Bar> p = Foo() is a load error when the checker sees both classes and Cannot initialize shared_ptr<Bar> with Foo: type must match or be a subclass at run time otherwise
    T& (a reference declaration or parameter)an lvalue that holds a T (a class: T or a subclass), a var included only while it holds one. A reference parameter its body never writes through also takes a literal or a temporary, and a string& parameter takes one as a writable temporaryno conversion: float& r = v with v holding an int raises Cannot initialize 'r' (declared float&) with int. A write-through parameter given a literal is the load error 'bump' writes through parameter 'x' (line 1); pass a variable. A store through a reference obeys the reference's declared type (var v = 0; int& r = v; r = 3.9 is a load error). Storage that has a declared type of its own keeps its rule (int x; var& w = x; w = 2.7 raises Cannot assign float to 'w' (declared int&))
    varanything, foreverthe opt-out: everything computed from a var is unknown to the checker and can only fail at run time
    auto with an initializerinferred from the initializer, then enforced as that typea null initializer carries no type, so the variable stays dynamic until its first non-null store
    auto without an initializerdynamic until the first assignment, then lockedthe checker cannot see branch order, so it stays silent here

    When a mismatch is caught. If both sides are visibly typed (int x = "s", a string returned from a function declared -> int, an unrelated class into a typed field), the checker reports it and the load fails before a single statement runs. If the value came through var (or any other slot the checker treats leniently), the same rule runs at run time and raises a catchable error with the texts in Diagnostics. Both cases are the same table; only the moment differs.

    Compound assignment. What a op= b stores depends on its target:

    • On a typed (or locked-auto) target, a op= b computes like C++ and converts the result back to the target's type (int i = 7; i /= 2 → 3; i += 0.5 and i += "s" are errors).
    • On a var target the stored value is whatever the operation produces.
    • A compound reads its target first, so on a missing map key it raises (map<string, int> m; m["x"] += 5 raises Key "x" not found in map).

    The value of an assignment expression is what the destination stored (float f; auto r = (f = 3) is float 3.0).

    The typed boundary and the escape hatches​

    Three spellings let you say, precisely, where you are stepping outside what the checker can see. None of them loosens anything else.

    cast<T>(e), cast<T&>(e), cast<shared_ptr<T>>(e)​

    jaiscript
    class Base { int b = 1; }
class Derived : Base { int t = 0; }
class Holder { Base p = Derived(); }     // a Derived, held through a Base-typed field

print("{} {} {}", cast<int>('a'), cast<char>(97), cast<string>('z'));
char c = cast<char>(65);                 // `char c = 65;` would be a load error

auto h = Holder();
cast<Derived&>(h.p).t = 5;               // alias the same object: the store lands
print("{} {}", c, cast<Derived&>(h.p).t);

shared_ptr<Derived> sp = new Derived();
shared_ptr<Base> sb = cast<shared_ptr<Base>>(sp);   // share it, don't copy it
sb.b = 42;
print("{}", sp.b);

var v = Base();
try { Derived d = cast<Derived>(v); } catch (e) { print("caught: {}", e); }
    output
    97 a z
A 5
42
caught: Cannot cast 'Base' to 'Derived'
    FormYieldsNotes
    cast<T>(e)what T tmp = e; would holda class target is a value copy when e's class is T or derives from it (the copy keeps e's class); primitives take the conversion table above, plus float to int truncating toward zero (cast<int>(2.7) is 2) and an int to the enum value it equals. Casting a handle or a reference this way copies the instance. The checker warns and suggests the other two forms
    cast<T&>(e)a reference to the same objectmember reads and stores go through. This is the fix under strict checking when a subtype's member is reached through a base-typed receiver: cast<Derived&>(h.p).t = 5. The cast itself is an lvalue whose declared type governs the store: cast<int&>(x) += 2 leaves an int in x, even when x is a var
    cast<shared_ptr<T>>(e)a handle sharing the instancean upcast of a handle without a copy
    cast<int>(c) / cast<float>(c)the code point, 0..255the char↔int door, one direction
    cast<string>(e)e's display text, as to_string(e) gives itthe explicit stringify a string slot does not make implicitly; a char is its one-character string
    cast<char>(e)a charfrom an int in 0..255 or a string of exactly one character; anything else raises Cannot cast 'int' to 'char' / Cannot cast 'string' to 'char'

    The operand is never checked against T statically. That is the point of a cast. A class mismatch raises the catchable Cannot cast 'X' to 'T' where X is the object's run-time class. null passes the handle form (an empty handle) and fails the value form (Cannot cast 'null' to 'T') and the reference form (Cannot cast 'null' to 'T&'). A T that names no class is a load error. Chapter: The Type Ladder.

    extern​

    extern declares a name that exists outside the program (a host global bound after load, a function the running instance registers, a value another engine injects). The checker then counts it as declared instead of reporting use of undeclared identifier. At run time it declares nothing: the name resolves when it is used. A use while nothing defines it raises 'name' is declared extern but never defined (an 'inline' declaration creates it) (extern function: without the parenthesis).

    inline T name; is the C++17 inline variable: one variable shared by every unit that declares it. The first unit to run creates it with its initializer or its type's default, and the rest adopt it (a later unit's initializer does not run again). Inline and plain declarations of one name never mix:

    • A plain declaration of an inline variable raises 'x' is already defined inline; declare it 'inline int x;' to share it.
    • An inline declaration of another unit's plain variable raises 'x' is already defined (not inline) in <file>; declare every definition 'inline' to share it.
    • When the checker sees both units it reports the plain declaration at load, with the first text.

    using ns::name; (a comma list: using game::spawn, game::cost;) makes the rest of the file read name as ns::name, for any namespace. It is a parse-time rewrite: file-local, not transitive through imports or includes, and the name cannot be declared again in that file. There is no using namespace.

    SpellingMeaning to the checker
    extern function log_to_host;a callable of unknown signature: calls are unchecked
    extern int frame; / extern shared_ptr<Game> G;typed: member access, assignments and conversions are checked exactly as for a declared variable of that type
    extern config;untyped: behaves like var
    extern function game::spawn; / extern int a::b::depth;a namespace member, in any of the three strengths: the namespace declares it, so game::spawn is not no member 'spawn' in namespace 'game', and the path opens the namespace for its other members' checks

    An extern stands at program scope or in a namespace, where its name is the namespace's. namespace game { extern int tick; } declares game::tick, which the namespace's own blocks read as tick, and namespace game { extern ai::depth; } declares game::ai::depth.

    A use of a qualified extern while nothing defines it raises the same text with the qualified name: 'game::tick' is declared extern but never defined (an 'inline' declaration creates it). The definition is a namespace block of any unit (namespace game { int tick = 0; }) or the host's registration of that namespace.

    An extern name travels with the program: every unit the root imports sees it. It is also the idiom for a shared leaf that reaches into a module only some programs import. In a program that does import the module, the declaration is inert and the real definition wins.

    [[warn_mode]] and [[strict_mode]]​

    jaiscript
    extern function log_to_host;   // the host registers this later: calls are unchecked
extern int frame;              // typed: reads and stores are checked as an int
extern config;                 // untyped: behaves like var

int total = 0;
try {
    [[warn_mode]] total = "oops";        // this one statement is only warned about...
} catch (e) {
    print("run time: {}", e);            // ...so the mistake surfaces here instead
}
print("{}", total);
    output
    run time: Cannot assign string to 'total' (declared int)
0

    The two attributes set the checker's mode for a region of one file. They compose and the innermost wins; everywhere else a file is strict. Where the attribute sits decides what it covers:

    PositionCovers
    first declaration of a file ([[warn_mode]]; at the top; a leading comment is fine)the whole unit
    first statement of a block (a function, method or lambda body, an if/while/for body, a bare { })the whole block, nested bodies included
    before any other statementthat one statement's own subtree; a nested function or lambda body inside it keeps the enclosing mode

    What each mode does:

    • In a warn region every error is reported as a warning (still collected, still visible through engine->check()) and an undeclared identifier is accepted as unknown; nothing is proven from it.
    • In a strict region errors gate the load, even inside a warn region.
    • The runtime never changes: both backends treat the attribute as nothing. A warn region's type mistakes raise at run time exactly as they would have without a checker, which is what the example shows.
    • A unit's mode says nothing about the units it imports.

    The one other attribute is [[nodiscard]], which marks a function or a method whose result a caller must use (Functions). Any other name is a parse error.

    Language rules in one place​

    The contractual one-liners: the things both backends are tested to agree on, byte for byte.

    RuleWhere to read more
    Checking is always strict. A typed-to-typed mismatch or an undeclared identifier fails the load; a [[warn_mode]] region reports its errors as warnings instead. Only a var-sourced value can still fail at run time, where try/catch sees it.Static Checking
    One conversion table for declarations, =, by-value parameters, returns, instance and static field stores and container elements; one step, never chained.above
    A float never enters an int slot implicitly, compound assignment included. cast<int>(x) and math::itrunc(x) truncate toward zero, math::ifloor(x) rounds down. An int widens to a float everywhere.Type Ladder
    A class value is never null. A slot declared as a class by value refuses null, a class-returning function returns on every path, and a class cannot hold itself by value. shared_ptr<T>, weak_ptr<T>, var and function hold null.Type Ladder
    An enum name is a type. An E slot holds E's values; a value converts to int, an int enters only through cast<E>(n). The bare name is its value table, a map<string,int>.Enums
    Builtin method results are typed. On a receiver of declared type a builtin method has its catalog result type at load: int bad = xs.join(","); is a load error. s.to_int() is null for text that does not parse; s.to_int(0) is an int.API
    Program closure. A file whose import/include paths are literals is the root of a program. Every unit those paths reach is gathered and checked before anything runs, names and class models cross units, and import order does not matter for names. A dynamic-path import(expr) keeps undeclared identifiers at warning severity in that unit.Modules
    Evaluation order is contractual: the callee is resolved before any argument is evaluated, and arguments go left to right, each taking its value when it is evaluated. (pick()(arg("left", 1), arg("right", 2)) records callee left right on both backends.) An assignment t = e or t op= e evaluates e before every part of the target (a member's receiver, a subscript's container and index), as in C++17.Functions
    Captures are exhaustive. [] captures nothing and [x] only x. Using an unlisted local of the enclosing function is the parse error Lambda capture list does not capture enclosing local 'n'; name it or use [=] or [&]. [=]/[x] copy at creation, and [&]/[&x] share the variable (and outlive its frame). [x = e] initializes the lambda's own x, [this] captures the instance. A program-scope name is never captured by default: the lambda reads it when it runs. An anonymous function(...) expression is the JavaScript closure: it captures as [&].Functions
    Methods are called or bound. obj.heal without a call is an error, at load when the checker knows the receiver: 'heal' is a method of Player; call it with player.heal() or bind it with reflect::bind(player, "heal"). reflect::bind(obj, "name") is the method as a callable that holds the object. A builtin method read without a call raises the same way ('push' is a method of array; call it with arr.push() or wrap the call in a lambda).Classes
    Typed returns are required. Under strict checking a function declared to return a primitive, a string, an enum, a class value or a reference must return on every path: 'f' declared to return 'int' may reach the end of its body without returning.Strict checking
    Declarations without an initializer take their type's default: a class default-constructs, int 0, float 0.0, bool false, an enum its first value, string "", containers empty, a math vector zero; var stays null. A class that declares no constructor takes aggregate initialization: Pt p{1, 2}, Pt{1, 2}, Pt(1, 2) fill the instance fields in declaration order (bases first); the rest keep their initializers. A reference has no default: int& r; raises Reference variable must be initialized.Classes
    Fields initialize in declaration order. A field initializer reads the fields above it, its bases' fields, the statics and the enclosing scope, never a constructor's parameters; reading its own field or a later one fails the load. Its value lands as the declaration T f = e; would, null included.Classes
    Top-level code runs in order. A statement at a file's top level sees the declarations above it.
    • A function called before its declaration fails the load ('f' is called before its declaration (line 1): top-level code runs in order, so declare it above the call or make the call after it).
    • A global read, a class constructed or a function taken as a value before its declaration raises Undefined variable 'G'.
    • A function or method body may name a declaration that comes later in the file, because it runs only when called; what it names must exist by then.
    • A namespace's top-level code runs in order the same way. Until its declaration runs, a bare name the namespace declares further down reaches an enclosing namespace's member or the global, and with neither it is the same load error.
    		What the checker sees
    Access control is two levels. public: for everyone; private: (and its synonym protected:) for the declaring class and every class derived from it. Members start public. Outside that family: Cannot access private member 'x' of class 'C', and for a private constructor (checked on the overload resolution picks) Cannot access private constructor of class 'C'. A load (from_json, from_binary) reconstitutes the saved state and is never blocked: it runs the default constructor whatever its access, or creates a class no constructor builds without arguments without one.Classes
    == is memberwise on heavy values. Arrays elementwise, maps entrywise, instances of one class fieldwise (a user operator== first); handles compare by pointer; same_object(x, y) is identity. contains, index_of, has and switch cases use the same ==.Operators
    A return conversion is part of the return statement. It fails inside the callee, at the return's line, with the callee as the top frame; a try around the return catches it there, and uncaught it surfaces in the caller.Return-type rules
    A reserved word is a member name when qualified. After ., ?., -> or :: every word is a member name (p.catch(f), obj.default, spider::catch(url), Mode::default, super::catch()). Every reserved word but this and super declares a field, a method, a namespace member or an enum value. A host binds one the same way (.method("catch", ...)), and reflection and archives use the word as written. Bare, the word stays the keyword: a statement catch(x); and a program-scope void catch() {} are parse errors. A class reaches its own keyword member as this.catch(x).Classes
    Static fields enforce their declared type and are spelled Class::name (bare name inside the class's own methods). Class.name is not a spelling. Statics are inherited names, as in C++: a subclass sees its bases' statics bare and Derived::name names them.Statics
    User accessors win. If a class (or an ancestor) declares _get_x / _set_x, obj.x reads and writes through them instead of the synthesized accessors. A bare x inside the class's methods is the backing field, so an accessor can read its own field without recursing.Name resolution
    Coroutine spellings. coroutine prefixes every function form, at top level, in namespaces and as methods (static ones too): coroutine int g(), coroutine g() -> int, coroutine function g() -> auto, coroutine function g(), and bare coroutine g(). There are no coroutine lambdas, and a coroutine takes no reference parameter: it runs on after the call returns, so it takes copies or a shared_ptr.Coroutines
    C++ property references bind the member. Passing a bound property (f(this.value), f(obj.value)) to a & parameter reads and writes through the host getter and setter, like any field lvalue.Value Semantics
    Value semantics; references by declaration. Assignment, parameters and returns copy. & parameters, auto&, for (auto& x : ...) and shared_ptr<T> (new T(...) is sugar for it) are the spelled-out ways to alias.Value Semantics
    A lost write fails the load. Take a store into a by-value copy of a known value type (a range-for variable, a parameter, a local, a field or element of one). If no path reads it again before the copy dies, and nothing else can observe it, the store is a load error that names the reference spelling.Lost writes
    A dropped [[nodiscard]] result fails the load. An expression statement whose value is a call to a [[nodiscard]] function, method or host callable, or to a library copy such as string::to_upper or array::sort, is a load error; the check is static only.[[nodiscard]]
    Integers are checked, shifts wrap. + - * and unary - raise on overflow; << discards high bits by contract; math::wrap_* is explicit wraparound arithmetic.Operators

    include vs import​

    From Modules:

    include "f.jai"import "f.jai"
    Runsevery time it is evaluatedwhen first reached, then again when its file changed (checked in passes: import_recheck_interval, default 0.2 s)
    Scopeexecutes in the current scopemodule declaration
    Expression?yes: var cfg = include "config.jai"; evaluates to the file's last expressionthe statement form never (auto x = import ... is a parse error); the call form import("f.jai") is a bool: true when a module ran
    Dynamic pathsyes: include(expr)yes: import(expr)
    Checked how?a literal path joins the program closure: its names and classes are known to every unit and checked before anything runs; a dynamic path cannot be gathered, so that unit's undeclared identifiers drop to warnings
    Idiomforcing a re-run: hot reload of rules/content mid-gamedeclaring your module graph at the top of each file

    #include "x.jai" is include "x.jai", for C++ muscle memory. Persistent state goes in a module you only import and never include, so a reload can't wipe it.

    Every file-based load also maintains a jaibite disk cache in a .cache folder beside the source (foo.jai → .cache/foo.jai.jaibite, or below the host's cache directory). A cache recording the exact source text (size + hash) and a matching registration fingerprint loads instead of parsing; any other text reparses and refreshes the cache, whatever its mtime. Parse-level and side-effect-free: it never changes whether a file runs. Silent on write failure; eng->jaibite_cache(false) disables.
