# Gator Quest

A Britannia-lite RPG for the terminal, written entirely in JaiScript. You are a gator. Six tyrants rule the
six realms beyond the Moongates, each hoarding a Relic Scale; bring all six to the Shrine of the Six and
become the Gator Avatar. Along the way: swordplay and spellcraft, fishing and mining, smithing and cooking,
raccoons that steal your gold (catch them in their warrens below the sewers and they drop it), slimes that split, and a
ghostly walk back to the healer when it goes wrong.

It runs on the stock `jaiscript` runner with no other dependencies: the world, the art, the sound effects and
the music are all generated by the scripts.

## Run it

From the JaiScript source root, build the runner once:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release --target jaiscript_runner
```

then:

```bash
build/bin/jaiscript examples/gatorquest/scripts/gatorquest.jai
```

(On Windows the runner is `buildin\jaiscript.exe`.)

## Play

`play.bat` (Windows) and `play.sh` start the same command: each finds the runner in `build/bin` or beside itself.

Use a terminal with 24-bit color and UTF-8 (Windows Terminal is ideal), at least 100x30; bigger is better
(the view switches to 8-pixel tiles from about 190 columns). `Z` cycles the zoom.

## Controls

```
arrows / WASD   move (bump a monster to fight it, bump a shopkeeper to talk)
SPACE or E      use what you face: talk, fish (water), mine (rock), chop (tree), open chests
F or TAB        next target (you keep swinging while it is in reach)
G               pick up what is at your feet or next to you
1-9             cast a spell from your spellbook      Q  drink the best healing potion
H               apply a bandage                        X  hide (stealth)
I P K J B C     backpack, paperdoll, skills, journal, spellbook, crafting
M               world map                              ?  help
ENTER           chat (/pvp /who /invite name /accept /leave /p msg /home)
ESC             clear target, then the menu (save, load, music, sound, zoom, host, leave to title, quit)
```

In a list: up/down (or W/S) to choose, ENTER to act, ESC to close. In the backpack ENTER uses or equips and
`D` drops. Shopkeepers offer Buy/Sell, healers heal (and resurrect ghosts for free), the banker keeps a box.

## The shippable demo

```
powershell -File make_dist.ps1 [-Exe path\to\jaiscript.exe]
```

builds `dist\GatorQuest\` (gitignored): `jaiscript.exe` (statically linked: only Windows system DLLs), the scripts,
`play.bat`, `host.bat`, `join.bat`, `serve.bat`, a player-facing `README.txt` (from `dist_readme.txt`) and the
pre-synthesized audio cache, then checks the folder with a short headless smoke run by the copied exe. About 9 MB,
93 files; zip it and it runs on any Windows 10+ machine with a truecolor terminal.

## The road to Gator Avatar

Quests from the Mayor, the Captain, the shopkeepers and the Oracle lead from sewer rats to the six realm tyrants.
Each tyrant guards a Relic Scale: Big Mama Snapper in the Bayou, the Drowned King in Sogg, Count Crocula in Gloomfen,
the Glacier Queen in Frostfang, Emberjaw the Wyrm on Mt. Scorchmaw (bring fire resistance, and friends) and the
Thunder Roc on Cloudreach's far island. Bosses announce themselves, fill a health bar across the top of the view,
call for help, rage at half health and telegraph a stomp. Bring all six scales to the Oracle at the Shrine of the Six.
`-- endgame` plays the whole road with a scripted hero and reports each fight (time, deaths, potions); a hero with
gear of the right tier finishes it with a handful of deaths in total.

## Multiplayer

Up to 16 gators in one swamp over a LAN (or any network that reaches the host's port, 28777 by default). The title
screen has it all: type your name, pick a color, then choose Single player, Host a game or Join a game.

- **Host a game** takes a port (28777 unless you change it) and lists this machine's addresses, which is what friends
  type. In single player, ESC also offers Host this game, and a host can Stop hosting.
- **Join a game** takes the host's address and port (`192.168.1.20:30000` works too) and remembers every server you
  joined with the name you used there (`saves/servers.txt`; pick one and press ENTER, or backspace to forget it).
  Connecting shows what it is waiting for; a failed join says why: NAME TAKEN, SERVER FULL, VERSION MISMATCH, or
  UNREACHABLE (with the address, and whether nothing listened there or the name did not resolve).
- **Leave to title** (ESC) ends the session: a host sends everyone home with their gators saved and saves the world; a
  joined player just leaves. When a host goes away, its players land back on the title with the reason.

The command line opens the same pages filled in, and the dedicated host has no screen at all:

```
play.bat host [port N]                  # the host page (ENTER starts hosting)
play.bat join 192.168.1.20 [port N]     # the join page with the address in (ENTER connects)
jaiscript scripts/gatorquest.jai -- serve [port N] [bots K]     # a dedicated host with no screen
```

The host runs the world; everyone else sends what they do (moves, attacks, spells, trades) and receives, ten times
a second, what they can see. Joiners' characters live on the host in `saves/chars/`: leave, come back with the same
name, and you are where you left off. In game, ENTER opens chat: plain text reaches everyone in your realm, `/p text`
your party. `/invite name` and `/accept` make a party (kills near your party mates count for their quests too),
`/leave` leaves it, `/who` lists who is online, and `/pvp` flags you: flagged gators can fight each other, unflagged
ones cannot be hurt by players (and killing an unflagged gator makes you a murderer the guards will not forget). A
player who drops is saved and removed.

### Movement prediction

Your own gator moves on the frame you press the key, whatever the latency. Each step goes to the host tagged with a
sequence number (`S|seq|dir`); the host runs the steps in order at the gator's own pace (water, slows and ghosts
included), and every snapshot says which step it processed last and where that left the gator. The client drops the
acknowledged steps, replays the ones still in flight from the host's position, and when the result differs it glides
the drawn gator to the corrected tile (more than three tiles snaps). Facing, footsteps, the swing and the lunge of a
bump attack happen locally; damage, loot and everything else stay with the host. Other gators and the monsters are
drawn about 100 ms behind a smoothed copy of the host's clock, interpolating between the moves the snapshots
describe, so they glide instead of stepping when snapshots arrive unevenly. `noprediction` turns prediction off.

The network simulator adds latency, jitter and loss to a client's link (off by default; loss is TCP-style: a lost
message arrives 250 ms late and holds up the ones behind it):

```
play.bat join 192.168.1.20 lag 120 jitter 20 loss 2      # 120 ms round trip, +-20 ms, 2% of messages late
jaiscript scripts/gatorquest.jai -- predtest              # the prediction test at 0, 60, 150 and 300 ms round trips
```

`predtest` runs the real host and a real client over loopback on a virtual clock (a minute of walking in well
under a minute), through the same input path as the keyboard. It checks that every free step is taken on the frame the key
is held, that the prediction agrees with the host at every stop, that corrections on a clean link are rare and at
most one tile, that nothing snaps, and that a step into a monster the host saw first corrects once, by one tile,
without the drawn gator jumping. Every byte either side writes reaches the other before it next reads (the loopback
takes no virtual time), so the counts depend on the seeds alone and are the same on every machine and both
backends. Each round starts a fresh gator in its own save folder (64 seconds of walking at each round trip):

```
  rtt  jitter loss | walked  steps | corrections /min  max  snaps | same-frame misses | stops converged
     0      0   0% |    64s    268 |           0   0.0    0      0 |     0 of   268 | 12 of 12
    60     10   0% |    64s    275 |           0   0.0    0      0 |     0 of   275 | 12 of 12
   150     25   1% |    64s    231 |           8   7.5    1      0 |     0 of   231 | 12 of 12
  rejected move at 150 ms: step taken on the key frame yes, 1 correction of 1 tile 99 ms after the press, 0 snaps, largest frame-to-frame move of the drawn gator 0.16 tiles, back in agreement yes
   300     50   1% |    64s    244 |           0   0.0    0      0 |     0 of   244 | 12 of 12
```

Corrections under latency are monsters stepping into the gator's path before the client heard they had moved.

## Saves

The game saves by itself every five minutes of play, from the menu (ESC, Save game), and when you leave to the
title or quit. Starting
again loads the saved world, and typing the name of a saved gator (the title lists them; ENTER alone picks the last
one played) brings it back where it stood, with its gear, skills, quests and bank box. A new name starts a new gator
in the same world.

Files live in `saves/` beside the game folder when it is writable, otherwise in the per-user data folder
(`%LOCALAPPDATA%\GatorQuest\saves` on Windows):

```
saves/world.gqw            the world: seed, clock, every monster and npc, items on the ground, chests, weather
saves/chars/<name>.gqc     one file per character
*.bak                      the previous good save, used when the current one is damaged
```

Both are plain text owned by the scripts: a `GATORQUEST-WORLD 1` / `GATORQUEST-CHAR 1` first line, one `key values`
record per line, and a last line `end <checksum>`. The terrain is not stored; it regenerates from the seed. A save is
written to `.tmp`, read back and verified, the old file becomes `.bak`, then the real file is replaced. Loading falls
back to `.bak` (then `.tmp`) when a file is missing, cut short, fails its checksum or comes from a newer version;
unknown records are skipped and missing ones keep their defaults, so older saves keep loading.

## Dev mode: hot reload

```
jaiscript scripts/gatorquest.jai -- dev
```

Edit any `gq_*.jai` script while playing and save it: on the next frame it re-runs in place, and the HUD says what
was reloaded (or why the edit was rejected, with the file and line). The world, your gator and every monster carry on.

Dev mode imports the whole module list once per frame, as one group: `import(DEV_MODULES)`. The engine looks at the
files in check passes (at most every 0.2 seconds; between passes the import costs nanoseconds), so a frame sees all of
your saved edits or none of them. Every changed module is parsed and checked, knowing what the others declare, before
any of them runs: a mistake anywhere is rejected as one error, nothing applies, and the running code stays as it was
until the file is fixed. When they re-run, functions pick up their new bodies everywhere, classes gain or lose fields with live
instances migrating, and enums take their new members. A top-level declaration with an initializer takes its new
value (change a monster's line in `gq_data.jai` and the next spawn has the new stats); one without an initializer
keeps what it holds. That is the whole convention: state is declared without an initializer. `gq_state.jai` and
`gq_cstate.jai` declare nothing else, so they reload too; the starting values that are not a type's default live in
`client_state_init()` and `sim_reset()`. A run-time error while a module re-runs is reported as well, and the
declarations above the failing line have already taken effect; saving the fixed file re-runs it whole.

## Headless modes (tests and captures)

```
jaiscript scripts/gatorquest.jai -- smoke ticks 3000 bots 2      # autopilot session with a save/load round trip, prints STATE_HASH
jaiscript scripts/gatorquest.jai -- savetest                     # save robustness: missing, corrupt, truncated, newer, sparse files
jaiscript scripts/gatorquest.jai -- thieftest                    # the Raccoon Bandits: warrens, pace, thefts, the purse they drop, the quest
powershell -File hotreload.ps1 [-Backend interp]                # edits scripts mid-session in a scratch copy, checks the carry-over
jaiscript scripts/gatorquest.jai -- nettest                      # host + 17 client sessions over loopback, one process
powershell -File nettest2.ps1 [-Backend interp]                  # a dedicated host and two clients as three processes
jaiscript scripts/gatorquest.jai -- predtest [lag N jitter N loss N]   # movement prediction under a simulated link
jaiscript scripts/gatorquest.jai -- menutest                     # the title's host and join pages, every refusal, leaving
jaiscript scripts/gatorquest.jai -- endgame                      # the six tyrants and the Six Scales, start to crown
jaiscript scripts/gatorquest.jai -- tour [screen 200x56]         # captures of every realm, night, a boss fight, fishing
jaiscript scripts/gatorquest.jai -- shot ticks 900 every 300     # frame captures (.ans, .txt sketch, .png)
jaiscript scripts/gatorquest.jai -- shot title                   # every title page as a capture
jaiscript scripts/gatorquest.jai -- demo frames 600              # the real play loop driven by a bot
jaiscript scripts/gatorquest.jai -- sheet                        # every sprite and tile texture as a PNG
```

The STATE_HASH is identical on `--backend=vm` and `--backend=interp` for the same seed and tick count, and the same
with or without the mid-session round trip (`noroundtrip`): saving and loading is invisible to the simulation.
Test modes exit with the number of failures.

## The Lua port (benchmark twin)

`lua/` is a port of what the smoke session runs (world generation, the content tables, mobiles, spawners,
combat, items, quests, actions, bots, the tick and the state hash) to Lua 5.4+, one module per `.jai` file, with
generated LuaJIT and Luau twins. It
prints the same output as the JaiScript smoke run with `noroundtrip`, STATE_HASH included (`python lua/parity.py`
checks a seed/ticks/bots matrix line for line). Rendering, audio, netplay and save/load are not ported.

```
lua lua/gatorquest.lua smoke ticks 2000 seed 1 bots 2 [verbose]           # Lua 5.4 / 5.5
luajit lua/luajit/gatorquest.lua smoke ticks 2000 seed 1 bots 2            # LuaJIT (add -joff for its interpreter)
luau lua/luau/gatorquest.luau -a smoke ticks 2000 seed 1 bots 2             # Luau (-O2 before the file: its optimizer; -O2 --codegen: native code)
python lua/parity.py --jai PATH/jaiscript.exe --lua PATH/lua.exe --luajit PATH/luajit.exe --luau PATH/luau.exe
python lua/to_luajit.py                                                    # regenerate lua/luajit/ after editing lua/
python lua/to_luau.py                                                      # regenerate lua/luau/gatorquest.luau after editing lua/
```

Arrays stay 0-based, so every id, index and hashed value is the script's. Integer division and remainder
that can see a negative operand go through `idiv`/`imod` (C truncation); the script's
value-class copies are explicit (`copy_item`) wherever the copy is stored or mutated. `lua/luajit/` is generated
from `lua/` by `to_luajit.py` (operators to `bit` calls and `math.floor`); its `gq_util.lua` is hand-written,
because the 32-bit hash and RNG need exact 32-bit multiplies on doubles. `lua/luau/gatorquest.luau` is generated by
`to_luau.py` as one file: the `luau` CLI runs each required module in its own sandboxed globals, so the bundle runs
every module as a function in one environment and assigns its exports to the globals; operators become `bit32` calls
(`//` stays, Luau has it), and `luau/gq_util.lua` is the hand-written twin of the util module.
